現状の Unity 画面（0% 基準）との差: 現状は数値がテキストで左右の箱に入り、予兆は無く、スタミナは数字だけで投入量の選択が無い。本書は「予兆 → 間合い → スタミナ」の順に目が動く配置へ組み替える。

### 1.2 「予兆に対して間合いとスタミナをどう使うか」を一目にする配置

読み合いの一手は次の 3 段で成立する。画面の上から下へ、この順に置く。

1. **敵の頭上**に予兆（何が来るか）。
2. **床の帯**に「その攻撃は今の位置だと ×1.0 / ×0.5 / ×0.15」（どこへ動けば避けられるか）。移動を含むカードに触れると、移動先に半透明の残像を出し、帯の色を移動後の補正へ更新する。
3. **手札の上**にスタミナのピップと構え線（いくら投入できるか、いくら残すか）。カードのチップ T0〜T3 は「投入量 → 予測値」を現在間合いで表示する。

つまり「上で読んで、床で動き先を決め、下でいくら払うか決める」。三つの判断が縦一列に並ぶ。

### 1.3 表示しないもの

- 命中率・回避率（存在しない。補正の × 表示がその代わり）。
- 体勢ゲージ・AP・速度・エネルギー（`battle_core_v3.md` §1.1 が持たない値）。
- 敵の投入量の事前表示（実行時に決まる。開示度が上がると威力幅だけ出す）。

### 2.2 L2（代替: 手札右・アリーナ広）

手札を右側に縦積み（幅 22%）にし、アリーナを左 78% に広げる。スタミナ帯は手札の直上、ターン終了は手札の最下段。間合いの実距離を広く取れる代わりに、「予兆 → 床 → スタミナ」の縦一列が崩れる。**L1 を採用**し、L2 は横長のウルトラワイド対応が要るときの保険にする。

### 2.3 手記ドロワー

- 上帯右の「手記を開く（読むだけ）」で、右から幅 30% のドロワーが 220ms で出る。アリーナは暗くしない（読みながら盤面を見られるように）。
- 内容は敵の頁のみ: 開示度、間合いごとの傾向（決定木そのもの）、弱点 / 耐性 / 特殊行動（未開示は「？」）。
- 操作は閉じるだけ。開いている間もカードは選べるが、プレイはできない（誤操作対策）。

## 3. 操作設計

### 3.1 1 ターンの判断を 2〜3 操作に収める

| 判断           | 操作                                            | 画面の反応                                                                 |
| -------------- | ----------------------------------------------- | -------------------------------------------------------------------------- |
| どのカードを   | 1. カードをクリック（またはキー 1 / 2 / 3）     | カードが持ち上がり、チップ T0〜T3 が出る。移動があれば残像と帯の更新       |
| どこへ動くか   | （カードに内蔵。追加操作なし）                  | 残像と狙い帯の色で移動後の補正を見せる                                     |
| いくら投入して | 2. チップをクリック（またはキー 0 / 1 / 2 / 3） | **チップのクリックがそのままプレイ**。ダメージ → 移動 → 追加効果の順に解決 |
| ターンを終える | 3. ターン終了（または Enter）                   | 構え判定 → 捨札 → 敵フェーズ                                               |

- 1 枚のプレイは 2 操作。1 ターンで複数枚プレイしても、各カードは 2 操作で完結する。
- チップに触れている（hover）間、予測値（威力・Guard・移動後の間合い・残スタミナ・構えの可否）を全て出す。乱数が無いので、予測値は確定値である。
- 選択の取り消しは、カード以外の場所をクリックするか Esc。

### 3.2 既定の投入量

チップを出したとき、**「使った後も残スタミナが 3 以上になる最大の段」** を既定で強調する（敵 AI の規則 `battle_core_v3.md` §6.3 と同じ基準）。該当が無ければ選べる最小の段。既定チップに「構え維持」の小さな注記を付ける。

- 目的: 迷ったときの一手が「温存の意味」（§3.5 構え）を自然に守る。
- 既定は強調するだけで、クリックしないとプレイされない。

### 3.3 選べない段の見せ方

| 状態                           | 見せ方                            |
| ------------------------------ | --------------------------------- |
| 現在スタミナが投入量に満たない | チップを薄くし、「スタミナ不足」  |
| `minInvest: 1` のカードの T0   | チップ自体を出さない（表に「—」） |
| 手記ドロワーが開いている       | チップは出るが押せない            |
| 敵フェーズ中・演出中           | 手札全体を暗くし、押せない        |

### 3.4 敵フェーズの進行

- 自動で進む。1 手ごとに 600ms の間を置き、クリックまたは Space で次の手へ早送りできる。
- 早送りしても演出の「結果」（数値・位置）は飛ばさない。動きだけを短縮する。
- 敵フェーズの末に次の予兆を出し、「あなたの番」に戻る。

### 3.5 キーボードとゲームパッド

| 入力          | 操作                                   |
| ------------- | -------------------------------------- |
| 1 / 2 / 3     | 手札のカードを選択                     |
| 0 / 1 / 2 / 3 | 選択中に投入量を決めてプレイ           |
| ← / →         | 選択中に投入量を移動（Enter でプレイ） |
| Enter         | ターン終了（選択が無いとき）           |
| Esc           | 選択取り消し / ドロワーを閉じる        |
| J             | 手記ドロワー                           |
| Space         | 敵フェーズの早送り                     |

ゲームパッドは「LB / RB でカード、A で決定、B で取り消し、Y で手記、X でターン終了」を仮置きする。実機調整は残り 20% に含める。

## 4. 見た目の方向

### 4.1 共通の約束

- **数字は全て等幅・tabular**（IBM Plex Mono）。HP・スタミナ・威力の桁がぶれない。
- **色は役割で固定する**: 自分 = accent、HP = warm、敵と予兆と被弾 = omen、Guard = guard、空振り = whiff。役割以外に色を使わない。
- **UI 文言は日本語**。技名は 4〜6 文字、ラベルは名詞止め。
- **階層で背景の濃淡を変える**（concept-v2 から継承した「幻想ベース、階層で濃淡」）。UI の色は階層で変えない。変わるのはアリーナの背景と靄だけ。
- 立ち絵は 2.5D アニメ（Live2D 本命、`plans/2026-06-28-unity-migration-character-art.md`）。UI はその絵を邪魔しないよう、アリーナには枠を置かない。

### 4.2 3 案の比較

| 案                         | ground    | accent（自分） | warm（HP） | omen（予兆・敵） | guard     | 書体（見出し / 本文 / 数字）                          | 質感                                                     |
| -------------------------- | --------- | -------------- | ---------- | ---------------- | --------- | ----------------------------------------------------- | -------------------------------------------------------- |
| **A 霧と灯り**（幻想寄り） | `#0f1a22` | `#8fd3c7`      | `#e8b86d`  | `#e0614f`        | `#a9c4e6` | Shippori Mincho / Zen Kaku Gothic New / IBM Plex Mono | 足元に灯りのグロー、透過パネル、角丸 6px                 |
| **B 鉄と革**（写実寄り）   | `#141210` | `#b89b5e`      | `#c9a45c`  | `#b43a2a`        | `#7f8f9c` | Zen Old Mincho / Noto Sans JP / IBM Plex Mono         | 角丸 0、真鍮の 1px 線、グロー無し、硬い影                |
| **C 墨と朱**（版画的）     | `#111214` | `#f2efe8`      | `#d9c9a3`  | `#d63a2f`        | `#9aa5ad` | Yuji Syuku / Zen Kaku Gothic New / IBM Plex Mono      | 人型は黒シルエット、パネルは枠線だけ、朱は予兆と被弾だけ |

補助トークン（3 案共通の役割）: ink（本文）/ ink-2（補足）/ line（罫線）/ whiff（空振り、彩度なしの灰）。実値はモックアップの `data-skin` 定義を正とする。

### 4.3 階層ごとの背景（A 案の値。B / C はモックアップ参照）

| 階層 | 上 → 下               | 靄                               | 印象               |
| ---- | --------------------- | -------------------------------- | ------------------ |
| 1    | `#1d3340` → `#0f1a22` | 白 5% の淡い霧                   | 夜明け前の湿った林 |
| 2    | 1 と 3 の中間         | 同上、やや濃く                   |                    |
| 3    | `#1a1f3a` → `#0b0d1a` | 紫の霧                           | 地下の石室         |
| 4    | 3 と 5 の中間         | 紫から赤へ                       |                    |
| 5    | `#1a0e12` → `#070507` | 赤黒い瘴気の靄（下から上へ薄く） | 瘴気の底           |

瘴気ゲージの色は階層に関わらず omen 系の薄い色で固定する。背景の靄と混ざらないよう、ゲージは上帯のパネル上に置く。

### 4.4 推奨: A「霧と灯り」を採用

- 立ち絵の方針がアニメ 2.5D（Live2D）で、塗りと光を生かせるのは A だけである。B の写実は絵柄と喧嘩し、C の版画はシルエット前提で Live2D の塗りを捨てる。
- concept-v2 から続く「幻想ベース、階層で濃淡」に一致する。灯りの暖色が階層の冷色と対になり、深く潜るほど灯りが小さく見える演出（§5.9）に伸ばせる。
- C の規律「朱は予兆と被弾だけ」は A にも取り入れる。omen を予兆・敵の HP 減少・被弾以外に使わない。
- B は見送り。C は保留で、手記の頁と死亡画面（「力尽きた」「手記はここに残る」）に版画的な表現を使う候補として残す。

最終選択はこうだいさんの判断とする（推奨は A）。

## 5. 演出仕様

補間の記法: `out` = ease-out（減速）、`in` = ease-in（加速）、`inout` = ease-in-out、`linear`。音は「有 / 無」と、有なら種類。すべて `prefers-reduced-motion` 相当の設定で 1ms に短縮できる（結果の数値と位置は同じ）。**乱数が無いので、演出で結果を曖昧にしない**: ヒットの有無・数値・移動先は、演出の前に確定した値をそのまま出す。

### 5.1 ターン開始

| 順  | 何が                       | ms             | 補間   | 音           |
| --- | -------------------------- | -------------- | ------ | ------------ |
| 1   | 「あなたの番」バナー fade  | 300            | out    | 無           |
| 2   | Guard バッジが 0 に薄まる  | 150            | linear | 無           |
| 3   | 回復ピップ点灯（1 個ずつ） | 80 × n         | out    | 有・小さな灯 |
| 4   | 手札 3 枚が下からスライド  | 220、90 ずらし | out    | 有・紙 ×3    |
| 5   | 予兆バナー明滅 1 回        | 250            | inout  | 無           |
| 6   | 狙い帯 fade-in             | 300            | out    | 無           |

### 5.2 カードの選択と投入

| 順  | 何が                                    | ms          | 補間   | 音           |
| --- | --------------------------------------- | ----------- | ------ | ------------ |
| 1   | カード持ち上げ 12px                     | 120         | out    | 有・紙       |
| 2   | チップ T0〜T3 fade-in、既定チップを強調 | 150         | out    | 無           |
| 3   | 移動があれば残像を移動先に表示          | 200         | out    | 無           |
| 4   | 狙い帯の色を移動後の補正へ更新          | 150         | linear | 無           |
| 5   | チップ hover: 数値更新                  | 0           | —      | 無           |
| 6   | チップ押下: 投入ぶんのピップが消える    | 60 × 投入量 | in     | 有・息を吐く |
| 7   | カードが中央へ飛んで消える              | 220         | in     | 有・紙       |

投入量 0 のときは 6 を飛ばし、カードの縁を一瞬灰にする（「型だけ」の合図）。

### 5.3 攻撃の解決（自分 → 敵、敵 → 自分は左右反転）

| 順  | 何が                                        | ms        | 補間   | 音               |
| --- | ------------------------------------------- | --------- | ------ | ---------------- |
| 1   | 攻撃側の人型が相手へ踏み込む                | 180       | out    | 有・踏み込み     |
| 2   | 止め                                        | 80        | —      | 有・技ごとの斬撃 |
| 3   | 的中（×1.0 / ×0.5）: 相手が白く光る         | 60        | linear | 有・命中         |
| 4   | 的中: 相手が横に 6px 揺れる（3 往復）       | 180       | inout  | 無               |
| 5   | ダメージ数字が上昇して消える（大・tabular） | 600       | out    | 無               |
| 6   | HP バーが減る。灰の残像が遅れて追従         | 300 / 500 | out    | 無               |
| 7   | 攻撃側が戻る                                | 220       | inout  | 無               |

- 半減（×0.5）の数字は同じ大きさで、脇に小さく「×0.5」。的中と区別が付くように、揺れは 1 往復に減らす。
- 空振り（×0.15）: 3〜4 を飛ばし、灰の小さな数字「空振り 1」だけを 600ms で上げる。相手は揺れない。0 なら「空振り 0」。
- 死力（×1.5）が乗ったときは数字の脇に「死力」を添える。
- 敵の攻撃は投入量が実行時に決まるので、順 1 の直前に敵スタミナのピップが投入ぶん消える（60ms × 投入量）。

### 5.4 Guard と被弾

| 順  | 何が                                              | ms  | 補間 | 音           |
| --- | ------------------------------------------------- | --- | ---- | ------------ |
| 1   | 盾バッジが受け止めて割れる（Guard が減る）        | 200 | out  | 有・金属     |
| 2   | 「Guard −3」が灰で上昇                            | 600 | out  | 無           |
| 3   | 残りがあれば「−3」が omen 色で上昇（順 2 と並ぶ） | 600 | out  | 有・命中     |
| 4   | HP バーが減る                                     | 300 | out  | 無           |
| 5   | HP 30% 未満: 画面端に omen 色のビネット           | 200 | out  | 有・低い鼓動 |

Guard で全て止めたときは 3〜5 を出さず、盾バッジだけが光る（150ms）。HP 30% 未満のビネットは常時薄く残し、被弾で一度濃くする。

### 5.5 移動（間合いの変化）

| 順  | 何が                                          | ms  | 補間   | 音             |
| --- | --------------------------------------------- | --- | ------ | -------------- |
| 1   | 人型が新しい距離へスライド                    | 320 | inout  | 有・足音       |
| 2   | 体勢のクロスフェード（前傾 / 直立 / 後傾）    | 200 | linear | 無             |
| 3   | 「間合い 中」のラベル入替（順 1 の 150ms 後） | 150 | out    | 無             |
| 4   | 順 1 の終了時に狙い帯の色を更新               | 150 | linear | 無             |
| 5   | 移動に Guard が付くカードは盾バッジがポップ   | 300 | out    | 有・金属（小） |

端で止まる（clamp）ときは人型が 40ms だけ前へ寄って戻る（「これ以上下がれない」）。距離のラベルは変えない。

### 5.6 予兆の提示と的中 / 空振り

| 場面                   | 何が                                                                       | ms        | 補間        | 音             |
| ---------------------- | -------------------------------------------------------------------------- | --------- | ----------- | -------------- |
| 提示（敵フェーズ末）   | バナーが敵の頭上から降りてくる。狙い帯 fade-in                             | 260 / 300 | out         | 有・低い弦     |
| 的中（実行、diff 0）   | バナーが一瞬 omen 色で塗り潰し → §5.3 の攻撃へ                             | 200       | out         | 有・命中       |
| 半減（実行、diff 1）   | バナーの狙い間合いに取り消し線、脇に「×0.5」→ §5.3                         | 200       | out         | 有・命中（軽） |
| 空振り回避（diff 2）   | バナー全体に取り消し線、文言が「空振り → 間合い取り直し」→ §5.5 で敵が移動 | 200 → 320 | out → inout | 有・空を切る   |
| 攻撃以外（防御・移動） | バナーに盾または足跡のアイコン。狙い帯は出さない                           | 260       | out         | 無             |

空振り回避は「ダメージを受けなかったこと」と「敵が位置を取り戻したこと」の両方をはっきり見せる。バナーの取り消し線を先に、移動を後に。

### 5.7 構え

| 順  | 何が                                   | ms  | 補間 | 音             |
| --- | -------------------------------------- | --- | ---- | -------------- |
| 1   | ターン終了で残 ≥ 3: ピップ 1〜3 が光る | 250 | out  | 有・息を吸う   |
| 2   | 盾バッジに +2 がポップ                 | 300 | out  | 有・金属（小） |
| 3   | 残った手札が下へ捨てられる             | 200 | in   | 有・紙         |

残 < 3 のときは順 1〜2 を出さず、否定の演出（赤や震え）も出さない。構えの予告（右下の文言）が事前に伝えているので、結果で責めない。

### 5.8 崩し

| 順  | 何が                                             | ms  | 補間 | 音         |
| --- | ------------------------------------------------ | --- | ---- | ---------- |
| 1   | §5.3 の的中の後、相手のピップ 1 個が砕けて落ちる | 300 | in   | 有・砕ける |
| 2   | 相手の人型がよろける（−6° → 0）                  | 400 | out  | 無         |
| 3   | ラベル「崩し −1」が相手のスタミナ列の上に        | 600 | out  | 無         |

崩しの結果は次の敵フェーズの投入量に効くので、次の予兆バナーに「（残スタミナ 4 → 低投入）」を添える（開示度が高いときだけ）。

### 5.9 敵フェーズの区切りと勝敗

| 場面   | 何が                                                                           | ms              | 補間           | 音               |
| ------ | ------------------------------------------------------------------------------ | --------------- | -------------- | ---------------- |
| 敵の番 | 「敵の番」バナー。敵の Guard が 0 に、回復ピップ点灯                           | 400 / 80 × n    | out            | 有・低い弦       |
| 勝利   | 敵人型が崩れ落ちる → 「撃破」→ 持ち越しパネル「HP 22 / 30 ・ スタミナ 4 / 9」  | 800 → 300 → 300 | in → out → out | 有・短い解放     |
| 敗北   | 画面が墨色に沈む（800ms）→ 「力尽きた」（300ms）→ 1 秒後「手記は ここに 残る」 | 800 → 300 → 300 | in → out → out | 有・灯りが消える |

勝利は派手にしない。HP とスタミナが持ち越されるゲームなので、勝利パネルの主役は「残った値」である。敗北は死亡地点に手記が残ることを 1 行で伝え、継承の間へ繋ぐ。

### 5.10 音の方針

- 効果音は 1 行動につき最大 2 つ（動作と結果）。
- 数値が出る瞬間には音を付けない（音は動作に、数値は目に）。
- 本物の効果音は残り 20%（§8）。仮音は Unity 側で無音のまま進めてよい。

## 6. Unity 写像

### 6.1 Canvas 階層

`BattleScreenView.cs` の「コードで組む」方針は保ち、階層を次に組み替える。ScreenSpace-Overlay、参照解像度 1920×1080、`matchWidthOrHeight = 0.5`（現状どおり）。

```
BattleCanvas (Canvas, CanvasScaler, GraphicRaycaster)
├── L0 Background        — 階層ごとの背景 Image ×2（上 / 下のグラデーション）+ 靄の Particle
├── L1 Arena             — 床 Image、狙い帯 Image（9-slice、色は omen / amber / whiff）、
│   ├── PlayerFigure     —   立ち絵（Live2D CubismModel か SpriteRenderer を RawImage 経由）、足元の灯り Image
│   ├── PlayerGhost      —   半透明の残像（同じ立ち絵の alpha 0.35）
│   ├── EnemyFigure      —   同上（反転）
│   ├── OmenBanner       —   予兆バナー（Enemy の頭上に追従。RectTransform を EnemyFigure の子に）
│   └── DistanceLabel    —   「間合い 中」
├── L2 Hud               — 上帯（刻限・瘴気・ターン・敵名・手記ボタン）、ステータス帯（HP バー・盾バッジ・敵ピップ）
├── L3 Hand              — スタミナ帯（ピップ・構え線）、手札 3 枚（HorizontalLayoutGroup）、チップ列、ログ、構え予告、ターン終了
├── L4 Drawer            — 手記ドロワー（右から 30%）
└── L5 Overlay           — 手番バナー、勝敗、ビネット
```

- 人型は UGUI ではなく World-space の SpriteRenderer / Live2D に置き、`Camera.WorldToScreenPoint` でバナーの位置だけ HUD に写す案もある。**まずは全て Canvas 内（RawImage に Live2D の RenderTexture）** で始める。世界座標に出すのは、立ち絵が入って UI との前後関係が問題になったときでよい。
- 全ての数値は `BattleViewModel` から取る（現状の方針を維持）。View に持つ状態は「選択中カード」「hover 中のチップ」「ドロワー開閉」「再生中フラグ」だけ。

### 6.2 アニメーションの実装単位

| 種類                                                       | 実装                                    | 理由                                                                                                |
| ---------------------------------------------------------- | --------------------------------------- | --------------------------------------------------------------------------------------------------- |
| 位置・数値・色・alpha の補間（移動、ピップ、バー、バナー） | **DOTween**（無料版で足りる）           | 距離 260 / 520 / 820 のようなパラメータ補間は tween が自然。ms と ease を §5 の表からそのまま書ける |
| 立ち絵の体勢・攻撃・被弾・崩れ・倒れ                       | **Animator**（Live2D は Cubism Motion） | クリップとして絵に紐づく。GUI で反復調整する（移行計画の判断と同じ）                                |
| 演出の順序制御（§5 の「順」）                              | DOTween の `Sequence`                   | 1 行動 = 1 Sequence。早送りは `timeScale` を上げるだけで結果が変わらない                            |
| 手番の待ち                                                 | コルーチン                              | 600ms の間と Space の早送り                                                                         |

- Sequence は `BattleStore` の通知 1 回につき 1 本作り、完了するまで次の通知を溜める（現状の即時 Render を「差分演出 → Render」に変える）。
- `prefers-reduced-motion` 相当の設定は DOTween の `timeScale = 1000` と Animator の `speed = 1000` で実現する。

**立ち絵（プレイヤー 1 体、敵 1 体から）**

## 7. 開示度と予兆の表示（手記との接続）

`concept-v3.md` §5 と `battle_core_v3.md` §6.1 に従い、予兆の情報量は手記の開示度で決まる。開示度の段階はルール側（R2-3）で未定なので、本書は表示の側から 3 段を仮置きする。

| 開示度 | 予兆バナー                                 | 手記の敵の頁                         |
| ------ | ------------------------------------------ | ------------------------------------ |
| 0      | 種別のみ「攻撃」「防御」「移動」           | 名前と HP 最大だけ                   |
| 1      | 種別 + 狙い間合い「攻撃・中」              | 間合いごとの傾向（決定木）           |
| 2      | 技名 + 狙い + 威力幅「薙ぎ払い・中・4〜8」 | 上に加えて特殊行動・崩しの有無・弱点 |

狙い帯は開示度 1 以上で出す。0 では床に何も出さず、間合いの読みは手記を埋めるまで「賭け」になる。

## 9. ルール側に返したい要望（`battle_core_v3.md` は本書で変えない）

1. **開示度の段階を定義してほしい**（§7 の 3 段を叩き台に）。予兆バナーと狙い帯の出し分けに要る。R2-3 へ。
2. **崩しを受けた敵の「次の投入量」を予兆に添えてよいか**（§5.8）。ルール上は実行時に決まるので、「残スタミナから低投入になる」という見込み表示になる。開示度 2 限定なら矛盾しない。
3. **端で止まる移動（clamp）のログ文言**。「これ以上下がれない」を UI が出すので、ルール側のログと二重にならないよう、clamp をイベントとして通知してほしい（`shift` が 0 になった事実だけ）。
4. **敵の Guard の表示**は対称で出す前提にした。敵の「構え」もプレイヤーと同じ演出（§5.7）で出す。異論があれば教えてほしい。
5. **端数処理の確定**。`battle_core_v3.md` §7.3 の `round` が 2.5 を 3 にするか 2 にするか（C# の `Math.Round` は既定で銀行家丸め）。UI は予測値を確定値で出すので、モックアップは暫定で切り捨てにした。C# 側で `MidpointRounding` を決めてほしい。
