# Vision — Original Card Battle

> 抽象構想・設計原則の正本。CLAUDE.md は「現状の実装規約」、本ファイルは「目指す姿」を持つ。詳細は [`concept-v3.md`](./concept-v3.md)（2026-09-12 APPROVED）。

## 1-line

死者の技を継ぎ、失われた知識を自らの記憶で補いながら、限られた生の中でダンジョンの深奥を目指す、高難度ダンジョン探索 × カード戦略ゲーム。短縮形: **「死ぬたびに人は変わる。だが、技と記憶は次の生へ。」** 個人開発（N=1）。実装先は Unity（`unity-port/` の C# コアが実装元）。

## Primary user

作者本人。単一プレイヤー。

## Core Value（concept-v3 §2 の 5 要素を一つの循環として扱う）

- **V1 — 間合いの奪い合い**: 近 / 中 / 遠。カードも敵も間合いで性能が変わる。敵と自分の双方に有利な距離を取り合うターン制の読み合い
- **V2 — スタミナ配分**: ターン持ち越し・1 枚に最大 3 投入・温存にも意味がある。最大値は探索中の一時変化と衰弱で動く
- **V3 — 文脈ベースの習熟**: 「どう使ったか」でカードが育ち、名称が変わり、高習熟で永続能力になる。探索用カードと戦闘用カードのジレンマ
- **V4 — 消える図鑑と残る記憶**: 敵図鑑・ダンジョン図鑑は死で消える。プレイヤーの記憶だけが残る
- **V5 — 刻限と衰弱**: 刻限 = 階層で何をするか、衰弱 = 生をどこまで続けるか。二つを競合させない
- **V6 — 生と継承**: 生存ルートか死亡か。死亡地点の遺産から数個だけ選んで継ぐ。浅層の意図的な死では強い技を残せない

## Non-Goals

- マルチプレイヤー / オンライン同期
- 課金・サーバーサイド
- 3 クラス目以降の拡張は当面しない（剣士で新コアを完成させ、魔術師は後追い）
- モバイルネイティブ化
- キャラクターの永続成長（レベル・恒久スキルツリー）。成長は「この生」の中だけ

## 凍結（2026-09-12）

- **アーマー**（AP / 装備耐久 / 装備破損 / 鍛冶屋の修理・強化）。防御は Guard のみで難易度と調整を測る。解除はユーザー判断
- **装備・Gold・ソウル経済**（ショップ / サンクチュアリ / エクストラクション型の持ち帰り）。企画書に記述がないため凍結。継承の単位は技術と知識

## 設計原則

- **データとロジックの分離**: ゲームデータと振る舞いを混在させない（TS 版は `src/constants/data/` と `src/domain/`、C# 版は `unity-port/BattleCore/` の Types / Constants と Reducer）
- **状態の単一所有**: 各 state は 1 つの所有者が持ち、他は読むだけ
- **不可侵コード**: `deck.ts` / `deckReducer.ts` はシャッフル決定性の核。改変禁止
- **パリティ**: TS の battle-lab コアと C# コアは fixture で同期を保つ（`npm run parity:check`）
- **設計書駆動**: 数値は `docs/*_document/` の設計書を正とし、実装との差分はどちらかに寄せて解消する。上書きの優先順位は concept-v3 §10
- **React 19 パターン / CSS スコープ**: Web 版に残るコードは CLAUDE.md の規約に従う
