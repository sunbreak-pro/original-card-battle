## 決まっていること

- **職の壁をなくす。** 探索者は 1 人で、剣術と魔術を 1 つの束から選ぶ（2026-11-22、こうだいさん）。
- **魔術の札は、敵の術を手記で読み解いて写したもの。** 世界観の「人の側に魔術は無い」を変えないため。
- **札の割り方は、剣術 59〜64 種・魔術 37〜40 種・合わせ技 約 5 種。** 朝の「14 枚を外して 50 種」は取り下げた。外すか書き換えるのは、役の薄い 5 枚（遠間の構え・棘の一射・受け歩き・見切りの目・影踏み）。
- **戦法の柱は 10 本。** 柱 1 本に、主に属す札 9〜13 種と、隣の柱とつなぐ札 3〜4 種をそろえる。同じ柱でも入れる札が人ごとに分かれるようにするため。
- **術の印と連動(術) を足す。** こうだいさんは、規則を足さない推奨ではなく、印を足すほうを選んだ。
- **出立のときの束に、柱ごとの入口（仕込む札 1 種と得をする札 1 種）を入れる。**
- **順番は #999 → #934 と #903 → #898。** 同じ設計書を続けて触るので、1 本ずつ main に入れる。#997 は #999 のあと、#996 は #898 と別の回。
- **数え方は束全体。** 同じ条件と効果の組は 3 枚まで、4 マスの配分は、剣術と魔術を合わせて数える。#999 と #934 のうち先に入るほうが、札の設計書の数え方を書き直す（両方の Issue にコメント済み）。
- **数値は 1 つずつ。** 連鎖の予測を書かない（メモリの決まり）。

## 落とし穴

- **Issue の本文の案は、設計書と突き合わせてから使う。** #1004 の実装役は、案の 3 点（変幻の構えが鈍足 2 に決まっている、など）を確かめられず、書かなかった。札の表は、#903 が入るまで古い効果のまま。
- **案出しの指示に古い規則を書いた。** 「スタンスの札はデッキ 3 枚まで」は v4.4 でなくなっている。Workflow に渡す前提は、設計書の本文で確かめる。
- **merge 済みの PR の本文に `Closes #n` や `Refs #n` を書くと、その Issue が着地済みに数えられる。** 結びたくない Issue は「Issue 999」のように `#` を付けずに書く。
- **worktree で build を回すとき、`node_modules` を junction でつないだら、worktree を消す前に `cmd //c "rmdir node_modules"` で外す。** つないだまま消すと、main の `node_modules` まで消えるおそれがある。
- **main に merge するたびに、ハーネス索引（使い続ける Artifact）が古くなり、返信の終わりに更新を求められる。** PR をまとめて入れてから 1 回だけ更新すると、手間が減る。別のセッションの公開とぶつかったら、名前の挙がったファイルを `read` で落としてから公開し直す。
- **申し送りは git に入らない。** Workflow の実装役が `wf-*` の worktree の `.claude/comm/handoff/` に書くので、worktree を消す前に回収して Issue にする。
