# Tier 2 — 補助要件（コアが回った後に体験を厚くする）

> **入力**: `docs/vision/concept-v3.md` / `tier1-core.md` v6

## R2-1: ダンジョン構造の設計書化（単一ダンジョン・ノード式）

- **由来**: concept-v3 §12-14（2026-09-12 決定: 一つのダンジョンを深く潜る。マップはノード式のまま、後で変更の可能性あり）
- **内容**: 単一ダンジョンの階層数・階層ごとの敵プール・ノードの種類（戦闘 / 情報収集 / イベント / 休息 / 近道 / 特殊地点）・刻限との対応を `danjeon_document/` に書く。マップ生成はノード式を継続し、マップ方式を差し替えられるよう「ノード = 刻限を消費する行動の置き場」として抽象化する。死亡地点の遺産（R1-12）が階層 + ノードで一意に指せること
- **依存**: R1-12
- **受け入れ基準**:
  - [ ] 遺産の痕跡が階層・ノードで一意に指せる
  - [ ] マップ方式（ノード式）を差し替えても刻限・遺産のデータが壊れない境界がある

## R2-2: 剣士カードの再定義（習熟段階付き）

- **由来**: concept-v3 §4 / 旧 R1-10
- **内容**: 剣士カードを新ルール（間合い補正表 / 投入量 0〜3 / 習熟段階と名称変化 / 一部の永続能力 / 探索効果）で再定義。枚数は所持上限 80 に対して十分な選択肢が出る規模
- **2026-09-13**: 属性 5 つ × 特性 × 状態の v4 規則（`battle_core_v4.md`）で 80 種（初期 40 / 習得 40）を `card_document/swordsman_cards_v4.md` に起票。同種 3 枚まで、minInvest 0 は 20 種まで。習熟段階と探索の面は列だけで中身は未定
- **依存**: R1-5, R1-6
- **受け入れ基準**:
  - [ ] 80 種の配分（単属性 40 / 二属性 40、アタック面 38 種で 近 15 / 中 14 / 遠 9）が `swordsman_cards_v4.md` §4 の集計と一致する
  - [ ] 全カードに習熟段階の定義がある
  - [ ] `card_document/` と実装データの差分ゼロ

## R2-3: 敵ロースターの新ルール対応

- **由来**: concept-v3 §3.1 / §3.5 / §5
- **内容**: 敵定義に得意間合い・間合い変更行動・予兆・手記項目（弱点 / 耐性 / 条件 / 関係 / 適応条件）を付与。ボスに適応ルールを持たせる
- **2026-09-13**: 80% 用の 9 体（通常 6 / 精鋭 2 / ボス 1）を `enemy_document/enemy_roster_v4.md` に起票。敵の行動もカードと同じ属性・面・特性・状態を持つ。精鋭は 2 行動 + 予兆 2 段、ボスは適応 + 専用の状態 2 つ。100% 用の残り 10 体は名前と役割だけ
- **依存**: R1-4, R1-15
- **受け入れ基準**:
  - [ ] 9 体の「正解の間合い」が試験台で全て異なる（間合いを変えると勝率が 15 pt 以上動く）
  - [ ] 全敵が手記の全項目を埋められる

## R2-4: 探索イベントとツールの拡充

- **由来**: concept-v3 §7
- **内容**: 最大スタミナ・HP・瘴気を変えるイベント（重い宝箱 / 休息 / 食事 / 呪い / 泉 / 薬草）と、探索用・戦闘用ツールの実データ（防瘴の面を含む）。資源（浄化の香など）とアイテム（§12-17）の扱いをここで決める
- ランダム性（concept-v3 §7.3）: 報酬の種類と量、イベントの発生を乱数で決める。深い階層ほど期待値を高くし、生存ルートの安全さと釣り合わせる
- **依存**: R1-9, R1-14
- **受け入れ基準**:
  - [ ] 1 階層あたり最大スタミナが動くイベントが 2 つ以上出る
  - [ ] 瘴気を和らげる手段がツール・資源に 1 つずつ以上ある

## R2-5: 戦闘 HUD と演出

- **由来**: concept-v3 §3 / §6。設計書は `battle_document/battle_ui_ux_v1.md`（2026-09-12、80% 設計）が正。モックアップは `docs/mockups/2026-09-12-battle-uiux-mockup.html`
- **内容**: `battle_ui_ux_v1.md` の L1 レイアウトを Unity（UGUI、コード生成）で実装する。上帯（刻限 / 瘴気 + 濃度 + 最大スタミナへの減少 / 階層・ターン・手番 / 敵名・手記ボタン）、アリーナ（2 体の実距離と体勢で間合い、敵の頭上に予兆バナー、床に予兆の狙い帯、移動カード選択時の残像）、ステータス帯（HP バー + 盾バッジ、敵スタミナのピップ）、スタミナ帯（ピップ列 + 構え線 + 瘴気で失った枠の破線）、手札 3 枚（現在間合いでの予測値、選択で投入量チップ T0〜T3）、ターン終了と構えの予告、手記ドロワー（読むだけ）。演出は同書 §5 の ms / 補間、実装単位は §6（DOTween + Animator）。見た目は同書 §4 で採用した案のトークン。アート / Live2D は `plans/2026-06-28-unity-migration-character-art.md`
- **依存**: R1-9, R1-15
- **受け入れ基準**:
  - [ ] 1 枚のプレイが 2 操作（カード選択 → 投入量チップ）で完結し、投入量 0〜3 の各段に現在間合いでの予測値（威力 / Guard / 移動先 / 残スタミナ）が出る
  - [ ] 既定の投入量が「使った後に残 3 以上になる最大の段」で強調され、「構え維持」と表示される
  - [ ] 予兆バナーと狙い帯が敵フェーズ末に出て、移動カードに触れると移動後の補正（×1.0 / ×0.5 / ×0.15）へ床の色が変わる
  - [ ] 間合いは 2 体の中心距離（近 260 / 中 520 / 遠 820 px、1920 基準）と体勢差分で表現され、タブ・トラック型の UI が無い
  - [ ] 予兆の的中 / 半減 / 空振り回避、構え（+2）、崩し（ピップの砕け）、Guard の割れと被弾、勝敗の 8 演出が §5 の表どおりの順と ms で再生される。早送りしても数値と位置は同じ
  - [ ] 瘴気ゲージに濃度と最大スタミナへの減少が併記され、失った枠が破線で見える
  - [ ] 手記ドロワーを開いても予兆の表示は変わらず、ドロワーが開いている間はプレイできない
  - [ ] 数値は全て等幅 tabular で、色は役割トークン（自分 / HP / 敵・予兆 / Guard / 空振り）以外に使われていない
  - [ ] 演出短縮の設定で全アニメーションが 1ms 相当になり、結果が変わらない
