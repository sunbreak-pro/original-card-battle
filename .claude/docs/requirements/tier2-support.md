## R2-1: ダンジョン構造の設計書化（単一ダンジョン・ノード式）

- **由来**: concept-v3 §12-14（2026-09-12 決定: 一つのダンジョンを深く潜る。マップはノード式のまま、後で変更の可能性あり）
- **内容**: 単一ダンジョンの階層数・階層ごとの敵プール・ノードの種類（戦闘 / 情報収集 / イベント / 休息 / 近道 / 特殊地点）・刻限との対応を `danjeon_document/` に書く。マップ生成はノード式を継続し、マップ方式を差し替えられるよう「ノード = 刻限を消費する行動の置き場」として抽象化する。死亡地点の遺産（R1-12）が階層 + ノードで一意に指せること
- **依存**: R1-12
- **受け入れ基準**:
  - [ ] 遺産の痕跡が階層・ノードで一意に指せる
  - [ ] マップ方式（ノード式）を差し替えても刻限・遺産のデータが壊れない境界がある

## R2-2: 剣士カードの再定義（習熟段階付き）

- **由来**: concept-v3 §4 / 旧 R1-10
- **内容**: 剣士カードを新ルール（列 1〜4 の固定コスト / 届く間合いと間合いの境目 / 習熟段階と名称変化 / 一部の永続能力 / 探索効果）で再定義。枚数は所持上限 80 に対して十分な選択肢が出る規模（2026-09-20: 投入量と間合い補正表は廃止 → `battle_core_v4.md` §17.2 / §18.2。2026-09-22: 位置の条件は届く間合いと境目、ムーブ面は前へ n / 後ろへ n、間合い 3 以上で使えない札を置く → 同書 §7、#160）
- **2026-09-13**: 属性 5 つ × 特性 × 状態の v4 規則（`battle_core_v4.md`）で 80 種（初期 40 / 習得 40）を `card_document/swordsman_cards_v4.md` に起票。同種 3 枚まで、戦闘デッキは 20〜40 枚。習熟段階と探索の面は列だけで中身は未定
- **依存**: R1-5, R1-6
- **受け入れ基準**:
  - [ ] 80 種の配分（単属性 40 / 二属性 40、間合いを読む特性 16 枚を 攻撃 / 防御 × 詰めて得 / 離れて得 の 4 マスへ 4 枚ずつ）が `swordsman_cards_v4.md` §4 の集計と一致する
  - [ ] 全カードに習熟段階の定義がある
  - [ ] `card_document/` と実装データの差分ゼロ

## R2-3: 敵ロースターの新ルール対応

- **由来**: concept-v3 §3.1 / §3.5 / §5
- **内容**: 敵定義にマス・大きさ・開始のマス（全ての敵）・間合いを動かす行動と押す / 引く・間合いの帯 3 枝の決定木・予兆（種別と狙うマス）・手記項目（弱点 / 耐性 / 条件 / 関係 / 適応条件）を付与。ボスに適応ルールを持たせる
- **2026-09-13**: 80% 用の 9 体（通常 6 / 精鋭 2 / ボス 1）を `enemy_document/enemy_roster_v4.md` に起票。敵の行動もカードと同じ属性・面・特性・状態を持つ。精鋭は 2 行動 + 予兆 2 段、ボスは適応 + 専用の状態 2 つ。100% 用の残り 10 体は名前と役割だけ
- **依存**: R1-4, R1-15
- **受け入れ基準**:
  - [ ] 3 体（ボス 1 / 精鋭 2）で、終える間合い N を変えると勝率が 15 pt 以上動く（2026-09-22: 全ての敵がマスを持つ → `battle_core_v4.md` §7）
  - [ ] 全敵が手記の全項目を埋められる

## R2-4: 探索イベントとツールの拡充

- **由来**: concept-v3 §7
- **内容**: 最大スタミナ・HP・瘴気を変えるイベント（重い宝箱 / 休息 / 食事 / 呪い / 泉 / 薬草）と、探索用・戦闘用ツールの実データ（防瘴の面を含む）。資源（浄化の香など）とアイテム（§12-17）の扱いをここで決める
- ランダム性（concept-v3 §7.3）: 報酬の種類と量、イベントの発生を乱数で決める。深い階層ほど期待値を高くし、生存ルートの安全さと釣り合わせる
- **依存**: R1-9, R1-14
- **受け入れ基準**:
  - [ ] 1 階層あたり最大スタミナが動くイベントが 2 つ以上出る
  - [ ] 瘴気を和らげる手段がツール・資源に 1 つずつ以上ある

## R2-5: 戦闘 HUD と演出

- **由来**: concept-v3 §3 / §6。設計書は `battle_document/battle_ui_ux_v2.md`（2026-09-13、core v4.1 対応）が正。v1.2 は View v1.1 の実装記録。モックアップは `docs/mockups/2026-09-13-battle-uiux-v4-mockup.html`
- **内容**: `battle_ui_ux_v2.md` の L1 v2 を Unity（UGUI、コード生成）で実装する。View v1.1 で実装済みの骨格（上帯 / アリーナの 2 体の立ち位置・予兆バナー・狙い帯 / ステータス帯 / スタミナ帯 / 手記ドロワー / 敗北画面）はそのまま使い、v4.1 の部品を足す: 手札 5 枚の扇（3〜8）、ドラッグ（受け皿 = 単体の相手、投げ上げ線 = 全体と自分向き。クリックとキーは副操作）、手札の特性の合図と「このターンにプレイした属性」、状態チップ（スタック制。プレイヤーは種類 6 まで、敵は上限なし、ボス専用 2 語）、スタンス枠（両者、置き換えは新旧を 1 秒並べる）、山札 / 捨札 / 除外、2 体目の敵（敵ごとの HP / Guard / スタミナ / 予兆 / 狙い帯 / 位置はボスと精鋭だけ）、精鋭とボスの予兆 2 段、ボスの適応の予告、連戦の進捗と休憩の選択と結果画面。演出は同書 §5（系統 8 × 段 4 × 固有の飾り）の ms / 補間で、1 行動 2.0 秒 / 精鋭の 2 行動 3.5 秒の時間予算を持つ。実装単位は §6.2（View v1.1 の `UiTween` を継続、Animator と DOTween は入れない。ドラッグは `EventSystem` + 自前の当たり判定）。見た目は §4 の A+ トークンに属性 5 色と状態 2 色を足したもの。実装順は `plans/2026-09-13-battle-v4-implementation.md` の順 3（ドラッグと HUD）→ 順 4（演出の文法）。アート / Live2D は `plans/2026-06-28-unity-migration-character-art.md`（2026-09-20: 投入帯と既定の投入量は廃止。相手の選び方は受け皿と投げ上げ線、間合いは立ち位置と一字札 → `battle_core_v4.md` §17.1 / `battle_ui_ux_v2.md` §10。2026-09-22: 間合い N へ。一字札をやめ、床のマス・届くマスの光・狙うマスへ → #163）
- **依存**: R1-9, R1-15, R2-2, R2-3
- **受け入れ基準**:
  - [ ] 1 枚のプレイがドラッグ 1 回（持つ → 受け皿か投げ上げ線 → 離す）で完結し、持ち上げている間に予測値（威力 / Guard / 移動先 / 残スタミナ / 構えの可否 / 特性の発火）が出る
  - [ ] クリック（1 枚 = 2 クリック。札 → 受け皿か投げ上げ線）とキー（1〜8 でカード、Tab で相手、← / → で向き、Enter で確定、X でターン終了、Esc）がドラッグと同じ `PlayRequest` に落ち、同じ結果になる
  - [ ] 今のスタミナで払える札と払えない札が手札で見分けられ、使った後に残 3 以上になる札が「構え維持」と表示され、ターン終了の予告が「残 n → Guard +3」を出す
  - [ ] 手札の各カードに特性の条件が今満たされているかの合図があり、「このターンにプレイした属性」が HUD に見える
  - [ ] 状態チップが両者に出て（語 + スタック数）、プレイヤーは種類 6 つまでで 7 つ目が付かないことが表示で分かる。ボス専用 2 語は専用の色
  - [ ] スタンス枠が両者にあり、置き換えで新旧が 1 秒並び、出した札が除外へ移るのが見える
  - [ ] 2 体戦で敵ごとに予兆バナーと狙い帯があり、受け皿で相手を選べ、投げ上げ線の全体攻撃が両方へ効く
  - [ ] 精鋭とボスの予兆が 2 段（1 手目 / 2 手目）で出て、ボスの適応の予告と専用状態のチップが見える
  - [ ] 予兆バナーと狙い帯が敵フェーズ末に出て、ムーブ面を持つカードを持ち上げると移動後の立ち位置が床に示される
  - [ ] 間合い N は床のマスと届くマスの光で、予兆は狙うマスで表現され、一字札も体勢差分もタブ・トラック型の UI も無い（2026-09-22: `battle_ui_ux_v2.md` の追従は #163）
  - [ ] 予兆の的中、構え（+3）、崩し、Guard の割れと被弾、hits、push、特性の発火、状態の付与と tick、スタンスの置き換え、勝敗の演出が §5 の表どおりの順と ms で再生され、早送りしても数値と位置は同じ。1 行動は 2.0 秒以内、精鋭の 2 行動は 3.5 秒以内
  - [ ] 瘴気ゲージに濃度と最大スタミナへの減少が併記され、失った枠が破線で見える
  - [ ] 手記ドロワーを開いても予兆の表示は変わらず、ドロワーが開いている間はプレイできない
  - [ ] 連戦モードで 撃破 → 持ち越しパネル → 休憩の選択 → 次の敵 が通り、結果画面に 何戦目 / 残 HP / 属性の内訳 / 特性の発動回数 / 平均ターン数 が出る
  - [ ] 数値は全て等幅 tabular で、色は役割トークン（自分 / HP / 敵・予兆・被弾 / Guard / 属性 5 / 状態 2 / ボス専用）以外に使われていない
  - [ ] 演出短縮の設定で全アニメーションが 1ms 相当になり、結果が変わらない
