## 3. §12 に残る 2 件

### A. 刻限 10 回の内訳（§12-1）

**案**: `dungeon_exploration_v4.md` §3 に出しました（Issue #95 / PR #118）。踏破 5 + 余白 5 の配分にし、余った刻限は次の階層へ持ち越しません。習熟訓練は休息ノードの二択の片方に置きます。

**§12-1 の差し替え文案**:

> 1. ~~1 階層における刻限 10 回の具体的な行動~~ → **決定（2026-09-16 / 2026-09-21）**: 消費は 1 ノード 1 回。戦闘も休息も同じ重さにする。習熟訓練は休息ノードの二択の片方で、刻み 1（§14）。10 回の内訳は 通常戦闘 3 / 精鋭 1 / ボス 1 / 休息または訓練 2 / 情報収集 1 / イベント 1 / 余白 1（`danjeon_document/dungeon_exploration_v4.md` §3）

### B. ボスの適応（§12-8）

**いま決まっていること**: 予兆はコミット式で空振りを避ける。通常敵は距離で決まる決定木（`battle_core_v3.md` §6）。ボスは固定パターンではなくプレイヤーの行動で方針を変え、予兆と手記と観察で予測できる（§3.5）。戦闘の解決に乱数は使わない（§7.3）。

**案**: ボスに **3 つの観測カウンタ** を持たせ、閾値を超えたら「構え」が 1 段だけ変わる形にします。

| 項目           | 案                                                                             | 理由                                                              |
| -------------- | ------------------------------------------------------------------------------ | ----------------------------------------------------------------- |
| 何を観測するか | 近間での攻撃 / 防御札（Guard など）/ 同じ札の反復 の 3 つ。ボスごとに 2 つ持つ | 3 つとも `battle_core_v4.md` に既にある概念で、新しい軸を足さない |
| 切り替えの条件 | どれかが 3 回に達したら、その札に対する構えへ移る（叩き台）                    | 回数で決まるので乱数を使わない。プレイヤーが数えられる            |
| 何段変わるか   | 1 戦で 2 回まで。元の構えには戻らない                                          | 読み合いが一方向に進み、手記の情報が腐らない                      |
| 予兆の出し方   | 通常どおりコミット式。構えが変わるターンだけ、1 ターン前に別の予兆を出す       | 「適応された」ことが不意打ちにならない                            |
| 手記との繋がり | 開示度 1 で「適応する敵である」こと、2 で「どのカウンタを持つか」が見える      | §14 の開示度 2 段と噛み合う                                       |

**この案を採らない場合の対案**: HP の割合で段階を切り替える（一般的な段階ボス）。実装は軽いですが、プレイヤーの行動を読んでいないので §3.5 の「適応型」ではなくなります。

**注意**: この項目の正本は `battle_document/battle_core_v4.md` で、担当は battle レーンです。dungeon レーンは案を置くだけで、本体へは書きません。採用が決まったら battle レーン宛に Issue を切るのが筋です。

## 4. §16.5 に残る 3 件

3 件とも design レーン（世界観と見た目）の持ち物です。dungeon レーンからは案だけ置きます。

### C. 役目を出す主体（§16.5-1）

**案**: 街の世俗の組織にします。踏破者を任命し、装束と剣を支給し、継承の間で遺産を管理する役所です。教団と領主は採りません。

| 候補 | 採否     | 理由                                                                                                       |
| ---- | -------- | ---------------------------------------------------------------------------------------------------------- |
| 役所 | 採る     | 刻限（定められた潜行の期限）・瘴気（帰還の義務）・継承の間（遺産の管理）の 3 つが 1 つの主体からぶら下がる |
| 教団 | 採らない | 瘴気が宗教的な罰の色を帯びる。資源として管理する読みから遠ざかる                                           |
| 領主 | 採らない | 代替わりで方針が変わるため、世代をまたぐ記録の保全に別の理由が要る                                         |

### D. 解禁記録の繋ぎ（§16.5-2）

**案**: 作中の記録には残しません。「根の裂け目が開く」を階層 7 の固定の現象として扱い、解禁条件はゲーム外のプレイヤー記録のままにします（層の位置は `seven_layers_v4.md` §6 で五層から七層へ移しました）。

理由は二重を避けるためです。作中の記録に残すと「役所が知っている情報」になり、手記の開示度と役割が重なります。§15.2 が「解禁が与えるのは挑戦の機会だけ」と決めているので、作中の説明を足さなくても筋は通ります。

### E. Live2D のパラメータ（§16.5-3）

**案**: プレイヤーの 3 パラメータを **lean / 面の角度 / マントの揺れ** に置き換えます。目と口を落とし、数は 3 のまま保ちます。

§16.3 が「感情は面の角度と肩・手・マントの動きで示す」と決めているので、パラメータをその 3 つへ寄せるだけで済みます。敵側のパラメータは変えません。正本は `battle_ui_ux_v2.md` §6.4 で、design レーンが書き換えます。
