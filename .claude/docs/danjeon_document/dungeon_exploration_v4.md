## 2. 要素の選別

「80% 版」は、出立 → 階層 1 → 戦闘 → 次の階層 が Unity で 1 周通る版を指します（#94 の Definition of Done）。判断の基準は 2 つです。**ループの 5 要素（習熟 / 間合い / スタミナ / 手記 / 瘴気）のどれかに直接つながるか**と、**無いと 1 周が成立しないか**です。

### 2.1 残す（13 件）

| 要素 | 形 | 残す理由 |
| --- | --- | --- |
| 通常戦闘ノード | 踏むと 1 戦。刻限 1 | 階層の主成分。これが無いと探索が移動だけになる |
| 精鋭ノード | 寄り道に置く。報酬が厚く、HP とスタミナを多く削る | 「安全に通すか、削られても取るか」の分岐を作る |
| 階層ボスノード | 階層の出口。撃破すると次の階層へ | 階層の区切りが無いと刻限の予算が意味を持たない |
| 休息ノード（階層内） | HP 15% 回復 / スタミナ全回復 / 最大スタミナ +2。瘴気は濃度分たまる | HP の持ち越しに対する唯一の階層内の答え |
| 習熟訓練 | 休息ノードの二択の片方。指定した 1 枚に刻み 1 | 探索から習熟へ届く唯一の線。§14 で決定済み |
| 情報収集ノード | 手記の開示度を 2 段目へ上げる。対象はこの階層の敵 1 種 | 手記を探索側から動かす。戦闘の予兆の精度に直結する |
| イベント 3 種 | 泉（HP 回復）/ 重い宝箱（貴重品 + 最大スタミナ -2）/ 特殊な食事（最大スタミナ +1 + 代償） | 探索の選択が戦闘の数値を変える例を、最小の数だけ持つ |
| 階層間の休憩 | HP 30% 回復 / スタミナ全回復 / 瘴気はたまらない | 階層の切れ目。ここで次へ潜るか生を閉じるかを選ぶ |
| 死亡地点の痕跡 | 前の生の遺産を回収する。1 つの生で 1 件 | 継承のループが探索に現れる唯一の点 |
| 刻限 | 階層ごとの行動予算。尽きるとその階層の行動が終わる | 探索の圧力そのもの |
| 瘴気 | 行動ごとに濃度分たまる。最大スタミナへ効く | 生の長さ。戦闘へ効く経路が既に決まっている |
| ノードの段階開示 | 遠い = 種別アイコンだけ。隣接 + ホバー = 中身（敵名 / 脅威度 / 回復量） | 選ぶ材料が無いと、ノードの分岐が運になる |
| 消耗品 3 枠 | 拾ったらその場で入れ替え | §14 で決定済み。拾得の受け皿が無いと報酬を置けない |

## 3. 刻限 10 回の内訳（concept-v3 §12-1 への回答案）

### 3.1 満寸の階層（ノード 10〜12）

1 階層あたりの刻限 10 を、次の配分で組みます。プレイヤーが全部を取れるわけではありません。**踏破に 5、選べる余白に 5** という形です。

| 用途 | 目安 | 内訳の中身 |
| --- | --- | --- |
| 通常戦闘 | 3 | 最短ルート上に 2、寄り道に 1 |
| 精鋭 | 1 | 寄り道側だけに置く。避けて通れる |
| 階層ボス | 1 | 出口。必須 |
| 休息 / 習熟訓練 | 2 | 休息ノード 2 つ。各ノードで「休む」か「訓練する」の二択 |
| 情報収集 | 1 | この階層の敵 1 種の開示度を 2 段目へ |
| イベント | 1 | 泉 / 重い宝箱 / 特殊な食事 から 1 |
| 余白 | 1 | 痕跡の回収、または取りこぼしの拾い直し |
| **合計** | **10** | |

最短ルート（入口 → 分岐 2 つ → ボス）は 5 刻限です。残り 5 を寄り道へ回すか、瘴気を惜しんで次の階層へ降りるかを選ばせます。**刻限が余っても次の階層へ持ち越しません**。余らせて降りるのが正解になる場面を作るためで、階層が深く瘴気の濃度が高いほど「降りる」が強くなります。

### 3.2 二択を「1 ノード 1 回」の例外にしない

習熟訓練を休息ノードの中の追加行動にすると、1 ノードで刻限を 2 使う例外ができます。そこで**休息ノードでは「休む」か「訓練する」のどちらか 1 つだけを選ぶ**形にします。刻限 1 のまま、回復と習熟の取り合いが生まれます。

### 3.3 最小の階層では刻限 6

ノード 6 の階層に刻限 10 を渡すと、全部踏んでも 4 余ります。圧力が消えるので、**縦切りの間は刻限をその階層のノード数に揃えます**（最小の 1 階層なら 6）。確かめたいのは「刻限が尽きると次の階層へ押し出される」挙動なので、予算はノード数ぴったりで足ります。満寸の階層へ広げるときに 10 へ戻します。

## 4. 最初に通す最小の 1 階層（ノード 6）

### 4.1 形

```text
            [1 入口 / 通常戦闘]           <- 必ず戦闘。操作の導入
               /          \
      [2 休息]              [3 情報収集]  <- 回復か、手記かの二択
               \          /
        [4 通常戦闘]   [5 精鋭]           <- 安全か、厚い報酬かの二択
               \          /
            [6 階層ボス]                  <- 出口
                  |
            （階層間の休憩）-> 階層 2
```

- 接続は縦だけです。横移動は入れません（§2.2）
- 1 行に 2 ノードが並ぶ段が 2 つあり、**プレイヤーが選ぶ分岐は 2 回**です
- 階層間の休憩はノードではありません。刻限を使わず、瘴気もたまりません
- **一度踏んだノードを通り直すのは無料です**（#97 で明文化）。刻限を払うのは新しいノードに入るときだけなので、分岐の片側へ寄ってから戻り、もう片側へ行けます。4 刻限で踏破、6 で両側という §4.2 の数はこの規則から出ます

### 4.2 1 周で何が起きるか

| 刻限 | ノード | 起きること |
| --- | --- | --- |
| 1 | 入口 | 通常戦闘 1 戦。減った HP とスタミナを持ち越す |
| 2 | 休息 / 情報収集 | 休息なら HP 15% とスタミナ全回復。情報収集なら敵の開示度が 2 段目へ |
| 3 | 通常戦闘 / 精鋭 | 精鋭は報酬が厚く、消耗も大きい |
| 4 | 階層ボス | 撃破で階層 2 へ。倒せずに死ぬとここが死亡地点になる |
| 5〜6 | 余白 | 踏まなかった側へ寄り道できる。瘴気は行動ごとにたまる |

4 刻限で踏破でき、6 まで使うと分岐の両側を取れます。**瘴気が「全部取る」を罰する**構図が、この 6 ノードだけで成立します。

### 4.3 検証の合格条件

- 階層 1 の 6 ノードが生成され、入口が戦闘、最後がボスになる
- ノードを踏むたびに刻限が 1 減り、瘴気が階層の濃度分たまる
- 瘴気 20% ごとに最大スタミナが 1 減り、その値が戦闘へ持ち込まれる
- HP とスタミナがノードをまたいで持ち越される
- 刻限 0 で次の階層へ押し出される
- ボス撃破で階層間の休憩へ移り、HP 30% 回復とスタミナ全回復が起き、瘴気がたまらない

## 6. 探索の画面（#101）

### 6.1 役割と約束

探索の画面は、探索のコア（`unity-port/DungeonCore/`）が持つ 1 階層ぶんの状態を映します。戦闘の画面と同じく、**View は値を計算しません**。画面に出す数値と文言は、純 C# の組み立て役（`Assets/View/Exploration/Script/`）がコアから読んで渡します。

1 歩先の予告もコアが出します。組み立て役は、進めるノードごとにコアの遷移（`ExplorationReducer.Step`）をその場で 1 回試し、試した結果の刻限・瘴気・最大スタミナ・HP をそのまま予告に書きます。予告と実際に踏んだ結果は、同じ関数から出るので必ず一致します。

### 6.2 画面に出す値

| 値 | 置き場所 | 中身 | 変わるとき |
| --- | --- | --- | --- |
| 層の名前 | 上の帯の左 | 「第 N 層」と層の名前。第 2 層は秘跡の彫りを拾うまで「■■の秘跡」と書く（`world-v1.md`） | 層を降りたとき、彫りを拾ったとき |
| 刻限 | 上の帯 | 残りと層の刻限（「刻限 7 / 10」）と、残りの数だけ埋まった目盛り | 新しいノードに入ったとき |
| 瘴気 | 上の帯の中央 | 10 目盛りのゲージと %。20% ごとの線。次の新しいノードで増える量（「次の 1 歩で +3%」） | 新しいノードに入ったとき、消耗品 |
| HP | 上の帯の右 | 「HP 38 / 50」 | 休息、戦闘、階層間の休憩 |
| スタミナと最大 | 上の帯の右 | 「スタミナ 8 / 9」と最大の内訳（「最大 9 = 10 − 瘴気 1」。一時の増減があれば足す） | 1 歩ごと、休息、戦闘 |
| 訓練の刻み | 上の帯の右 | この層の休息ノードで訓練を選んだ回数 | 訓練を選んだとき |
| 地図 | 左 7 割 | ノードと道。入口が上、階層ボスが下 | 1 歩ごと |
| ノードの詳細 | 右の欄 | 選んだノードの中身と、1 歩の予告と、進むボタン | ノードを選んだとき |
| 持ち物 | 右下 | ツールの一覧と消耗品 3 枠。消耗品は押すと使う。階層の切れ目の札が出ている間も使える | 消耗品を使ったとき |
| 「この生を終える」 | 左下 | 生存ルートの入口（§6.6） | 常に出す。生が終わったら消す |
| 手記 | 上の帯の右端 | 手記のドロワーを開くボタン。キーは J（§6.7） | — |
| 所持カード | 上の帯の右端（手記の右） | 所持カードの画面を開くボタン。キーは C | — |
| 設定・セーブ | 上の帯の右端（所持カードの右、いちばん端） | 設定・セーブの画面を開く歯車のボタン。キーは Esc | — |

上の帯の右端には、左から「手記」「所持カード」「設定・セーブ」の 3 つのボタンを並べます。所持カードと設定・セーブは、手記とは別の画面です。中身は `camp_document/CAMP_FACILITIES_DESIGN.md` §3.4 と §3.5 が決め、本書は探索中の置き場とキーだけを決めます。

- **所持カード**は、今のキャラクターが持つカードの現在の名称・習熟度・永続能力を読むだけの画面です。戦闘デッキは組み替えられません。
- 習熟が伸びて名称が変わるのは戦闘の後です。そのため、探索の途中で所持カードを確かめられるようにします。
- 所持カードのキーは C で、もう一度 C かボタンを押すと閉じます。C は、手記の J とも、戦闘のキー（`battle_ui_ux_v2.md` §3.4）とも重なりません。
- **設定・セーブ**は、戦闘の速さ・演出短縮・音の大きさの設定と、「保存してゲームを閉じる」を置く画面です。キーは Esc です。
- Esc は、確認の札が開いていればそれを先に閉じます。確認の札がなく、手記のドロワーか所持カードの画面が開いていれば、そちらを先に閉じます。
- どれも開いていないときだけ、Esc で設定・セーブの画面を開閉します。
- 「保存してゲームを閉じる」は、今の状態を保存してゲームを閉じる操作です。生は終わりません。
- 「この生を終える」（左下、§6.6）は、生を終える操作で、保存とは別です。押し間違えないように、歯車は上の帯の右端に置いて左下から離します。
- 保存して閉じた後に起動すると、保存した地図の場面から再開します（`requirements/tier1-core.md` R1-16）。
- 戦闘の札（§6.8）が出ている間は戦闘中と同じ扱いにし、所持カードと設定・セーブのボタンを押せなくします。
- 設定・セーブを止めるのは、戦闘の状態が保存の中身に入らないためです（`CAMP_FACILITIES_DESIGN.md` §3.5）。所持カードを止めるのは、戦闘で使うのが戦闘デッキだけだからです（同 §3.4）。

### 6.3 地図とノードの段階開示

ノードは立ち位置で 5 つに分けます。

| 立ち位置 | 条件 | 見せ方 | 押したとき |
| --- | --- | --- | --- |
| 今いる | プレイヤーが立っているノード | 太い枠。種別と中身を出す | 詳細を読めるだけ |
| 進める | 隣にあり、まだ踏んでいない。刻限が残る | 明るい枠。種別と中身を出す。道も明るくする | 詳細の欄に予告と「進む」を出す |
| 戻れる | 隣にあり、もう踏んだ | 細い枠。「刻限を使わない」と書く | 詳細の欄に「移る」を出す |
| 踏んだ | 隣ではなく、もう踏んだ | 薄くする。種別と中身は残す | 詳細を読めるだけ |
| 遠い | 隣ではなく、まだ踏んでいない | 種別の字だけを出す | 種別だけを読める |

遠いノードは種別しか見せず、隣と踏んだノードは中身まで見せます（§2.1 のノードの段階開示）。中身の行は種別ごとに次のとおりです。

| 種別 | 中身の行 |
| --- | --- |
| 通常戦闘 | 脅威度「通常」。敵の名前（開示度 1 から）。開示度 2 なら傾向の行を足す |
| 精鋭 | 脅威度「精鋭」。避けて通れること。敵の名前は通常戦闘と同じ扱い |
| 階層ボス | 脅威度「階層の主」。倒すと階層間の休憩へ進むこと |
| 休息 | 「休む」の回復量（HP の実数と %、スタミナ全回復、最大スタミナ +2）と「訓練する」（刻み 1）の二択 |
| 情報収集 | この層の敵 1 種の開示度が 2 段目へ上がること |
| イベント | 泉 / 重い宝箱 / 特殊な食事 のどれかが起きること |
| 痕跡 | 受け取りの状態で変わります。まだどの痕跡も踏んでいない生には、前の生の遺産が残っていることと、最初に踏んだ痕跡だけを受け取れること（1 つの生で 1 件）を出します。踏んだ後は、受け取る痕跡がここか別の層かを出します。選んだ後は「この生は既に遺産を受け取った」を出します。選ぶ画面がつながるまでは「遺産を選ぶ画面はまだ出ない」も足します（§7.7） |
| 秘跡の彫り | この層の名前が分かること。戦闘には効かないこと |

敵の名前と開示度は、手記（§6.11）から取ります。開示度 0 の敵は「？」です。組み立て役は敵の情報を差し込み口（`IEnemyIntel`）から受け取るので、差し込む側を替えても画面の側は変わりません。情報収集ノードを踏んだ層では、差し込み口に「この層は情報収集を済ませた」と伝え、差し込み口がその層のボスの枠の敵を開示度 2 で返します。

### 6.4 1 歩の予告

進めるノードを選ぶと、詳細の欄に予告を出します。予告は選び方ごとに 1 行です。「刻限 7 → 6」と「瘴気 38% → 41%」を必ず書き、変わるときだけ「最大スタミナ 9 → 8」「スタミナ 5 → 8」「HP 30 → 38」を足します。

予告には、次の 3 つの警告を添えます。

- **最大スタミナが下がる**: 瘴気が 20% の線を越え、最大スタミナが実際に下がるとき。「瘴気が 40% を越え、最大スタミナが 9 から 8 に下がります」と書きます。休息の「休む」は最大スタミナを +2 するので、線を越えても最大が下がらなければ出しません
- **瘴気死**: そのノードで瘴気が 100% に届くとき。「ここで瘴気が 100% に達し、この生が終わります」と書きます。進むボタンを押すと確認の札を 1 回挟みます
- **押し出し**: そのノードで刻限が尽き、しかも階層ボスではないとき。「刻限が尽き、この層の行動が終わります」と書きます

休息ノードは「休む」と「訓練する」の 2 つのボタンを並べ、それぞれの予告を出します（§3.2 の二択）。上の帯の瘴気のゲージには、次の新しいノードで増える分を薄い色で先に描きます。

### 6.5 階層の切れ目

階層ボスを倒したときと、刻限が尽きて押し出されたときは、地図の上に札を出し、「階層間の休憩へ」で休憩の画面に移ります。

休憩の画面には、休憩で起きること（HP 30% 回復とその実数、スタミナ全回復、瘴気はたまらない）と、次の層の予告（層の名前、1 刻限ごとに増える瘴気、刻限の数）を出します。ボタンは「次の層へ降りる」と「この生を終える」の 2 つです。

休憩の画面の右上には、地図の画面の上の帯と同じ並びで「手記」「所持カード」「設定・セーブ」の 3 つのボタンを置きます（§6.2）。キーも同じ J・C・Esc です。所持カードは、この層の戦いで伸びた習熟を、次の層へ降りる前に確かめられるように置きます。設定・セーブの歯車は右上の端に置き、下の「この生を終える」から離します。「保存してゲームを閉じる」で閉じたときは、次に起動するとこの休憩の画面から再開します。

次の層の入口ノードは着いた時点で踏んだことになるので、降りると 1 歩ぶんの瘴気がすぐにたまります。降りた入口で瘴気が 100% に届くときは、休憩の画面に「降りると入口で瘴気が 100% に達し、この生が終わります」と書き、「次の層へ降りる」を押すと確認の札を 1 回挟みます。休憩の間も消耗品は使えるので、浄化の香で瘴気を戻してから降りる道が残ります。

最後の層で押し出されたときは、降りる先がありません。休憩の画面は「この生を終える」だけを出します（§5 の 6）。

### 6.6 「この生を終える」

生存ルートの入口です。探索中はいつでも押せて、階層間の休憩の画面にも同じボタンを置きます。押すと確認を 1 回挟み、確認の札には「生きたまま次の生へ移ります。手記は丸ごと次の生へ渡ります」と書きます。受け継ぎの中身（手記の全頁と生存者ボーナス）は #108 が入れます。

コアでは `ExplorationReducer.EndLife` が生を閉じ、状態は `RunPhase.Survived` になります。刻限も瘴気も動かさず、以後の遷移は受け付けません。

### 6.7 手記のドロワー

右から幅 30% で開くドロワーで、上の帯の手記のボタンか J で開閉します。戦闘の手記ドロワー（`battle_ui_ux_v2.md`）と同じ部品を使い、頁の型（`Assets/View/Journal/Script/` の `JournalPage`）を共有します。

- タブは「敵・ダンジョン・メモ」の 3 つに、用語と状態の頁を足した形です（#234、2026-10-03 のこうだいさんの決定。`requirements/tier1-core.md` R1-10、`CAMP_FACILITIES_DESIGN.md` §3.3）。左から「敵ごと / ダンジョン / メモ / 用語」の順に並べます
- 頁の型の `JournalTab` には、用語と状態の頁のための値を 1 つ足します
- 探索中はどのタブも開けます。戦闘中に開けるのは、いま戦っている敵の頁と、用語と状態の頁だけです
- 戦闘中は、ダンジョンの頁とメモのタブを暗くして押せなくします（`battle_ui_ux_v2.md` §2.4）
- 用語と状態の頁は、上に用語、下に状態の 2 つの見出しを持つ規則の説明です。中身と見た目は `art_document/battle-visual-v1.md` §7.3 と §7.5 に従います
- 用語と状態の頁は開示度を付けず、最初の生から全項目が読めます。痕跡と遺産の対象から外し、死亡の後も残します
- 開示度は敵の頁の見出しの脇に「開示度 1 / 2」と書きます。開示度が足りない行は「？」にします
- ダンジョンの頁は、今の層の名前・1 刻限ごとの瘴気・刻限・ノードの内訳・情報収集を済ませたかを書きます。値はコアの層の数値から取ります
- 敵の頁、ダンジョンの頁の出来事、メモの中身は §6.11 が決めます。この層に開示度 1 以上の敵がいないときは、「敵の頁はまだありません」の頁を 1 枚置きます

### 6.8 戦闘との往復

戦闘・精鋭・階層ボスのノードに入ると、探索はそのノードで誰と戦うかを層の出会いの表（`encounters_and_rewards_v4.md` §2）から引き、戦闘へ渡します（#99）。

| 向き | 中身 |
| --- | --- |
| 探索 → 戦闘 | 層、ノードの種類、敵の並び（1 つの戦闘の敵の順と、続けて戦う戦闘の順）、場のマス数（`seven_layers_v4.md` §2.4）、HP と最大 HP、スタミナ、最大スタミナ（瘴気と一時変化を数えた後の値）、敵ごとの開示度、デッキ（その生の習熟で育った札）、戦闘で効くツールの量 |
| 戦闘 → 探索 | HP、スタミナ、習熟の刻み、観察の結果（開示度は戦闘の終わりに上がる）、習得した固有の札、死亡 |

- **シーンは分けます。** 戦闘のシーンを探索のシーンの上に重ねて読み込み、戦闘が終わったら外します。探索のシーンは読み込んだまま隠すので、探索の状態はそのまま残ります。戦闘のシーンは Unity のリポジトリで作ったものをそのまま使います。
- **2 戦続く精鋭は**、1 戦目の HP とスタミナを 2 戦目へ持ち越します。1 戦目で倒れたら、そこで終わります。
- **開示度は**、戦った敵が少なくとも 1 になり、観察の札を出した戦闘の敵は 2 になります。2 体が並ぶ戦闘では、予兆に渡す開示度を 2 体の低いほうにします。
- **固有の札は**、本物のボスを倒すと 3 種、四層と五層の代役のボスを倒すとその精鋭の 2 種を覚えます。本物の精鋭を倒すと、その精鋭の札 2 種から 1 種を選びます（`encounters_and_rewards_v4.md` §4.2）。覚えた札は、デッキに空きがあれば 1 枚入ります。
- **戦闘のシーンを読み込めないとき**（ビルドの設定に入っていないときなど）は、地図の上の仮の札に戻ります。札の「勝ったことにする」は HP とスタミナを変えず、「倒れたことにする」は HP を 0 にします。どちらの道も、コアの `ExplorationReducer.ReportBattle` を通ります。

受け渡しの C# は `unity-port/unity-project-kit/Assets/View/Exploration/Bridge/`（`Expedition` と `EncounterBattle`）にあり、`dotnet test`（`unity-port/Exploration.Bridge.Tests/`）で確かめます。

### 6.9 終わりの画面

生の終わりは 4 通りで、どれも地図の上に札を出します。

| 終わり方 | 札の文 |
| --- | --- |
| 瘴気死 | 瘴気が 100% に達し、第 N 層でこの生が終わった |
| 倒れた | 第 N 層の戦いで倒れた |
| 踏破 | 歪みの根を倒した |
| 生存ルート | 生きたまま、この生を閉じた |

札のボタンは「新しい生で潜り直す」の 1 つで、乱数の種を変えて第 1 層からやり直します。死亡地点・遺産・継承の間へつなぐのは #104 と #106 です。

### 6.10 見た目と Unity への写し方

瘴気のゲージと瘴気で暗くなる画面、地図の奥の背景と幕のほかは、見た目は仮です。ノードは灰色の四角に種別の 1 字（戦・精・主・休・調・事・痕・彫）を置き、色は灰色の濃淡と強調の 1 色だけを使います。色・書体・ノードの絵は design の担当と #90 が決め、決まったら View の側だけを差し替えます。

ゲージと暗さの色・不透明度・動きは、`art_document/battle-visual-v1.md` §2.5 に従います（#613）。値は `Assets/View/Backdrop/Script/MiasmaLook.cs` から読みます。強調の 1 色（琥珀）はゲージに使いません。琥珀はプレイヤーの側の色だからです。

- ゲージの塗りは、燐光から菫へ % に比例して寄せます。目盛りは 10% ごとに 9 本です。新しい % へは 500 ms かけて伸び、80% からは塗りが息づきます。
- 次の 1 歩の分が注意の色になるとき（20% の線を越える 1 歩と、100% に届く 1 歩）は、上の帯の予告の文の頭に「△ 」を付けます。△ を付けるのはこの予告の文だけです。休息の「休む」のように最大スタミナが上がる行動の警告は、§6.4 のとおり最大スタミナそのもので判断します。
- 地図の奥には、いまの層の背景と地 `#10141d` の幕を敷きます（`battle-visual-v1.md` §2.5、#614）。奥から「地 → 層の背景 → 幕 → 暗さ → 地図・上の帯・右の欄」の順です。背景と幕の値は `Backdrop.ExplorationBackdropSpec` から読み、背景は `Backdrop.View.BackdropLayers` が描きます。地図の下にパネルは敷かず、ノードと道と文字を、幕を掛けた背景の上に直に描きます。
- 層を降りたときは、背景と幕の不透明度を 400 ms（`BackdropSpec.CrossfadeMs`）で切り替えます。戦闘の背景は `BackdropView` が描くので、探索の画面は `BackdropView` を置きません。
- 暗さは幕と地図のあいだに描き、上の帯と右の欄には掛けません。組み立て役（`View/Exploration/Script/`）は △ を決めるために、`Backdrop.Script` を参照します。

| 置き場所（`unity-project-kit/Assets/`） | 中身 |
| --- | --- |
| `DungeonCore/` `DungeonContent/` | 探索のコアと持ち物の目録の写し。原本は `unity-port/DungeonCore/` と `DungeonContent/` |
| `View/Exploration/Script/` | 画面の組み立て役（純 C#）。コアの状態から画面の値を作り、操作をコアへ渡す |
| `View/Exploration/` | 画面（UGUI）。組み立て役が作った値を置くだけ |
| `View/Journal/` | 手記のドロワー。頁の型（純 C#）と画面。戦闘の画面からも使える形にしてある |

組み立て役と頁の型は `dotnet test`（`unity-port/Exploration.Script.Tests/`）で確かめます。画面を動かすのは Unity のシーンで、空の GameObject に `ExplorationBootstrap` を付けると画面が全部コードで組み上がります。

### 6.11 手記の中身と開示度（#107）

手記は、敵の頁・ダンジョンの頁・メモの 3 種と、用語と状態の頁でできています。用語と状態の頁は §6.7 のとおりで、ここでは扱いません。手記は 1 つの生のものです。新しい生は、空の手記から始まります。遺産と生存ルートで次の生へ渡す手順は #106 と #108 が決めます。

**敵の頁**は、`enemy_document/enemy_roster_v4.md` の各敵の「手記」の 4 文をそのまま使います。4 文は、間合い 0・間合い 1〜2・間合い 3 以上の動きと、弱点です。ボス 3 体と竜神の頁には、適応の条件も載せます。ロースター §1.5 が「開示度 2 では条件そのものが手記の頁に書かれます」と決めているためです。ロースターは 4 文について「開示度 2 で全部見える」とだけ書き、開示度 1 で読める文を決めていません。そこで、本書が次のように切ります。

| 開示度 | 読める行 | 理由 |
| --- | --- | --- |
| 0 | どの行も「？」 | まだ会っていない |
| 1（遭遇） | 間合い 0・1〜2・3 以上の 3 行 | 戦ったときに目の前で見た動きだから |
| 2（観察か情報収集） | 上の 3 行に、得意な間合いと弱点を足した全部。ボスと竜神は、適応の条件の行も足します | 弱点と適応の条件は、見た動きを読み解いた結果だから。適応の条件はロースター §1.5 が開示度 2 に置いているから |

- ロースターに手記を持つのは 14 体です（通常 7、精鋭 3、ボス 3、竜神）。§8 の 8 体はまだ手記が無いので、頁もありません
- 文はロースターから写します。ロースターの手記が変わったら、写しの `Assets/View/Journal/Script/EnemyJournal.cs` も直します
- 適応の条件の文は、ロースターの適応の表（§4.4・§5.4・§6.4・§7.11）の「条件（手記の文）」の列から、表の順に写します。行の見出しは「適応 1」「適応 2」…です。セルク・ガルド・竜神は 4 行、歪みの根は 7 行になります。HP で段階が替わる条件も表の行なので、同じく載せます
- 地図の戦闘ノードは、開示度 1 から敵の名前を出し、開示度 2 で傾向の行（「傾向: 錆槍の竜兵は得意な間合い 1〜2」）を足します（§6.3）
- 2 体が同時に出る戦闘は「錆槍の竜兵 + 灰弩の竜兵」、続けて戦う 2 戦は「錆槍の竜兵 → 瘴牙の走竜」と書きます。開示度 0 の敵だけを「？」にし、出す開示度はノードの敵のうち最も低い値です。1 つの戦闘に 2 体が出るときは、予兆に渡す値と同じです（§6.8）。続けて戦う 2 戦では、地図は 2 戦を通して最も低い値を出し、予兆は戦闘ごとにその戦闘の敵の値で出ます
- 地図の予告に出す敵は、ノードに着いたときに引く敵と同じです。同じ種から引くためです

**開示度の上がり方**は次の 3 つです。

- **遭遇**: 戦った敵は、戦闘の終わりに少なくとも 1 になります（§6.8）
- **観察**: 観察の札を出した戦闘の敵は、戦闘の終わりに 2 になります（§6.8）
- **情報収集**: 情報収集ノードを踏むと、その層のボスの枠の敵がすぐに 2 になります。その生が終わるまで 2 のままで、層を降りても下がりません。ボスの枠の敵は、`encounters_and_rewards_v4.md` §2 の代役を含めた敵です（一層は瘴牙の走竜、二層は瘴甲の竜兵、三層は大黒蛇 セルク、四層は鉄壁の門竜、五層は不退の槍竜、六層は獄竜 ガルド）。七層には情報収集ノードがありません。ボスを選んだのは、層のどの道を通っても最後に必ず戦う相手で、2 行動の予定と数字が開示度で変わる相手だからです

七層のボスの歪みの根も、新しい生では他の敵と同じく開示度 0 から始まります。`seven_layers_v4.md` §4 と §9 の 2 には、七層に情報収集を置かない代わりに、歪みの根の手記を最初から開示度 2 にする案がありました。この案は採りません。`concept-v3.md` §12-9 が、2 段目に上げる手段を観察の札と情報収集に限っているためです。七層のボスを開示度 2 で読むには、その戦闘で観察の札を出すか、前の生の頁を遺産で受け継ぎます。遺産で受け継ぐ手順は #106 が決めます。

どの上がり方でも、次の戦闘の予兆は上がった開示度で出ます（`OmenDisclosure`、#500）。

**ダンジョンの頁**は、層ごとに 1 枚です。上に層の数値（§6.7）を置き、その下に、その層で分かることを出来事ごとに並べます。出来事は「近道」「条件出現」「イベント」の 3 種で、出来事ごとに開示度を持ちます。

| 開示度 | 出来事の行 | 上がるとき |
| --- | --- | --- |
| 0 | 「？」 | — |
| 1 | 起きたこと（例: 「HP が最大の 20% 戻る」） | その生で、その層でその出来事が起きたとき |
| 2 | 起きたことに、出る見込みか条件を足す（例: 「この層のイベントは 2 つで、1 つ目が泉になる見込みは 50%。2 つ目は 1 つ目と違う種類になる」） | その層の希少な頁を読んだとき |

- 「？」の行を残すのは、その層にまだ知らないことがあると分かるようにするためです
- 中身を持つのはイベントだけです。`encounters_and_rewards_v4.md` §5 の表から、一層から三層に泉・重い宝箱・特殊な食事の 3 件、七層に重い宝箱と特殊な食事の 2 件を置きます。四層から六層にはイベントが無いので、出来事もありません
- 近道と条件出現は、書く場所だけを用意しました。中身はまだありません（§2.2）
- **希少な頁**（`encounters_and_rewards_v4.md` §4.3）は、その層の出来事のうち開示度 2 でないものから 1 つを等確率で選び、2 にします。選べる出来事が無ければ、頁はカードに替わります（同 §4.3）。希少な頁で敵の開示度は上げません。2 段目に上げるのは観察と情報収集だけだからです（`concept-v3.md` §12-9）

**メモ**は、プレイヤーが書いた文をそのまま持つだけです。ゲームは中身を読まず、どの数値も変えません。何件でも書け、書き直しと消去ができます。ドロワーでは 1 枚のメモの頁に全件を「メモ 1」「メモ 2」の見出しで並べます。番号は書いた順で、消しても詰めません。

**遺産の一覧に並べる 1 行の形**: `concept-v3.md` §14 は、遺産の候補に習熟 1 段以上のカードと埋まった頁を全部並べ、そのために手記をコンパクトで整然とした形にすると決めています。そこで、埋まった頁を 1 頁 1 行、「種類｜題｜中身」の 3 欄で書きます。

| 頁 | 埋まったとみなす条件 | 1 行の例 |
| --- | --- | --- |
| 敵の頁 | 開示度 1 以上 | 敵｜錆槍の竜兵｜開示度 2 / 2（弱点まで） |
| ダンジョンの頁 | その層の出来事が 1 件以上、開示度 1 以上 | ダンジョン｜第 1 層｜分かったこと 2 件（うち中身まで 1 件） |
| メモ | 空白でない 1 件ごと | メモ｜メモ 1｜書いた文の 1 行目（20 字を超える分は「…」） |

- 並べる順は、ドロワーのタブと同じ「敵・ダンジョン・メモ」です。敵はロースターの順、ダンジョンは上の層から、メモは書いた順です
- メモは 1 件ずつ選べるように、1 件を 1 行にします
- 用語と状態の頁は並べません（§6.7）

**旧い計画書から拾ったもの**: `journal_document/journal_system_implementation_plan.md`（V3.0、一部を置き換え済み）からは、敵の行動と弱点を書く頁、ダンジョンのイベントとその結果を書く頁、何件でも書けて探索中も書き直せるメモ、知らない項目を「？」で見せる形を拾いました。カードと装備の図鑑、撃破数とドロップ率、収集率の表示、メモの分類タグは拾いませんでした。装備と経済は凍結中で、所持カードは手記とは別のボタン（§6.2）で開くためです。収集率と分類タグは、遺産の一覧を簡潔に保つのに要らないためです。

**実装**は純 C# です。頁の中身と 1 行の形は `Assets/View/Journal/Script/`（`EnemyJournal` `DungeonJournal` `JournalMemo` `JournalLines`）、1 つの生の手記は `Assets/View/Exploration/Script/LifeJournal.cs` です。`LifeJournal` は探索の画面の差し込み口（`IEnemyIntel`）で、`Exploration.Bridge.Expedition` が作って探索に渡します。戦闘が残した開示度は `Expedition` が持ち、`LifeJournal` はそこに情報収集の分を足して返します。戦闘の報酬の希少な頁は、`Expedition.Return` が 1 枚ごとに `LifeJournal.DrawRarePage` で読み、その層の出来事を 1 つ開示度 2 にします。選べる出来事が無い頁は、カードに替えます（`encounters_and_rewards_v4.md` §4.3）。メモを書く入力欄、遺産の一覧の画面、イベントを解決して出来事を開示度 1 にする呼び出しは、まだつないでいません。

## 7. 死亡と痕跡と遺産（#106）

`concept-v3.md` §8.3・§8.4・§14 の決定を、探索の規則に落とした節です。規則は探索のコアの `Heritage` と `TraceLedger`（`unity-port/DungeonCore/`）が持ち、`dotnet test`（`unity-port/DungeonCore.Tests/`）で確かめます。

### 7.1 死亡の確定

生が死亡で終わるのは 2 通りです。戦闘で HP が 0 になったとき（倒れた）と、瘴気が 100% に達したとき（瘴気死）です。どちらも、その状態になった時点で死亡を確定し、痕跡を 1 つ残します。

- 痕跡を残すのは、探索の流れを持つ `ExplorationSession` です。ノードに入ったとき、戦闘の結果を受け取ったとき、層を降りたとき、生を始めたときの 4 か所で、状態が死亡かを確かめます。
- 1 つの生が残す痕跡は 1 つです。
- 生存ルート（§6.6）と踏破は死亡ではないので、痕跡を残しません。

### 7.2 痕跡の中身

痕跡は次の 5 つを持ちます。

| 項目 | 中身 |
| --- | --- |
| 名前 | 死んだ者の名前。世代ごとの名前は #110 が入れます。それまでは「N 代目」と書きます |
| 層 | 死んだ層 |
| ノードの種類 | 死んだときに立っていたノードの種類。終わりの文に使うだけで、置き場所には使いません |
| 死因 | 倒れたか、瘴気死か |
| 候補の一覧 | 遺産として選べるもの（§7.3） |

### 7.3 遺産の候補と選べる数

候補は、習熟 1 段以上のカードと、埋まった手記の頁です。カードを先に、段の高い順に並べ、その後に頁を並べます。

- **浅層での死の規則**: 1 段目のカードは、どの層で死んでも候補になります。2 段目と 3 段目のカードは、第 3 層より深い層（第 3 層を含む）で死んだときだけ候補になります。
- **頁**は、手記が「埋まった頁」として渡すものを全部並べます。1 頁は id と 1 行の題で持ちます。頁の中身と 1 行の形は手記（#107）が決めます。用語と状態の頁は候補にしません（§6.7）。
- 手記（#107）が入るまでは、その生の手記で開示度 1 以上の敵ごとに 1 頁を並べます。題は「錆槍の竜兵の頁」の形で、並びは敵の一覧の順です（`HeritagePicks.cs` の `DisclosedEnemyPages`）。
- **選べる数は 3 つまで**です。`requirements/tier1-core.md` R1-12 の「仮 3」をそのまま採りました。0 個を選んで確定することもできます。
- 確定すると痕跡は回収されて消えます。選ばなかった候補は、痕跡と一緒に失われます。

### 7.4 死亡地点の持ち方

**死亡地点は、層とノードの種類で持ちます。座標（ノードの番号や行と列）は持ちません。**

地図は、生ごとに新しい乱数の種から作り直します（`ExplorationSession.LayerSeed`）。前の生の座標は、次の生の地図では別のノードを指すか、どこも指しません。そのため、痕跡は「どの層か」だけで探します。

- 次の生がその層に入ると、地図の通常戦闘 1 つを痕跡のノードに入れ替えて作ります（`seven_layers_v4.md` §4）。
- 痕跡のノードは寄り道の側に置きます。同じ行には、寄り道でないノードが必ず 1 つ残ります。痕跡を踏まずにボスまで行けます。
- どの位置に置くかは、その層の乱数の種が決めます。同じ種なら同じ位置です。
- 1 つの層の地図に置く痕跡は 1 つです。同じ層に回収されていない痕跡が 2 つ以上あるときは、古いほうから 1 つずつ置きます。
- 痕跡のノードに戦闘はありません。入ると刻限を 1 使い、瘴気がたまるのは他のノードと同じです。

### 7.5 1 つの生で受け取れるのは 1 件

- 生が最初に踏んだ痕跡が、その生で受け取る痕跡になります。踏んだ時点で選ぶ画面が開きます（Unity の画面へのつなぎ込みはまだです。§7.7）。
- 同じ生で 2 つ目の痕跡を踏んでも、選ぶ画面は開きません。その痕跡は消えずに残り、後の生が受け取れます。
- 痕跡は回収されるまで残ります。後の死で上書きされることはありません。
- 選ぶ前に生が終わったときは、その痕跡は回収されずに残ります。
- 選ぶ画面は地図を止めません。戦闘の札の選択と同じように、地図の上に重ねて出します（Unity の画面へのつなぎ込みはまだです。§7.7）。

### 7.6 継いだものの行き先

- **カード**は段をそのまま継ぎます。継いだカードは所持カードになります。習熟の刻みは、その段に届く最低の数にそろえます。この生で既にそれより多く刻んでいれば、多いほうを残します。
- 戦闘デッキに同じ種類のカードが無く、デッキに空きがあれば、1 枚がデッキに入ります。同じ種類が既にデッキにあるときは、段だけが上がり、枚数は増えません。
- 3 段目を持てるのは 1 つの生で 1 枚だけです（`battle_core_v4.md` §17.8）。既に別のカードが 3 段目にあるとき、3 段目のカードは 2 段目で継ぎます。
- **頁**は、継いだ頁の一覧として手記（#107）へ渡します。

### 7.7 選ぶ画面

選ぶ画面の中身は、純 C# の組み立て役（`Assets/View/Exploration/Bridge/HeritagePicks.cs`）が作ります。札を選ぶ画面（#626）と同じ形です。

| 置くもの | 中身 |
| --- | --- |
| 題 | 「死亡地点の痕跡: 遺産を選ぶ」 |
| 説明 | 「1 代目は第 3 層の階層ボスで倒れた。3 つまで継げます。選ばなかったものは失われます。」のように、誰が・どの層の・どのノードで・どう死んだかと、選べる数を書きます |
| カード | 継ぐ段での札の面と、その下に「習熟 N 段目」 |
| 頁 | 頁の 1 行の題と、その下に「手記の頁」 |
| 確定 | 「これを継ぐ」のボタンと、「選んだ数 2 / 3」 |

候補を押すと選び、もう一度押すと外します。3 つ選んだ後は、4 つ目を押しても選べません。

Unity の探索画面へのつなぎ込みは、まだ入っていません。別の Issue で入れます。それまでの Unity では、痕跡のノードを踏むと受け取りの権利だけが付き、選ぶ画面は出ません。そのため、その生は遺産を受け取れません。痕跡は消えずに残ります。痕跡のノードの中身の行は、受け取れると約束せず、「遺産を選ぶ画面はまだ出ない」と書きます（§6.3）。
