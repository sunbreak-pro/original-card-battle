## 2. 要素の選別

「80% 版」は、出立 → 階層 1 → 戦闘 → 次の階層 が Unity で 1 周通る版を指します（#94 の Definition of Done）。判断の基準は 2 つです。**ループの 5 要素（習熟 / 間合い / スタミナ / 手記 / 崩壊の暦）のどれかに直接つながるか**と、**無いと 1 周が成立しないか**です。

### 2.1 残す（13 件）

| 要素 | 形 | 残す理由 |
| --- | --- | --- |
| 通常戦闘ノード | 踏むと 1 戦。1 日 | 階層の主成分。これが無いと探索が移動だけになる |
| 精鋭ノード | 寄り道に置く。報酬が厚く、HP とスタミナを多く削る | 「安全に通すか、削られても取るか」の分岐を作る |
| 階層ボスノード | 階層の出口。撃破すると次の階層へ | 階層の区切りが無いと、降りるか生を閉じるかを選ぶ場所が無い |
| 休息ノード（階層内） | HP 15% 回復 / スタミナ全回復 / 最大スタミナ +2。1 日進む | HP の持ち越しに対する唯一の階層内の答え |
| 習熟訓練 | 休息ノードの二択の片方。指定した 1 枚に刻み 1 | 探索から習熟へ届く唯一の線。§14 で決定済み |
| 情報収集ノード | 手記の開示度を 2 段目へ上げる。対象はこの階層の敵 1 種 | 手記を探索側から動かす。戦闘の予兆の精度に直結する |
| イベント 3 種 | 泉（HP 回復）/ 重い宝箱（貴重品 + 最大スタミナ -2）/ 特殊な食事（最大スタミナ +1 + 代償） | 探索の選択が戦闘の数値を変える例を、最小の数だけ持つ |
| 階層間の休憩 | HP 30% 回復 / スタミナ全回復 / 日数を使わない | 階層の切れ目。ここで次へ潜るか生を閉じるかを選ぶ |
| 死亡地点の痕跡 | 前の生の遺産を回収する。1 つの生で 1 件 | 継承のループが探索に現れる唯一の点 |
| 崩壊の暦 | 新しいノード 1 つで 1 日。全ての生で共有し、0 で世界が終わる | 探索の圧力そのもの。寄り道の値打ちを日数で測らせる |
| 降り口 | 中ボスか王を倒すと開き、次の代から出立の地点に選べる（`seven_layers_v4.md` §4） | 浅い層を歩き直す日数を減らす。暦と組で効く |
| ノードの段階開示 | 遠い = 種別アイコンだけ。隣接 + ホバー = 中身（敵名 / 脅威度 / 回復量） | 選ぶ材料が無いと、ノードの分岐が運になる |
| 消耗品 3 枠 | 拾ったらその場で入れ替え | §14 で決定済み。拾得の受け皿が無いと報酬を置けない |

## 3. 満寸の階層の内訳（concept-v3 §12-1 への回答案）

### 3.1 満寸の階層（ノード 10〜12）

満寸の階層（ノード 11）を、次の配分で組みます。**真っ直ぐ抜けると 5 日、全部を踏むと 11 日** という形です。層ごとの値は `seven_layers_v4.md` §7 が持ちます。

| 用途 | 目安 | 内訳の中身 |
| --- | --- | --- |
| 通常戦闘 | 4 | 最短ルート上に 2、寄り道に 2。死亡地点の痕跡は、このうち 1 つと入れ替わる |
| 精鋭 | 1 | 寄り道側だけに置く。避けて通れる |
| 階層ボス | 1 | 出口。必須 |
| 休息 / 習熟訓練 | 2 | 休息ノード 2 つ。各ノードで「休む」か「訓練する」の二択 |
| 情報収集 | 1 | この階層の敵 1 種の開示度を 2 段目へ |
| イベント | 2 | 泉 / 重い宝箱 / 特殊な食事 から、同じ種類を重ねずに 2 |
| **合計** | **11** | |

最短ルート（入口 → 中段 3 行 → ボス）は 5 日です。寄り道は 1 つにつき 1 日を、全ての生で共有する暦から払います。層ごとの予算はありません。**寄り道で得る報酬と、次の代へ残す日数を比べさせます。** 暦が残り少ないほど「降りる」が強くなります。

### 3.2 二択を「1 ノード 1 回」の例外にしない

習熟訓練を休息ノードの中の追加行動にすると、1 ノードで 2 日使う例外ができます。そこで**休息ノードでは「休む」か「訓練する」のどちらか 1 つだけを選ぶ**形にします。1 日のまま、回復と習熟の取り合いが生まれます。

### 3.3 最小の階層（記録）

v4 では、縦切りの間だけ、刻限を階層のノード数に揃えていました（ノード 6 なら刻限 6）。2026-11-03 に刻限が無くなったので、この決まりは使いません。最小の階層でも、新しいノード 1 つで暦が 1 日進むだけです。

## 4. 最初に通す最小の 1 階層（ノード 6）

### 4.1 形

```text
            [1 入口 / 通常戦闘]           <- 必ず戦闘。操作の導入
               /          \
      [2 休息]              [3 情報収集]  <- 回復か、手記かの二択
               \          /
        [4 通常戦闘]   [5 精鋭]           <- 安全か、厚い報酬かの二択
               \          /
            [6 階層ボス]                  <- 出口
                  |
            （階層間の休憩）-> 階層 2
```

- 接続は縦だけです。横移動は入れません（§2.2）
- 1 行に 2 ノードが並ぶ段が 2 つあり、**プレイヤーが選ぶ分岐は 2 回**です
- 階層間の休憩はノードではありません。日数を使いません
- **一度踏んだノードを通り直すのは無料です**（#97 で明文化）。日数を払うのは新しいノードに入るときだけなので、分岐の片側へ寄ってから戻り、もう片側へ行けます。4 日で抜ける、6 日で両側という §4.2 の数はこの規則から出ます

### 4.2 1 周で何が起きるか

| 日 | ノード | 起きること |
| --- | --- | --- |
| 1 | 入口 | 通常戦闘 1 戦。減った HP とスタミナを持ち越す |
| 2 | 休息 / 情報収集 | 休息なら HP 15% とスタミナ全回復。情報収集なら敵の開示度が 2 段目へ |
| 3 | 通常戦闘 / 精鋭 | 精鋭は報酬が厚く、消耗も大きい |
| 4 | 階層ボス | 撃破で階層 2 へ。倒せずに死ぬとここが死亡地点になる |
| 5〜6 | 寄り道 | 踏まなかった側へ寄り道できる。暦は 1 日ずつ減る |

4 日で抜けられ、6 日使うと分岐の両側を取れます。**暦が「全部取る」に日数を払わせる**構図が、この 6 ノードだけで成立します。

### 4.3 検証の合格条件

- 階層 1 の 6 ノードが生成され、入口が戦闘、最後がボスになる
- 新しいノードを踏むたびに暦が 1 日減り、通り直しでは減らない
- 最大スタミナが一時的な変化だけで動き、その値が戦闘へ持ち込まれる
- HP とスタミナがノードをまたいで持ち越される
- 暦が 0 になると世界が終わり、最初からやり直す
- ボス撃破で階層間の休憩へ移り、HP 30% 回復とスタミナ全回復が起き、暦が減らない

## 6. 探索の画面（#101）

### 6.1 役割と約束

探索の画面は、探索のコア（`unity-port/DungeonCore/`）が持つ 1 階層ぶんの状態を映します。戦闘の画面と同じく、**View は値を計算しません**。画面に出す数値と文言は、純 C# の組み立て役（`Assets/View/Exploration/Script/`）がコアから読んで渡します。

1 歩先の予告もコアが出します。組み立て役は、進めるノードごとにコアの遷移（`ExplorationReducer.Step`）をその場で 1 回試し、試した結果の暦の残り・最大スタミナ・HP をそのまま予告に書きます。予告と実際に踏んだ結果は、同じ関数から出るので必ず一致します。

### 6.2 画面に出す値

| 値 | 置き場所 | 中身 | 変わるとき |
| --- | --- | --- | --- |
| 層の名前 | 上の帯の左 | 「第 N 層」と層の名前。第 3〜6 層は領域の名前も添える。名前の決まっていない層は「竜の領域 第 4 層」の形で書く。第 2 層は秘跡の彫りを拾うまで「■■の秘跡」と書く（`world-v1.md`、`seven_layers_v4.md` §3.4） | 層を降りたとき、彫りを拾ったとき |
| 暦 | 上の帯の中央 | 崩壊までの残りの日数（「残り 312 日」）。王が倒れていて暦が止まっているときは、そのことと王が戻るまでの日数（「竜王が戻るまで 41 日。暦は止まっている」） | 新しいノードに入ったとき、消耗品、王を倒したとき |
| HP | 上の帯の右 | 「HP 38 / 50」 | 休息、戦闘、階層間の休憩 |
| スタミナと最大 | 上の帯の右 | 「スタミナ 8 / 12」と最大の内訳（「最大 12 = 10 + 休息 2」。一時の増減を足した内訳） | 1 歩ごと、休息、戦闘 |
| 訓練の刻み | 上の帯の右 | この層の休息ノードで訓練を選んだ回数 | 訓練を選んだとき |
| 地図 | 左 7 割 | ノードと道。入口が上、階層ボスが下 | 1 歩ごと |
| ノードの詳細 | 右の欄 | 選んだノードの中身と、1 歩の予告と、進むボタン | ノードを選んだとき |
| 持ち物 | 右下 | ツールの一覧と消耗品 3 枠。消耗品は押すと使う。階層の切れ目の札が出ている間も使える | 消耗品を使ったとき |
| 「この生を終える」 | 左下 | 生存ルートの入口（§6.6） | 常に出す。生が終わったら消す |
| 手記 | 上の帯の右端 | 手記のドロワーを開くボタン。キーは J（§6.7） | — |
| 所持カード | 上の帯の右端（手記の右） | 所持カードの画面を開くボタン。キーは C | — |
| 設定・セーブ | 上の帯の右端（所持カードの右、いちばん端） | 設定・セーブの画面を開く歯車のボタン。キーは Esc | — |

上の帯の右端には、左から「手記」「所持カード」「設定・セーブ」の 3 つのボタンを並べます。所持カードと設定・セーブは、手記とは別の画面です。中身は `camp_document/CAMP_FACILITIES_DESIGN.md` §3.4 と §3.5 が決め、本書は探索中の置き場とキーだけを決めます。

- **所持カード**は、今のキャラクターが持つカードの現在の名称・習熟度・永続能力を読むだけの画面です。戦闘デッキは組み替えられません。
- 習熟が伸びて名称が変わるのは戦闘の後です。そのため、探索の途中で所持カードを確かめられるようにします。
- 所持カードのキーは C で、もう一度 C かボタンを押すと閉じます。C は、手記の J とも、戦闘のキー（`battle_ui_ux_v2.md` §3.4）とも重なりません。
- **設定・セーブ**は、戦闘の速さ・演出短縮・音の大きさの設定と、「保存してゲームを閉じる」を置く画面です。キーは Esc です。
- Esc は、確認の札が開いていればそれを先に閉じます。確認の札がなく、手記のドロワーか所持カードの画面が開いていれば、そちらを先に閉じます。
- どれも開いていないときだけ、Esc で設定・セーブの画面を開閉します。
- 「保存してゲームを閉じる」は、今の状態を保存してゲームを閉じる操作です。生は終わりません。
- 「この生を終える」（左下、§6.6）は、生を終える操作で、保存とは別です。押し間違えないように、歯車は上の帯の右端に置いて左下から離します。
- 保存して閉じた後に起動すると、保存した地図の場面から再開します（`requirements/tier1-core.md` R1-16）。
- 戦闘の札（§6.8）が出ている間は戦闘中と同じ扱いにし、所持カードと設定・セーブのボタンを押せなくします。
- 設定・セーブを止めるのは、戦闘の状態が保存の中身に入らないためです（`CAMP_FACILITIES_DESIGN.md` §3.5）。所持カードを止めるのは、戦闘で使うのが戦闘デッキだけだからです（同 §3.4）。

### 6.3 地図とノードの段階開示

ノードは立ち位置で 5 つに分けます。

| 立ち位置 | 条件 | 見せ方 | 押したとき |
| --- | --- | --- | --- |
| 今いる | プレイヤーが立っているノード | 太い枠。種別と中身を出す | 詳細を読めるだけ |
| 進める | 隣にあり、まだ踏んでいない | 明るい枠。種別と中身を出す。道も明るくする | 詳細の欄に予告と「進む」を出す |
| 戻れる | 隣にあり、もう踏んだ | 細い枠。「日数を使わない」と書く | 詳細の欄に「移る」を出す |
| 踏んだ | 隣ではなく、もう踏んだ | 薄くする。種別と中身は残す | 詳細を読めるだけ |
| 遠い | 隣ではなく、まだ踏んでいない | 種別の字だけを出す | 種別だけを読める |

遠いノードは種別しか見せず、隣と踏んだノードは中身まで見せます（§2.1 のノードの段階開示）。中身の行は種別ごとに次のとおりです。

| 種別 | 中身の行 |
| --- | --- |
| 通常戦闘 | 脅威度「通常」。敵の名前（開示度 1 から）。開示度 2 なら傾向の行を足す |
| 精鋭 | 脅威度「精鋭」。避けて通れること。敵の名前は通常戦闘と同じ扱い |
| 階層ボス | 脅威度「階層の主」。倒すと階層間の休憩へ進むこと |
| 休息 | 「休む」の回復量（HP の実数と %、スタミナ全回復、最大スタミナ +2）と「訓練する」（刻み 1）の二択 |
| 情報収集 | この層の敵 1 種の開示度が 2 段目へ上がること |
| イベント | 隣のノードになると、泉 / 重い宝箱 / 特殊な食事 のどれが起きるかと、その中身を出します（`encounters_and_rewards_v4.md` §5）。重い宝箱と特殊な食事には、受けるかどうかを選べることも足します。踏んだ後は、起きたことを足します。泉の 1 歩の予告には、戻る HP も数えます（§6.4） |
| 痕跡 | 受け取りの状態で変わります。まだどの痕跡も踏んでいない生には、前の生の遺産が残っていることと、最初に踏んだ痕跡だけを受け取れること（1 つの生で 1 件）を出します。踏んだ後は、受け取る痕跡がここか別の層かを出します。選んだ後は「この生は既に遺産を受け取った」を出します（§7.5） |
| 秘跡の彫り | この層の名前が分かること。戦闘には効かないこと |

敵の名前と開示度は、手記（§6.11）から取ります。開示度 0 の敵は「？」です。組み立て役は敵の情報を差し込み口（`IEnemyIntel`）から受け取るので、差し込む側を替えても画面の側は変わりません。情報収集ノードを踏んだ層では、差し込み口に「この層は情報収集を済ませた」と伝え、差し込み口がその層のボスの枠の敵を開示度 2 で返します。

### 6.4 1 歩の予告

進めるノードを選ぶと、詳細の欄に予告を出します。予告は選び方ごとに 1 行です。「暦 残り 312 → 311 日」を必ず書き、変わるときだけ「最大スタミナ 10 → 12」「スタミナ 5 → 8」「HP 30 → 38」を足します。暦が止まっているときは「暦は止まっている」と書きます。

予告には、次の警告を 1 つだけ添えます。

- **期限切れ**: そのノードで暦が 0 になるとき。「ここで暦が尽き、龍神が目覚めます。世界が終わり、最初からやり直します」と書きます。進むボタンを押すと確認の札を 1 回挟みます

v4 の警告のうち、瘴気で最大スタミナが下がる警告と瘴気死の警告は、瘴気と一緒に無くなりました。刻限が尽きて押し出される警告も、刻限と一緒に無くなりました。

休息ノードは「休む」と「訓練する」の 2 つのボタンを並べ、それぞれの予告を出します（§3.2 の二択）。上の帯の暦には、次の新しいノードで減る 1 日を薄い色で先に描きます。

### 6.5 階層の切れ目

階層ボスを倒したときは、地図の上に札を出し、「階層間の休憩へ」で休憩の画面に移ります。

休憩の画面には、休憩で起きること（HP 30% 回復とその実数、スタミナ全回復、日数を使わない）と、次の層の予告（層の名前、ノードの数、真っ直ぐ抜ける日数）を出します。ボタンは「次の層へ降りる」と「この生を終える」の 2 つです。

第 2 層の終わりの休憩では、「次の層へ降りる」の代わりに、竜・寄生・亡霊の 3 つの降り口を並べます（`seven_layers_v4.md` §3.1）。それぞれに領域の第 3 層の名前と予告を出します。選んだ領域は、その生のあいだ変えられません。

休憩の画面の右上には、地図の画面の上の帯と同じ並びで「手記」「所持カード」「設定・セーブ」の 3 つのボタンを置きます（§6.2）。キーも同じ J・C・Esc です。所持カードは、この層の戦いで伸びた習熟を、次の層へ降りる前に確かめられるように置きます。設定・セーブの歯車は右上の端に置き、下の「この生を終える」から離します。「保存してゲームを閉じる」で閉じたときは、次に起動するとこの休憩の画面から再開します。

次の層の入口ノードは着いた時点で踏んだことになるので、降りると 1 日がすぐに進みます。日読みの砂を持っていれば進みません（`tools_and_consumables_v4.md` §2.4）。降りた入口で暦が 0 になるときは、休憩の画面にそのことを書き、「次の層へ降りる」を押すと確認の札を 1 回挟みます。

王を倒した後の休憩では、降りる先は第 8 層だけです。第 8 層が閉じているあいだ、休憩の画面は「この生を終える」だけを出します（`seven_layers_v4.md` §9）。

### 6.6 「この生を終える」

生存ルートの入口です。探索中はいつでも押せて、階層間の休憩の画面にも同じボタンを置きます。押すと確認を 1 回挟み、確認の札には「生きたまま次の生へ移ります。手記は丸ごと次の生へ渡ります」と書きます。受け継ぎの中身は、手記の全頁と生存者ボーナス（次の 1 生だけツール枠 +1・デッキ上限 +5）です。死亡と比べた得は §7.8 に書きました。

コアでは `ExplorationReducer.EndLife` が生を閉じ、状態は `RunPhase.Survived` になります。暦を動かさず、以後の遷移は受け付けません。次の代の出立までの 3 日は、継承の間へ移るときに暦から引きます（`seven_layers_v4.md` §2.1）。

### 6.7 手記のドロワー

右から幅 30% で開くドロワーで、上の帯の手記のボタンか J で開閉します。戦闘の手記ドロワー（`battle_ui_ux_v2.md`）と同じ部品を使い、頁の型（`Assets/View/Journal/Script/` の `JournalPage`）を共有します。

- タブは「敵・ダンジョン・メモ」の 3 つに、用語と状態の頁を足した形です（#234、2026-10-03 のこうだいさんの決定。`requirements/tier1-core.md` R1-10、`CAMP_FACILITIES_DESIGN.md` §3.3）。左から「敵ごと / ダンジョン / メモ / 用語」の順に並べます
- 頁の型の `JournalTab` には、用語と状態の頁のための値を 1 つ足します
- 探索中はどのタブも開けます。戦闘中に開けるのは、いま戦っている敵の頁と、用語と状態の頁だけです
- 戦闘中は、ダンジョンの頁とメモのタブを暗くして押せなくします（`battle_ui_ux_v2.md` §2.4）
- 用語と状態の頁は、上に用語、下に状態の 2 つの見出しを持つ規則の説明です。中身と見た目は `art_document/battle-visual-v1.md` §7.3 と §7.5 に従います
- 用語と状態の頁は開示度を付けず、最初の生から全項目が読めます。痕跡と遺産の対象から外し、死亡の後も残します
- 開示度は敵の頁の見出しの脇に「開示度 1 / 2」と書きます。開示度が足りない行は「？」にします
- ダンジョンの頁は、今の層の名前と領域・ノードの内訳・情報収集を済ませたかを書きます。値はコアの層の数値から取ります
- 敵の頁、ダンジョンの頁の出来事、メモの中身は §6.11 が決めます。この層に開示度 1 以上の敵がいないときは、「敵の頁はまだありません」の頁を 1 枚置きます

### 6.8 戦闘との往復

戦闘・精鋭・階層ボスのノードに入ると、探索はそのノードで誰と戦うかを層の出会いの表（`encounters_and_rewards_v4.md` §2）から引き、戦闘へ渡します（#99）。

| 向き | 中身 |
| --- | --- |
| 探索 → 戦闘 | 層、ノードの種類、敵の並び（1 つの戦闘の敵の順と、続けて戦う戦闘の順）、場のマス数（`seven_layers_v4.md` §2.4）、HP と最大 HP、スタミナ、最大スタミナ（一時変化を数えた後の値）、敵ごとの開示度、デッキ（その生の習熟で育った札）、戦闘で効くツールの量 |
| 戦闘 → 探索 | HP、スタミナ、習熟の刻み、観察の結果（開示度は戦闘の終わりに上がる）、習得した固有の札、死亡 |

- **シーンは分けます。** 戦闘のシーンを探索のシーンの上に重ねて読み込み、戦闘が終わったら外します。探索のシーンは読み込んだまま隠すので、探索の状態はそのまま残ります。戦闘のシーンは Unity のリポジトリで作ったものをそのまま使います。
- **2 戦続く精鋭は**、1 戦目の HP とスタミナを 2 戦目へ持ち越します。1 戦目で倒れたら、そこで終わります。
- **開示度は**、戦った敵が少なくとも 1 になり、観察の札を出した戦闘の敵は 2 になります。2 体が並ぶ戦闘では、予兆に開示度を敵ごとに渡し、どちらの予兆もその敵の開示度で出ます（#763）。
- **固有の札は**、本物のボスを倒すと 3 種を覚えます。代役のボスと本物の精鋭は、その精鋭の札を渡します。精鋭ごとの札の数は `encounters_and_rewards_v4.md` §4.2 が持ちます。覚えた札は、デッキに空きがあれば 1 枚入ります。
- **戦闘のシーンを読み込めないとき**（ビルドの設定に入っていないときなど）は、地図の上の仮の札に戻ります。札の「勝ったことにする」は HP とスタミナを変えず、「倒れたことにする」は HP を 0 にします。どちらの道も、コアの `ExplorationReducer.ReportBattle` を通ります。

受け渡しの C# は `unity-port/unity-project-kit/Assets/View/Exploration/Bridge/`（`Expedition` と `EncounterBattle`）にあり、`dotnet test`（`unity-port/Exploration.Bridge.Tests/`）で確かめます。

### 6.9 終わりの画面

生の終わりは 4 通りで、どれも地図の上に札を出します。v4 の瘴気死は無くなり、期限切れが入りました。

| 終わり方 | 札の文 |
| --- | --- |
| 倒れた | 第 N 層の戦いで倒れた |
| 踏破 | 三体の王を倒した。文は `world-v1.md` §8 |
| 期限切れ | 暦が尽き、龍神が目覚めた。世界が終わり、最初からやり直す |
| 生存ルート | 生きたまま、この生を閉じた |

札のボタンは「新しい生で潜り直す」の 1 つで、乱数の種を変えて第 1 層からやり直します。死亡地点・遺産・継承の間へつなぐのは #104 と #106 です。

### 6.10 見た目と Unity への写し方

地図の奥の背景と幕のほかは、見た目は仮です。ノードは灰色の四角に種別の 1 字（戦・精・主・休・調・事・痕・彫）を置き、色は灰色の濃淡と強調の 1 色だけを使います。色・書体・ノードの絵は design の担当と #90 が決め、決まったら View の側だけを差し替えます。

**v4 の瘴気のゲージと、瘴気で暗くなる画面は外します。** 色と動きは `art_document/battle-visual-v1.md` §2.5 で決めていました（#613）が、2026-11-03 に瘴気が探索から外れました。値を持つ `Assets/View/Backdrop/Script/MiasmaLook.cs` をどうするかは、#888 で design と決めます。暦の見た目は design が決めます。

- 地図の奥には、いまの層の背景と地 `#10141d` の幕を敷きます（`battle-visual-v1.md` §2.5、#614）。奥から「地 → 層の背景 → 幕 → 地図・上の帯・右の欄」の順です。背景は層の名前で引きます（`seven_layers_v4.md` §3.2。直すのは #888）。背景と幕の値は `Backdrop.ExplorationBackdropSpec` から読み、背景は `Backdrop.View.BackdropLayers` が描きます。地図の下にパネルは敷かず、ノードと道と文字を、幕を掛けた背景の上に直に描きます。
- 層を降りたときは、背景と幕の不透明度を 400 ms（`BackdropSpec.CrossfadeMs`）で切り替えます。戦闘の背景は `BackdropView` が描くので、探索の画面は `BackdropView` を置きません。

| 置き場所（`unity-project-kit/Assets/`） | 中身 |
| --- | --- |
| `DungeonCore/` `DungeonContent/` | 探索のコアと持ち物の目録の写し。原本は `unity-port/DungeonCore/` と `DungeonContent/` |
| `View/Exploration/Script/` | 画面の組み立て役（純 C#）。コアの状態から画面の値を作り、操作をコアへ渡す |
| `View/Exploration/` | 画面（UGUI）。組み立て役が作った値を置くだけ |
| `View/Journal/` | 手記のドロワー。頁の型（純 C#）と画面。戦闘の画面からも使える形にしてある |

組み立て役と頁の型は `dotnet test`（`unity-port/Exploration.Script.Tests/`）で確かめます。画面を動かすのは Unity のシーンで、空の GameObject に `ExplorationBootstrap` を付けると画面が全部コードで組み上がります。

### 6.11 手記の中身と開示度（#107）

手記は、敵の頁・ダンジョンの頁・メモの 3 種と、用語と状態の頁でできています。用語と状態の頁は §6.7 のとおりで、ここでは扱いません。手記は 1 つの生のものです。新しい生は、空の手記から始まります。遺産と生存ルートで次の生へ渡す手順は #106 と #108 が決めます。

**敵の頁**は、`enemy_document/enemy_roster_v4.md` の各敵の「手記」の 4 文をそのまま使います。4 文は、間合い 0・間合い 1〜2・間合い 3 以上の動きと、弱点です。ボス 3 体と竜神の頁には、適応の条件も載せます。ロースター §1.5 が「開示度 2 では条件そのものが手記の頁に書かれます」と決めているためです。ロースターは 4 文について「開示度 2 で全部見える」とだけ書き、開示度 1 で読める文を決めていません。そこで、本書が次のように切ります。

| 開示度 | 読める行 | 理由 |
| --- | --- | --- |
| 0 | どの行も「？」 | まだ会っていない |
| 1（遭遇） | 間合い 0・1〜2・3 以上の 3 行 | 戦ったときに目の前で見た動きだから |
| 2（観察か情報収集） | 上の 3 行に、得意な間合いと弱点を足した全部。ボスと竜神は、適応の条件の行も足します | 弱点と適応の条件は、見た動きを読み解いた結果だから。適応の条件はロースター §1.5 が開示度 2 に置いているから |

- ロースターに手記を持つのは 14 体です（通常 7、精鋭 3、ボス 3、竜神）。§8 の 8 体はまだ手記が無いので、頁もありません
- 文はロースターから写します。ロースターの手記が変わったら、写しの `Assets/View/Journal/Script/EnemyJournal.cs` も直します
- 適応の条件の文は、ロースターの適応の表（§4.4・§5.4・§6.4・§7.11）の「条件（手記の文）」の列から、表の順に写します。行の見出しは「適応 1」「適応 2」…です。セルク・ガルド・竜神は 4 行、歪みの根は 7 行になります。HP で段階が替わる条件も表の行なので、同じく載せます
- 地図の戦闘ノードは、開示度 1 から敵の名前を出し、開示度 2 で傾向の行（「傾向: 錆槍の竜兵は得意な間合い 1〜2」）を足します（§6.3）
- 2 体が同時に出る戦闘は「錆槍の竜兵 + 灰弩の竜兵」、続けて戦う 2 戦は「錆槍の竜兵 → 瘴牙の走竜」と書きます。開示度 0 の敵だけを「？」にし、地図が出す開示度はノードの敵のうち最も低い値です。予兆は敵ごとにその敵の値で出ます（§6.8）。1 つの戦闘に 2 体が出るときも、続けて戦う 2 戦でも同じで、地図は最も低い値を出し、予兆は敵ごとに出ます
- 地図の予告に出す敵は、ノードに着いたときに引く敵と同じです。同じ種から引くためです

**開示度の上がり方**は次の 3 つです。

- **遭遇**: 戦った敵は、戦闘の終わりに少なくとも 1 になります（§6.8）
- **観察**: 観察の札を出した戦闘の敵は、戦闘の終わりに 2 になります（§6.8）
- **情報収集**: 情報収集ノードを踏むと、その層のボスの枠の敵がすぐに 2 になります。その生が終わるまで 2 のままで、層を降りても下がりません。ボスの枠の敵は、`encounters_and_rewards_v4.md` §2 の代役を含めた敵です（一層は瘴牙の走竜、二層は瘴甲の竜兵、三層は大黒蛇 セルク、四層は鉄壁の門竜、五層は不退の槍竜、六層は獄竜 ガルド）。七層には情報収集ノードがありません。ボスを選んだのは、層のどの道を通っても最後に必ず戦う相手で、2 行動の予定と数字が開示度で変わる相手だからです

中ボスと王も、新しい生では他の敵と同じく開示度 0 から始まります。v4 の `seven_layers_v4.md` には、七層に情報収集を置かない代わりに、七層のボス（歪みの根）の手記を最初から開示度 2 にする案がありました。この案は採りません。`concept-v3.md` §12-9 が、2 段目に上げる手段を観察の札と情報収集に限っているためです。第 7 層の王を開示度 2 で読むには、その戦闘で観察の札を出すか、前の生の頁を遺産で受け継ぎます。遺産で受け継ぐ手順は #106 が決めます。

どの上がり方でも、次の戦闘の予兆は上がった開示度で出ます（`OmenDisclosure`、#500）。

**ダンジョンの頁**は、層ごとに 1 枚です。上に層の数値（§6.7）を置き、その下に、その層で分かることを出来事ごとに並べます。出来事は「近道」「条件出現」「イベント」の 3 種で、出来事ごとに開示度を持ちます。

| 開示度 | 出来事の行 | 上がるとき |
| --- | --- | --- |
| 0 | 「？」 | — |
| 1 | 起きたこと（例: 「HP が最大の 20% 戻る」） | その生で、その層でその出来事が起きたとき |
| 2 | 起きたことに、出る見込みか条件を足す（例: 「この層のイベントは 2 つで、1 つ目が泉になる見込みは 50%。2 つ目は 1 つ目と違う種類になる」） | その層の希少な頁を読んだとき |

- 「？」の行を残すのは、その層にまだ知らないことがあると分かるようにするためです
- 中身を持つのはイベントだけです。`encounters_and_rewards_v4.md` §5 の表から、一層から三層に泉・重い宝箱・特殊な食事の 3 件、七層に重い宝箱と特殊な食事の 2 件を置きます。四層から六層にはイベントが無いので、出来事もありません
- 近道と条件出現は、書く場所だけを用意しました。中身はまだありません（§2.2）
- **希少な頁**（`encounters_and_rewards_v4.md` §4.3）は、その層の出来事のうち開示度 2 でないものから 1 つを等確率で選び、2 にします。選べる出来事が無ければ、頁はカードに替わります（同 §4.3）。希少な頁で敵の開示度は上げません。2 段目に上げるのは観察と情報収集だけだからです（`concept-v3.md` §12-9）

**メモ**は、プレイヤーが書いた文をそのまま持つだけです。ゲームは中身を読まず、どの数値も変えません。何件でも書け、書き直しと消去ができます。ドロワーでは 1 枚のメモの頁に全件を「メモ 1」「メモ 2」の見出しで並べます。番号は書いた順で、消しても詰めません。

メモは「どの敵のメモか」を任意で持ちます（2026-11-01 のこうだいさんの決定、#713）。持つメモは、その敵の頁の末尾の「自分のメモ」の行に読むだけで出し、ほかの敵の頁には出しません。戦闘中にメモのタブは灰色になるので、戦闘中にメモを読めるのはこの行だけです（`battle_ui_ux_v2.md` §2.4）。

- 戦闘中は読むだけで、書けません。戦闘の中で開いた頁の行は、末尾に「戦闘中は書けない」を足します。
- 自分で書いた文なので、敵の頁の開示度にかかわらず読めます。空白だけのメモは行に出しません。
- 敵を持たないメモは、今までどおりメモの頁に並びます。
- 敵を持つメモも、メモの頁に残します。書き直しと消去をする場所がメモの頁だけだからです。見出しは「メモ 1（錆槍の竜兵）」の形にします。遺産の一覧の 1 行は「メモ 1」のままです。

**遺産の一覧に並べる 1 行の形**: `concept-v3.md` §14 は、遺産の候補に習熟 1 段以上のカードと埋まった頁を全部並べ、そのために手記をコンパクトで整然とした形にすると決めています。そこで、埋まった頁を 1 頁 1 行、「種類｜題｜中身」の 3 欄で書きます。

| 頁 | 埋まったとみなす条件 | 1 行の例 |
| --- | --- | --- |
| 敵の頁 | 開示度 1 以上 | 敵｜錆槍の竜兵｜開示度 2 / 2（弱点まで） |
| ダンジョンの頁 | その層の出来事が 1 件以上、開示度 1 以上 | ダンジョン｜第 1 層｜分かったこと 2 件（うち中身まで 1 件） |
| メモ | 空白でない 1 件ごと | メモ｜メモ 1｜書いた文の 1 行目（20 字を超える分は「…」） |

- 並べる順は、ドロワーのタブと同じ「敵・ダンジョン・メモ」です。敵はロースターの順、ダンジョンは上の層から、メモは書いた順です
- メモは 1 件ずつ選べるように、1 件を 1 行にします
- 用語と状態の頁は並べません（§6.7）

**旧い計画書から拾ったもの**: `journal_document/journal_system_implementation_plan.md`（V3.0、一部を置き換え済み）からは、敵の行動と弱点を書く頁、ダンジョンのイベントとその結果を書く頁、何件でも書けて探索中も書き直せるメモ、知らない項目を「？」で見せる形を拾いました。カードと装備の図鑑、撃破数とドロップ率、収集率の表示、メモの分類タグは拾いませんでした。装備と経済は凍結中で、所持カードは手記とは別のボタン（§6.2）で開くためです。収集率と分類タグは、遺産の一覧を簡潔に保つのに要らないためです。

**実装**は純 C# です。頁の中身と 1 行の形は `Assets/View/Journal/Script/`（`EnemyJournal` `DungeonJournal` `JournalMemo` `JournalLines`）、1 つの生の手記は `Assets/View/Exploration/Script/LifeJournal.cs` です。`LifeJournal` は探索の画面の差し込み口（`IEnemyIntel`）で、`Exploration.Bridge.Expedition` が作って探索に渡します。戦闘が残した開示度は `Expedition` が持ち、`LifeJournal` はそこに情報収集の分を足して返します。戦闘の報酬の希少な頁は、`Expedition.Return` が 1 枚ごとに `LifeJournal.DrawRarePage` で読み、その層の出来事を 1 つ開示度 2 にします。選べる出来事が無い頁は、カードに替えます（`encounters_and_rewards_v4.md` §4.3）。イベントを解決すると、受けても受けなくても、`LifeJournal` がその層の出来事を開示度 1 にします（`ExplorationSession.EventHappened`、#718）。受けなくても、何があるかを見たからです。解決は探索の画面（`ExplorationBootstrap`）が `RunStart.ResolvesEvents` で入れます。切ったときの C# の動きとテストは変えません（`unity-port/TRIAL-PORT.md`）。重い宝箱の中身は戦闘の報酬と同じ行き先に入れます。カードは札の選択へ、消耗品は空きの枠か入れ替え待ちへ、頁は手記へ入れ、語ることが無い頁はカードに替えます。特殊な食事で HP は 1 より下がりません。手記の頁を遺産の一覧へ渡す差し込みは、`LifeJournal.FilledPages` です（§7.3）。メモを書く入力欄（敵の指定を含む）は、まだつないでいません。

## 7. 死亡と痕跡と遺産（#106）

`concept-v3.md` §8.3・§8.4・§14 の決定を、探索の規則に落とした節です。規則は探索のコアの `Heritage` と `TraceLedger`（`unity-port/DungeonCore/`）が持ち、`dotnet test`（`unity-port/DungeonCore.Tests/`）で確かめます。痕跡を保存して次のセッションへ持ち越すのは、試遊版の系譜（`InheritanceCore` の `Lineage`）です（§7.9）。

### 7.1 死亡の確定

生が死亡で終わるのは、戦闘で HP が 0 になったとき（倒れた）だけです。v4 の瘴気死は、2026-11-03 に瘴気と一緒に無くなりました。倒れた時点で死亡を確定し、痕跡を 1 つ残します。

- 痕跡を残すのは、探索の流れを持つ `ExplorationSession` です。ノードに入ったとき、戦闘の結果を受け取ったとき、層を降りたとき、生を始めたときの 4 か所で、状態が死亡かを確かめます。
- 1 つの生が残す痕跡は 1 つです。
- 生存ルート（§6.6）は死亡ではないので、痕跡を残しません。
- 踏破も死亡ではありませんが、札だけの痕跡を残します（§7.8）。

### 7.2 痕跡の中身

痕跡は次の 5 つを持ちます。

| 項目 | 中身 |
| --- | --- |
| 名前 | 死んだ者の名前。世代ごとの名前は #110 が入れます。それまでは「N 代目」と書きます |
| 層 | 死んだ層と、第 3〜6 層なら領域 |
| ノードの種類 | 死んだときに立っていたノードの種類。終わりの文に使うだけで、置き場所には使いません |
| 死因 | 倒れた。v4 の系譜にある瘴気死の痕跡は、そのまま読める形で残す（§7.9） |
| 候補の一覧 | 遺産として選べるもの（§7.3） |

### 7.3 遺産の候補と選べる数

候補は、習熟 1 段以上のカードと、埋まった手記の頁です。カードを先に、段の高い順に並べ、その後に頁を並べます。

- **浅層での死の規則**: 1 段目のカードは、どの層で死んでも候補になります。2 段目と 3 段目のカードは、第 3 層より深い層（第 3 層を含む）で死んだときだけ候補になります。
- **頁**は、手記が「埋まった頁」として渡すものを全部並べます。敵の頁・ダンジョンの頁・メモの 1 件ずつで、1 頁の題は §6.11 の 1 行（「種類｜題｜中身」）をそのまま使います。並びは手記の順で、敵はロースターの順、ダンジョンは上の層から、メモは書いた順です。用語と状態の頁は候補にしません（§6.7）。
- 1 頁は、id と題のほかに、その頁が何を持っていたかを持ちます（下の「頁が持つもの」）。次の生が頁を手記に戻せるようにするためです。探索のコアはこの中身を読まず、受け渡すだけです。
- **選べる数は 3 つまで**です。`requirements/tier1-core.md` R1-12 の「仮 3」をそのまま採りました。0 個を選んで確定することもできます。
- 確定すると痕跡は回収されて消えます。選ばなかった候補は、痕跡と一緒に失われます。

### 7.4 死亡地点の持ち方

**死亡地点は、層とノードの種類で持ちます。座標（ノードの番号や行と列）は持ちません。**

地図は、生ごとに新しい乱数の種から作り直します（`ExplorationSession.LayerSeed`）。前の生の座標は、次の生の地図では別のノードを指すか、どこも指しません。そのため、痕跡は「どの層か」だけで探します。

- 次の生がその層に入ると、地図の通常戦闘 1 つを痕跡のノードに入れ替えて作ります（`seven_layers_v4.md` §7）。第 3〜6 層の痕跡は、同じ領域へ降りた生だけが踏めます。
- 痕跡のノードは寄り道の側に置きます。同じ行には、寄り道でないノードが必ず 1 つ残ります。痕跡を踏まずにボスまで行けます。
- どの位置に置くかは、その層の乱数の種が決めます。同じ種なら同じ位置です。
- 1 つの層の地図に置く痕跡は 1 つです。同じ層に回収されていない痕跡が 2 つ以上あるときは、古いほうから 1 つずつ置きます。
- 痕跡のノードに戦闘はありません。入ると 1 日進むのは他のノードと同じです。

### 7.5 1 つの生で受け取れるのは 1 件

- 生が最初に踏んだ痕跡が、その生で受け取る痕跡になります。踏んだ時点で選ぶ画面が開きます（§7.7）。
- 同じ生で 2 つ目の痕跡を踏んでも、選ぶ画面は開きません。その痕跡は消えずに残り、後の生が受け取れます。
- 痕跡は回収されるまで残ります。後の死で上書きされることはありません。
- 選ぶ前に生が終わったときは、その痕跡は回収されずに残ります。
- 選ぶ画面は地図を止めません。戦闘の札の選択と同じように、地図の上に重ねて出します（§7.7）。

### 7.6 継いだものの行き先

- **カード**は段をそのまま継ぎます。継いだカードは所持カードになります。習熟の刻みは、その段に届く最低の数にそろえます。この生で既にそれより多く刻んでいれば、多いほうを残します。
- 戦闘デッキに同じ種類のカードが無く、デッキに空きがあれば、1 枚がデッキに入ります。同じ種類が既にデッキにあるときは、段だけが上がり、枚数は増えません。
- 3 段目を持てるのは 1 つの生で 1 枚だけです（`battle_core_v4.md` §17.8）。既に別のカードが 3 段目にあるとき、3 段目のカードは 2 段目で継ぎます。
- **頁**は、継いだ生の手記に入ります。頁が持っていたものを、次のように戻します。
  - 敵の頁は、その敵の開示度を、頁が持っていた値まで上げます。この生で既に高ければ、高いほうを残します。観察の札と情報収集で上がる 2 段目と同じ扱いで、継いだ開示度 2 の敵は、戦闘の予兆が開示度 2 で出ます。
  - ダンジョンの頁は、頁が持っていた出来事を、持っていた開示度（1 か 2）まで上げます。この生で既に高ければ、高いほうを残します。
  - メモは、書いた文とどの敵のメモかをそのまま、この生の新しいメモとして書き足します。番号は、この生のメモの続きから付けます。
  - 手記がまだ知らない id の頁は、継いだ頁の一覧（`Expedition.InheritedLegacyPages`）に残るだけで、手記は変わりません。
- **頁が持つもの**: 開示度を持つ頁（敵・ダンジョン）は、持つものの id から開示度への対応表を持ちます。敵の頁は敵 1 体、ダンジョンの頁はその層で分かった出来事すべてです。メモは文と、任意の敵の id を持ちます。`concept-v3.md` §14 は「候補は全部並べる」と決めているだけで、開示度やメモの文を戻す形は決めていません。そのため、開示度を `LegacyPage` に足す形にしました。頁を 1 行の題に畳む形のままでは、継いだ頁が開示度 1 なのか 2 なのか、ダンジョンのどの出来事を知っていたのかを戻せないためです。

### 7.7 選ぶ画面

選ぶ画面の中身は、純 C# の組み立て役（`Assets/View/Exploration/Bridge/HeritagePicks.cs`）が作ります。札を選ぶ画面（#626）と同じ形です。

| 置くもの | 中身 |
| --- | --- |
| 題 | 「死亡地点の痕跡: 遺産を選ぶ」 |
| 説明 | 「1 代目は第 3 層の階層ボスで倒れた。3 つまで継げます。選ばなかったものは失われます。」のように、誰が・どの層の・どのノードで・どう死んだかと、選べる数を書きます |
| カード | 継ぐ段での札の面と、その下に「習熟 N 段目」 |
| 頁 | 頁の 1 行の題と、その下に「手記の頁」 |
| 確定 | 「これを継ぐ」のボタンと、「選んだ数 2 / 3」 |

候補を押すと選び、もう一度押すと外します。3 つ選んだ後は、4 つ目を押しても選べません。

Unity の探索画面では、札を選ぶ画面の層の上に重ねて出します（`ExplorationScreenView.ShowHeritage`、#717）。札の選択が同時に待っているときは、遺産を選んだ後に札を選びます。画面は地図を覆うので、選び終えるまで地図は押せません。規則としては地図を止めていません（§7.5）。1 つも選ばずに「これを継ぐ」を押すと、痕跡は回収され、候補は失われます（§7.3）。

### 7.8 生存ルートと死亡の釣り合い（#108）

**生存ルートは、いつも死亡より得になるわけではありません。** 生存ルートは手記と枠を渡し、死亡は習熟したカードを渡します。次の生に何が足りないかで、得な側が替わります。2026-11-03 に手計算で比べた結果をここに残します。使った数は、遺産の選べる数 3、2 段目以上が残る第 3 層（§7.3）、生存者ボーナス（`concept-v3.md` §14）、習熟の閾値 3 / 8 / 15（`battle_core_v4.md` §3.2）です。

| 渡るもの | 生存ルート | 死亡 |
| --- | --- | --- |
| 手記 | 全頁が渡ります | 全頁が候補に並び、札と合わせて 3 つまで選べます |
| 習熟したカード | 渡りません | 1 段目はどの層でも、2 段目と 3 段目は第 3 層より深い死だけ候補に並びます |
| 枠 | 次の 1 生だけ、ツール枠が 3 から 4、デッキ上限が 40 から 45 になります | 変わりません |
| 受け取り方 | 出立の時点で受け取ります | 次の生がその層まで降り、痕跡のノードに 1 日払います |

型の違う 3 つの生で比べました。

| 生の型 | 終わった層 | 習熟したカード | 手記の頁 |
| --- | --- | --- | --- |
| 浅い生 | 第 2 層 | 1 段目 3 枚、2 段目 1 枚 | 7 |
| 中ほどの生 | 第 3 層 | 1 段目 4 枚、2 段目 2 枚、3 段目 1 枚 | 12 |
| 深い生 | 第 5 層 | 1 段目 5 枚、2 段目 3 枚、3 段目 1 枚 | 17 |

| 生の型 | 生存ルートで次の生が得るもの | 死亡で次の生が得るもの |
| --- | --- | --- |
| 浅い生 | 7 頁と枠を得ます。カードは 0 枚です | 1 段目のカード 3 枚（刻み 9 ぶん）か、頁を混ぜた 3 つです。2 段目は残りません |
| 中ほどの生 | 12 頁と枠を得ます。カードは 0 枚です | 3 段目 1 枚と 2 段目 2 枚（刻み 31 ぶん）です。第 3 層まで降りて受け取ります |
| 深い生 | 17 頁と枠を得ます。カードは 0 枚です | 刻み 31 ぶんは中ほどの生と同じです。第 5 層まで降りて受け取ります |

- **浅い生では、生存ルートが勝ちます。** 死亡で残るカードは 1 段目だけです。刻み 9 は 1 種あたり 3 刻みです。1 回のプレイで 1 刻み溜まるなら 3 回、4 刻みなら 1 回出せば戻ります。浅い層の意図的な死を得にしないための規則（§7.3）が、そのまま効いています。
- **第 3 層より深い生には、死亡でしか渡せないものがあります。** 3 段目のカードは刻み 15 で、1 つの生で 1 枚しか持てません（§7.6）。生存ルートを選ぶと、これを捨てることになります。
- **生存者ボーナスの枠は、深く潜る生ほど効きます。** 4 つ目のツール枠に、日読みの砂や帰り道の糸のような日数に効く品を足せます（`tools_and_consumables_v4.md` §2.4）。
- **手記は、生存ルートなら代を重ねても全部残ります。** 死亡なら 3 つに絞られます。知識は生存ルートで、習熟は死亡で運ぶ形なので、どちらかが常に勝つことはありません。
- **生存ルートで払うのは、その生でまだ潜れた深さと、世代の数です。** 代わりに、次の代の出立が死亡より 7 日早くなります（`seven_layers_v4.md` §2.1）。 踏破の画面は踏破までの世代の数を出すので（`concept-v3.md` §8.1）、すぐに生を閉じる繰り返しはその数に表れます。

上の 3 つの生は、`unity-port/InheritanceCore.Tests/InheritanceTests.cs` の `Balance_SurvivalCarriesKnowledgeAndSlots_DeathCarriesMastery` が規則どおりに通して確かめています。

**踏破した生は、生存者になりません**（`concept-v3.md` §8.1、2026-11-03 こうだいさんの決定）。前の生存者はそのまま残り、手記はどこへも渡りません。痕跡は札だけを残し、習熟したカードと歪みの根の札が候補に並びます。頁は並びません。終わりの画面は、札の痕跡が残ったことと、手記が次の生へ渡らないことを書きます。前の生存者のボーナスがまだ残っていれば、その生存者が残ることも書きます。踏破の文と世代の数は #111 が入れます。規則は `InheritanceCore/Inheritance.cs` の `RecordSurvival` が持ち、テストは同じファイルの R18 です。

**まだ測っていないこと**があります。1 回の戦闘で溜まる刻みの量と、手記の開示度が戦闘で何手を救うかです。試験台（#53）で測れたら、上の表の刻みの数を戦闘の回数に直します。

### 7.9 痕跡の保存とセーブの版（#109）

**痕跡を保存する記録は、試遊版の系譜（`InheritanceCore` の `Lineage`）だけです**（2026-11-03 こうだいさんの決定）。系譜は、痕跡・生存者・過去の生とその名前・世代の数・プレイヤーの記録（二層の刻印、歪みの根の撃破）を持ち、セーブに入ります。探索のコアの `TraceLedger` は、旧い探索の画面（`View/Exploration/`）が 1 回の探索のあいだだけ使う一覧で、保存しません。そのため、`TraceLedger` に次の世代の番号を持たせる依頼（#717 の申し送り）は取り下げました。`DeathTrace.Life` は、探索のセッションごとに 1 から数えたままです。

**セーブの版を上げるときは、系譜を変換します。** 系譜は代を重ねた記録の全部で、読めなくなると次の生では取り戻せないためです。

- 古い版の系譜は、版を 1 つずつ上げる手順を順に通して読みます。手順は `InheritanceCore/LineageMigrations.cs` の `Steps` に、版ごとに 1 つ足します。今の版は 1 なので、手順はまだありません。
- このビルドより新しい版の系譜は読みません。新しい版を古い版へ戻す手順は作りません。保存は別のキーへ写して残し、プレイヤーが「はじめから」を選ぶまで元のキーにも残します（今の動きのままです）。新しいビルドに戻せば、また読めます。
- 次の版への手順が無い版も、同じく読まずに残します。手順の書き忘れを推測で埋めると、正しい系譜の上に違う系譜を書くことになるためです。版を上げて手順を足し忘れると、テスト `EveryVersionBelowTheBuildsHasItsStep` が落ちます。
- セーブ全体の入れ物（`{ v, rev, tab, lineage, life, deckSave }`）の版も同じ扱いです。新しい版は読まずに残し、版の無いものは版 1 として読みます。

**生の途中（開始データと操作のログ）は変換しません。** ログの再生は、記録したビルドの規則で同じ結果になることが前提です。規則が変わった後に再生すると、別の生になります。開始データの版がこのビルドと違えば、その生は再開できないものとして扱います。今ある「再開できない生」の流れのとおり、保存を別のキーへ写し、プレイヤーが「あきらめる」を選ぶと出立前の系譜へ戻します。出立前の系譜も、上の手順で変換して読みます。

規則は `LineageMigrations`（系譜）と `Trial.Bridge` の `Save.OpenSave`・`LifeStartData.FromJson`（入れ物と生の途中）が持ちます。テストは `InheritanceCore.Tests/LineageMigrationTests.cs` と `Trial.Bridge.Tests/SaveTests.cs` です。保存した生から再開できるかの実機の確認は、こうだいさんがメインの Unity で行います。
