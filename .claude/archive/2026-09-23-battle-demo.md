## Context

### 何を作るか

カードのバランスとおかしな挙動を、実際に戦って確かめるための Unity のデモを作ります。`Battle.unity` を Play すると、デッキ選択 → モード選択（1 体か連戦）→ 戦闘 → 終了画面 → 選択画面へ戻る、が 1 周通る状態がゴールです（#187 の完了条件）。

数値や特性の厳密さより、最後まで止まらずに戦えることを優先します（#187 の本文）。

### いまのコアで表せる範囲

戦闘コア（`unity-port/BattleCore/`）は縦切りの 10 種と長柄 1 体のぶんしか語彙を持っていません。特性の条件は 4 種（間合い n 以下 / n 以上、無防備、温存）、効果は 4 種（威力 / Guard / 次ターン回復 / 重撃）、状態は鈍足だけです。回復（HP）、崩し、スタンス、多段攻撃もありません。

80 種を 1 枚ずつ当ててみると、いまのコアで欠けなく表せるのは約 16 種です。残る 64 種は、連動・予兆・初手・締め・連打・手薄・死力・崩し後・相手の状態・自分の状態の条件か、出血・強化・脆化などの状態か、スタンスのどれかに頼っています。

### 確認した判断（2026-09-23）

計画の判断 7 件を、こうだいさんに確かめてもらいました。5 の連戦の持ち越しだけを推した案から変え、ほかは推した案のまま進めます。3 の手薄は 2 枚以下で決定し、カードと敵の一覧への反映は #193 に回しました。

### 制約と非目標

- **他の担当が持つ文書は直しません。** カード一覧と敵の一覧（持ち主は cards）は読むだけです。食い違いは Issue にし、どちらに従ったかを Issue と PR に 1 行で書きます
- **試運転はメインのチャットで行います。** このブランチで回すのは `npm run build` / `npm run lint` / `npm run test:run` / `dotnet test` までです。Unity Editor での手順は PR 本文に書きます
- **View は計算しません。** デッキの条件、連戦の持ち越し、終了画面の値は BattleCore か Bridge が出し、テストで確かめます
- **merge はしません。** 5 本の PR が open になった時点で止まります
- **作らないもの**: 9 戦の並び、結果のログファイル、瘴気ゲージ、習熟、ボスの適応と段階、予兆 2 段の表示、2 体同時の戦闘

## Unity Editor でメインのチャットにお願いする作業（見込み）

画面は実行時にコードで組むので、シーンとプレハブは触らない見込みです。確定した手順は各 PR の本文に書きます。

1. PR を merge した後に `npm run unity:sync` で C# を Unity リポへ写す
2. Unity で `Assets/Scenes/Battle.unity` を開き、`BattleBootstrap` の「デモの流れ」が有効なことを確かめて Play する
3. デッキ選択 → モード選択 → 戦闘 → 終了画面 → 選択画面へ戻る、を 1 周通す
