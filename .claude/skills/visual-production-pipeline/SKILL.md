# visual-production-pipeline — キャラクターの外見と UI/UX を作る流れ

見た目を作る仕事を「前提を読む → 作る → Unity の実画面で確かめる → 権利を記録する → 報告を残す」の順に通すスキルです。引っ越しでいえば、段取り表と荷札と搬入チェックをひとまとめにした手順書です。絵を描く、1 案を選ぶ、リグを組むといった人の手の工程は Claude が代われません。Claude はその直前まで材料を揃えて、止まらずに報告まで進めます。

## モード

Skill の `args` の先頭語でモードを決めます。`<id>` は `enemy_roster_v4.md` の英字 id（例: `polearm_warped`）か、プレイヤーの職（`swordsman`）です。

| args                | 工程     | 成果物                                                                                                       |
| ------------------- | -------- | ------------------------------------------------------------------------------------------------------------ |
| `survey [観点]`     | 調べ直し | レポート、`references/tools-and-prerequisites.md` の差分、Artifact、Note                                     |
| `setup`             | S0 → S1  | 判断の記録、LFS と `.gitignore` の差分案、台帳、スタイルガイド、Artifact、Note                               |
| `character <id>`    | C0 → C11 | 仕様カード、影絵、依頼パック、候補の比較、素材と白シルエット、台帳、実画面の所見、Artifact、Note             |
| `background <階層>` | B1       | 背景と靄のタイル、縁のコントラスト表、台帳、Artifact、Note                                                   |
| `ui <画面か部品>`   | U0 → U8  | モックアップ、読みやすさの表、アイコンと書体、実装の依頼、実画面との差分、Artifact、Note                     |
| `vfx <系統>`        | V0 → V3  | 系統 × 段の表、系統素材、実装の依頼、時間の表、Artifact、Note                                                |
| 未指定              | —        | `MEMORY.md` の進行中と `.claude/docs/art_document/briefs/*.md` の進捗欄から続きを選ぶ。何も無ければ `survey` |

## 着手時にすること

1. **範囲の宣言**: 触るファイル / 完了条件（そのモードの成果物がすべて出ている）/ 触らないもの（凍結範囲、戦闘ルール、他の id の素材）を最初のメッセージに書きます。
2. **前提の確認**: `character` / `background` / `ui` / `vfx` では、次の 3 つが揃っているかを見ます。揃っていなければ `setup` の Claude の分を先に済ませ、人の分はレポートの「次に判断が要る点」に回します。
   - `.claude/docs/art_document/style-guide.md` がある
   - Unity プロジェクトの台帳 `Docs/art/asset-ledger.csv` がある
   - 両リポジトリで `git check-ignore -v .env` が終了コード 0
3. **Unity の接続**: Unity を触る工程の前に `unity status` で Editor の接続を確かめます。つながっていなければ、ビルド撮影（`-captureDir`）で代えます。

## 先に読むもの

1. `references/tools-and-prerequisites.md`: 採用ツール、決定済み / 未決の前提、法務の約束、確認日つきの価格。このスキルの正本です。
2. 設計の正本: `.claude/docs/battle_document/battle_ui_ux_v2.md`（§2 配置、§4 見た目とトークン、§5 演出、§6 Unity 写像、表 1194〜1262 行のアセット）、`.claude/docs/enemy_document/enemy_roster_v4.md`、`.claude/docs/vision/concept-v3.md`。
3. Unity 側の受け口: `unity-port/unity-project-kit/Assets/View/` の `BattleTheme.cs`（色と配置）、`ArenaView.cs`（人型 140×300、Rim / Fill / Flash / Ghost）、`ProceduralArt.cs`（仮素材）、`UiKit.cs`、`UiTween.cs`。
4. 直近のレポート: `docs/reports/*visual*`。

凍結範囲（アーマー / 装備 / Gold / ショップ / 鍛冶屋 / サンクチュアリ、旧属性アイコン `elements/*`）の絵は作りません。`public/assets/images/` の仮画像は絵柄が合わないので、生成の参照に入れません。

## 命名（S1 で見直すまでの既定）

- asset_id: `chr.<id>.<category>.<label>`。category は `act`（行動）/ `react`（被弾・崩れ・倒れ）/ `idle`（待機）。間合いは立ち位置で見せるので、体勢の差分（旧 `pose`）は作りません（2026-09-14）。label は roster の snake_case（例: `chr.polearm_warped.act.sweep`）。
- ファイル: `Assets/Art/Characters/<id>/chr_<id>_<category>_<label>.png`。白シルエットは同じ名前に `_sil` を付けます。
- 作業ファイル（`.clip` / `.kra` / `.cmo3` / `.can3`）は Git に入れず、台帳の `source_file` に置き場を書きます。

## survey（調べ直し）

1. Workflow を実行します。このスキルの指示が Workflow の起動許可にあたります。

   ```
   Workflow({
     scriptPath: ".claude/skills/visual-production-pipeline/workflows/survey.js",
     args: { today: "YYYY-MM-DD", focus: "<追加の観点。無ければ省く>", previousReport: "docs/reports/<前回>.html" }
   })
   ```

   観点は 6 つです（内部の前提 / 手元の環境 / 立ち絵と AI 生成 / 2.5D と VFX / UI ツール / Claude が動かせる範囲）。外部の事実は反証役が一次情報で確かめ、批評役が漏れを埋めます。

2. 結果は 15 万字を超えるので、`synth` / `critic` / `verification` をファイルに分けてから読みます。
3. 内部の事実を 3 件以上、自分で開いて確かめます（file:line）。結論を左右する外部の数値（価格・ライセンスの閾値・対応版）は 3 件以上、一次情報を WebFetch で開きます。食い違ったものは「未確認」に落とします。
4. `references/tools-and-prerequisites.md` を差分だけ更新し、確認日を書き換えます。
5. 共通の終わりへ進みます。slug は `visual-production-survey` です。

## 共通の終わり（全モード）

1. **レポート**: `html-report` スキルの型で `docs/reports/YYYY-MM-DD-<slug>.html` を書きます。発行前に `artifact-design` スキルを読みます。上から「結論カード → 根拠 → 置いた仮定 / 未確認 → 次に判断が要る点」の順です。
2. **Artifact**: 同じパスで発行します（初回だけ `favicon`）。
3. **Note**: life-editor に控えを残します。タグは必ず `card-battle` です（無ければ `tag_entity` が作ります）。

   ```
   node ~/.claude/skills/life-editor-note/scripts/le-note.mjs \
     --title "<レポート名>" --kind <判断|進捗|検証|計画> \
     --url <Artifact の URL> --path docs/reports/YYYY-MM-DD-<slug>.html \
     --summary "<要点 1>" --summary "<要点 2>" --tag card-battle
   ```

   出力が `url-in-body=yes` であることを確かめます。`NO` なら隠さずに報告します。

4. **tracker**: `task-tracker` で `MEMORY.md` と `HISTORY.md` を更新します。
5. **報告**: 何をしたか / 結果 / 次に判断が要る点の 3 つに、Artifact の URL、レポートのパス、Note の id を添えます。

## やらないこと

- 台帳の行が無い生成物を `Assets/` に置くこと。
- ライセンスが「未確認」のモデル・重み・書体を製品用の素材に使うこと。試作の仮置きは許し、台帳を `pending` にします。
- 生成の参照に購入素材（Asset Store の規約で AI の学習に使えない）や他作品の画像を入れること。
- 戦闘ルールや数値の変更。気づいた点はレポートの「次に判断が要る点」に回します。
- C# の改修をこのスキルの中で進めること。実装は `lead-pipeline` に渡します。
