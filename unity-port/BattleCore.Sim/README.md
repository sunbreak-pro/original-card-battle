# BattleCore.Sim — 戦闘コアの試験台（#53）

`battle_core_v4.md` §13 の基準 19 項目を、貪欲な打ち手に `BattleCore` の戦闘を回させて測るコンソールアプリです。`BattleCore` は読むだけで、コアの値も規則も変えません。カードは `CardCatalog` の id で組むので、カード表の値が変わればそのまま測り直せます。いまのカード表は `swordsman_cards_v4` v4.5 です。

## 回し方

```bash
cd unity-port
dotnet run -c Release --project BattleCore.Sim -- --seed 1                       # 表を出す（約 11 万戦。16 スレッドの Release で約 15 秒、Debug で約 1 分）
dotnet run -c Release --project BattleCore.Sim -- --seed 1 --json ../../sim.json # 同じ内容と生の勝率を JSON にも書く（リポジトリの外へ書く）
dotnet run -c Release --project BattleCore.Sim -- --seed 1 --max-plays 2         # 打ち手を 1 ターン 2 枚までにして測る
dotnet run -c Release --project BattleCore.Sim -- --only first3                  # 最初に見る 3 つ（§18.4）だけを速く出す
dotnet run -c Release --project BattleCore.Sim -- --trace one_stance:shadow_hound # 1 戦をターンごとに書き出す
dotnet test UnityCorePort.slnx                                                    # BattleCore.Sim.Tests を含む全テスト
```

| オプション | 既定 | 意味 |
| --- | --- | --- |
| `--seed N` | 1 | 種の元。同じ種なら表も JSON もバイト単位で同じになる（スレッド数にもよらない） |
| `--runs N` | 200 | 組み合わせ（デッキ × 敵 × 方針）ごとの戦闘数。基準 11 の最初の手札は N × 100 回配る |
| `--json <path>` | なし | JSON の書き出し先。かかった時間は JSON に入れず、標準エラーに出す。書き出し先がフォルダを指すときと、フォルダを作れないときは、戦闘を回す前に使い方を出して終了コード 2 で止まる。戦闘の後でファイルを書けなかったときは、表を出したうえで終了コード 1 |
| `-h` / `--help` | なし | 使い方を標準出力に出して終了コード 0 で終える |
| `--only first3` | なし | 主な戦闘（全てのデッキ × 全 13 体、位置の偏りなし）だけを回す。デッキの集まりは全体を回すときと同じなので、1〜7・12・S13〜S16 は同じ値になる。8〜11 と 13 の行は skipped になる |
| `--threads N` | コア数 | 並列の数。結果は変わらない |
| `--max-plays N` | 上限なし | 打ち手が 1 ターンに出す札を N 枚までにする。全ての戦闘に効く（下の「打ち手」） |
| `--trace deck:enemy[:policy]` | なし | 1 戦の手札・予兆・出した札とその値を書き出す。policy は Neutral / Close / Away / InOut / KeepTwo のどれか 1 つの名前（大文字小文字は問わない。数字やカンマ区切りは受け付けない）。知らないデッキ・敵・方針は使い方を出して終了コード 2 |

## 表の列

| 列 | 意味 |
| --- | --- |
| # | 1〜14 は §13 の最初の表の行の順。S13〜S17 は §13 の「基準 13〜17」 |
| 基準 / 目標 | §13 の文言。「型 5 種」は §19.8 の 6 型と読む（§13 の表の下の段落） |
| 測定値 | 試験台が測った値 |
| 判定 | pass / fail / not measurable（打ち手では測れない）/ skipped（`--only first3` で回していない） |
| 備考 | 何を数えたか。机上の計算値もここに出す |

勝率の表の下に、詰まり（60 ターンで決着しない戦闘）の数を 1 行で出します。JSON は同じ行に加え、デッキの中身と検査の結果、デッキ × 敵 × 方針ごとの勝率・詰まりの数・ターン数・1 ターンのプレイ枚数・1 撃の最大値、2 連戦の組ごとの勝敗と詰まり、基準 11 の最初の手札の数、詰まりのあった組み合わせの一覧（`stalls.byMatchup`）を持ちます。

## 打ち手（`GreedyPlayer`）

手順は次のとおりです。乱数は使いません。盤面の写しは自分の固定の種で解くので、本番の乱数の並びは動きません。

1. ターン開始に俊敏の無料の 1 マスがあれば、前・後ろ・動かないのうち値がいちばん高いものを選ぶ（0 より大きいときだけ動く）。
2. 手札の札を、出せる相手ごとに盤面の写しで実際に出してみて、出した後の盤面の値から出す前の値を引く。引いた札 1 枚につき 2 を足し、届く札の増減と方針の偏りを足す。
3. 値がいちばん高い札を、値が 0 より大きければ出す。出したら 2 に戻る。0 より大きい札が無くなるか、`--max-plays` の枚数に達したらターンを終える。同じ値なら手札の前にある札を選ぶ。

**引く札は見ない。** 写しの山札は本番と同じ順に並んでいるので、写しで引いた札は本当に次に来る札です。そこで、引いた札は種類を問わず 1 枚 2 の値だけを持ち、届く札の増減は出す前から手札にあった札だけで数えます。山札の順だけが違う 2 つの盤面で同じ値になることを、テスト（`AScore_DoesNotDependOnTheOrderOfTheDrawPile`）が確かめています。

**1 ターンの枚数の上限は、既定では付けません。** 基準 4 は「1 ターンのプレイ枚数の中央値 2 以上」、基準 S13 は「3 枚以上出したターンが 1 戦に 2 回以上」を見ます。2 枚までの打ち手では S13 が仕組みの上で 0 になり、基準 4 も 2 を超えません。この 2 つは「スタミナの許す限り出したら何枚になるか」を問う基準なので、既定は値が 0 を超える札を出し続ける打ち手にしました。§13 の打ち手の文言も、この打ち方に合わせてあります（#403）。#403 より前の文言「予兆に対して最も期待値の高い 1〜2 枚を選ぶ」で測るときは `--max-plays 2` を付けます。表の見出しと基準 4 / S13 の備考に、どちらで測ったかが出ます。

**打ち手が読む情報**は次のとおりです。手札・自分の HP / スタミナ / Guard / 状態 / スタンス・間合い・敵の HP / 状態のほか、敵の現在のスタミナと、いま出ている予兆が払えずに休み（`Omen.Rests`）になるかを読みます。この 2 つは開示度 2（`battle_core_v4.md` §17.7「崩しの見込みは開示度 2 で出し、払えなくなった予兆に印を付けます」）で画面に出る情報です。精鋭とボスの 2 手目の予兆は読みません。山札の中身と順は読みません。

盤面の値は HP を単位にした足し算です。自分の HP、敵の HP、いま出ている予兆が「このままターンを終えたら」与えるダメージ（`TurnLoop.PreviewOmen`。Guard と構えを数え、休みと空振りは 0）、状態とスタンスの固定の値、敵のスタミナ（1 点 1）、次のターンに残る自分のスタミナ（1 点 2。最大 − 3 を超える分は数えない）、倒した敵（1 体につき 15）、追撃（1 点につき 0.6）から作ります。勝った盤面は +10000、負けた盤面は −10000 で、ほかの項は足しません。定数は `GreedyPlayer.cs` の先頭にあります。

間合いの方針は、最も近い敵との間合いの変化に足す偏りです。

| 方針 | 中身 |
| --- | --- |
| Neutral（位置の偏りなし） | 間合い 3 以上から詰めた 1 マスに 2。表の主な行はこの方針で測る |
| Close（詰め続ける） | 詰めた 1 マスに +6、離れた 1 マスに −6 |
| Away（離れ続ける） | Close の逆 |
| InOut（出入りする） | そのターンに攻撃を出すまでは Close、出した後は Away |
| KeepTwo（間合い 2 以上に居続ける） | 詰めた後の間合いが 2 未満になる札に −50（1 → 0 も含む）。2 未満から離れる 1 マスに +6 |

## デッキ

`Decks.cs` のコメントに、§19.8 のどの記述からその札を選んだかを書いています。役割は v4.5 のものです。スタンスの札 14 種はスタンスだけを持ち、観察・間合い切り・覚悟は Guard を持つので防御に数えます。

- 型 6 種（溜め放ち / 振り子 / 研ぎ / 血路 / 一型 / 背水）。各 20 枚、同種 3 枚まで。一型は鉄壁の構え（v4.5 で「毎ターン 1 回、防御のカードのコスト −1」）の割引が効くよう、防御の札を 6 枚にしています（峰打ち × 2 を受け太刀 × 2 に替えた）。
- コスト 1 だけ: コストが 1 の札を全種 1 枚ずつ。
- スタンス無し: スタンスの札を持つ型（振り子 / 血路 / 一型）について、スタンスの札を素直な札（突き / 鉄の受け / 横薙ぎ / 深い呼吸）へ差し替えたもの。
- 初期デッキ: 試運転のデッキ（`PrototypeDeck`、10 種 × 2）。
- 初期 40 種 × 1: `swordsman_cards_v4` §2 の #1〜#40 を 1 枚ずつ。id を 1 つずつ書いて組むので、カード表の並びが変わってもデッキは変わりません。
- 素直だけ: 特性の無い札 × 3（参考の行）。

## 決めごと

- 敵は `Enemies.All` の 13 体と 1 対 1 で戦います。場のマスは「プレイヤーのマス 2 + 開始の間合い 3 + 敵の大きさ」です（6 か 7）。
- 60 ターンで決着しない戦闘は詰まり（stall）です。勝ちにも負けにも数えません。勝率は「勝った戦闘 ÷ 全ての戦闘」なので、詰まりは勝てなかった戦闘として分母に入ります。数は表の下の 1 行と JSON に別に出します。ターン数の中央値（基準 1 / 2）には 60 ターンとして入り、その数を備考に書きます。
- 種は「元の種・戦闘の種類・敵・何戦目」から作り、デッキと方針は混ぜません。どのデッキも同じ種の並びで戦うので、デッキどうしの差がぶれにくくなります。
- 基準 5 / S15 の 1 撃の最大値は、主な戦闘の全てのデッキの全試行の最大です（`battle_core_v4.md` §13「15 は全試行の最大値を取ります」）。`--only first3` でも同じデッキを回すので、判定は変わりません。表には最大を出したデッキの名前を出し、JSON には id を残します。
- 基準 3 / 13 / S14 の「〜pt 以上上回らない / 下回らない」は、ちょうどその pt の差を不合格として読みます。ちょうど 10 pt 下回れば S14 は fail です。
- 基準 S16 は、スタンスの札を持つ型ごとの中央値で判定します。全ての型が 1〜2 に入れば合格で、型をまとめた中央値は備考に出します。スタンスの札が 1 枚の型は、出したスタンスが除外されるので 1 戦に 1 回までしか出せず、まとめると多く出す型を隠すためです。
- 基準 7 は、スタンスがどれだけ勝率を足しているかで読みます。次の 2 つがどちらも通れば合格です。(a) スタンスの札を持たないデッキ（差し替え版と、もともとスタンスを持たない型）で最もよいものが「最強の型 − 15 pt」以上（§13 の字面）。(b) 差し替え版のどれも、元の型に 15 pt 以上負けない（`swordsman_cards_v4` §5-7。ちょうど 15 pt 負けたら fail）。`battle_core_v4.md` §19.6 は基準 7 を「必須化の上限」と書いています。スタンスの有無を問わず弱い型は基準 6 の差で見るので、基準 7 では落としません。(b) が通れば (a) も通るので、判定を決めるのは実際には (b) です。値は (b) の差し替え版 − 元の型の最小で、型ごとの差を備考に出します。
- 基準 10 の合格の線は、敵の数の 3 分の 2 以上（端数は切り上げ）です（§13、#403）。コアの敵は 13 体なので、9 体以上で合格です。
- 基準 11 は、初期 40 種 × 1 のデッキで判定します（`battle_core_v4.md` §14-4 が「初期 40 種を 1 枚ずつ入れたデッキ」で計算しているため）。試験台の種で `TurnLoop.Start` と `BeginPlayerTurn` に最初の手札を配らせ、移動の効果の札が 1 枚も無い手札の割合を数えます。手札の枚数はコアの `Constants.HandDraw`（いまは 6、#351）です。備考に、同じデッキの戦闘中の全ての手札の値、超幾何分布の机上の値 C(30,6) / C(40,6) ≈ 15.5%、試運転のデッキの値を並べます。
- 2 連戦は、通常 7 体をロースターの順に次の 1 体と組んだ 7 組で、休憩なしで HP とスタミナを持ち越します。どちらかが詰まった組は詰まりとして数え、勝ちには数えません。
- 測れない行: 1 ターンの判断時間（人が遊んで測る）と刻み（習熟は BattleCore にまだ無い）。
