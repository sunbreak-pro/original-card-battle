## 「80%」の定義（これを満たしたら完了）

- 戦闘中に見えるべき情報が全て、見るべき優先順位で画面に置かれている: HP / Guard / スタミナ（現在・最大、投入量の選択）/ 間合い / 予兆 / 瘴気（蓄積と濃度）/ 刻限 / 手札 / 敵の頁（手記、読むだけ）
- プレイヤーの 1 ターンの判断（どのカードを / いくら投入して / どこへ動くか）が、迷わず 3 操作以内でできる操作設計になっている
- 主要な状態変化に演出の仕様がある: カードのプレイと投入量、間合いの移動、予兆の提示と的中 / 空振り、構え、崩し、被弾と Guard、勝敗
- 見た目の方向（色・書体・キャラクターの見せ方・背景の階層差）が 1 枚の指針に決まっていて、モックアップで確認できる
- Unity での実装に必要な単位（Canvas 階層、アニメーションの長さと補間、アセットの一覧）に落ちている
- 残り 20% は「実機で触って直す調整」と「本物の立ち絵・効果音」と明記する

## 進め方

1. task-tracker で MEMORY の予定「戦闘 UI / UX 80%」を進行中へ
2. 情報設計を先に: 画面に出す値と優先順位を表にし、「予兆に対して間合いとスタミナをどう使うか」が一目で分かる配置を決める。間合いはタブやトラックでなく、2 体の距離と体勢で見せる（決定済み）
3. 見た目の方向を 2〜3 案（例: 幻想寄り / 写実寄り / 版画的）出し、それぞれをモックアップで比べる。色・書体・数字の書体（tabular）・階層ごとの背景の濃淡を含める。ui-ux-creator の既存パレットは参考にとどめる
4. 演出仕様: 各状態変化について「何が / どの順で / 何ミリ秒 / どの補間で / 音の有無」を表にする。予兆の的中と空振り回避、崩し（相手のスタミナが削れる）、構え（Guard +2）は必ず含める。乱数なしの戦闘なので、演出で結果を曖昧にしない
5. Unity 写像: Canvas 階層、Animator か DOTween 相当か、必要アセット（立ち絵の差分数、エフェクト、UI 部品）を一覧にする
6. 判断材料を HTML にまとめて Artifact 発行。見た目の方向は「採用 / 保留 / 見送り」で示す
7. session-verifier は文書のみなので軽く。task-tracker END で MEMORY / HISTORY を更新し commit
