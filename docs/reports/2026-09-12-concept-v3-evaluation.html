評価 A: ゲームデザイン観点

良くなった: 経済 6 系統（Gold / 魔石 / ソウル / 装備 Lv / 品質 / 修理）を捨てて単一の循環にした。投入 0〜3 で 1 枚の判断に幅が出た。探索カードと戦闘カードのデッキ内ジレンマは旧設計に無い。全リセットの廃止で「死は学習」の意図と矛盾しなくなった。

悪くなった: 手記の継承を捨てたので同じ敵を毎回観察し直す。永続成長が無く、詰まったときの逃げ道がプレイヤー技量だけ。「持ち帰るか進むか」の緊張が消え、生存ルートの見返りが未定義で代替になっていない。防御が Guard 1 層なのに適応 AI が「防御多用」を罰する。

矛盾: 永続能力（§4.1）は §9 表で死亡時に失われる。所持 80 枚の入手源が無い。

評価 B: 実装観点

順序: R1-3 の「パリティ fixture を更新」は TS と C# の二重実装を強いる。C# を正に切り替えるかパリティを打ち切るかを決める必要がある。R1-10 図鑑が観察手段（R1-6）より先。R1-7 の受け入れ基準が R1-14 の画面に依存。

抜け: 探索（階層・ノード）の Unity 実装、生と世代のデータモデル、戦闘 → 探索の結果の戻り経路（HP / スタミナ / 衰弱）、シーン遷移、HUD の帰属（R1-9 と R2-5）。

C# コアとの整合: 乱数注入・BattleStore・ViewModel 射影・シャッフルはそのまま使える。固定コスト / MaxStamina 20 / 疲労 / if 分岐の敵 AI は作り直し。battle_core_v3.md §13 の写像表がこれに対応する。

評価 C: 反対弁護人

重大 3 件: 遺産の連鎖消失（深層で死んだ A の遺産は B が届く前に死ぬと消える）。HP 回復の空白。「経済の記述なし」は事実と違う（企画書 §10.2・§22 に資源・アイテムがある）。

分類の疑い: 帰還は「廃止」ではなく生存ルートへの再解釈。ソウルは「凍結」と書きつつ実質廃止。Journal は「置換」ではなく再解釈。

アーマー凍結の副作用: 装備の存在意義が消える。凍結が 3 施設 + 倉庫に連鎖し廃止と差が無い。「一度だけ防御」ツールと「応急処置」カードは小型のアーマー / 回復で、凍結理由と両立しない。C# コアに AP は元々無いので、凍結は既定状態の追認。

差し戻しの条件: HP 回復モデル / スタミナ基礎値 / 持ち越し / 遺産の場所を決める。連鎖消失の規則を入れる。生存ルートの悪用対策。v3 版ギャップ分析。アイテム / 資源を凍結から外す。

評価 C は life-editor の元 Note を読めなかった（認証情報の参照拒否）。忠実性の判定は concept-v3 の自己言及からの間接推定。

  • 評価で挙がった設計判断（HP 回復、遺産の連鎖、図鑑の消失、セーブ前倒し、帰還の分類）は直さず判断待ちにした。転記ミスと事実誤りだけ直した。

次に判断が要る点

  1. HP の回復モデル（§12-20）。3 体とも指摘。案: 休息で HP も回復（刻限 -1）、階層到達で小回復、応急処置カード。衰弱を「生の長さ」に保つなら HP は戦闘間で持ち越しつつ回復手段を厚くする。
  2. 遺産の連鎖消失（§12-21）。案: 未回収の遺産は次の死亡で上書きされず、直近 1 件として残る。
  3. 図鑑を死で消す方針を保つか。企画書どおり消すなら、遺産の知識枠と予兆で補う（今回の設計）。一部を残すなら A1「手記は死を越える」の部分復活。
  4. セーブ（R1-16）を Phase 4 の頭へ前倒しするか。遺産とセーブスカムの関係から、私は前倒しを推します。
  5. TS / C# のパリティを続けるか。R1-3 で C# を正に切り替え、TS の battle-lab は凍結する案を推します。
  6. 戦闘設計書 v1 の数値でプロトタイプを回すか。Unity 側で R1-3 / R1-4 を実装して 6 観点を見るのが次の一手です。
