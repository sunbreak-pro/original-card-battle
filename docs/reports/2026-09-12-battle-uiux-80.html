戦闘 UI / UX は 80% に届いた。見た目は A「霧と灯り」を推す

情報の置き場、2 操作のプレイ、10 節の演出仕様、Unity の実装単位まで設計書に落ちました。残るのは見た目 3 案の最終選択と、実機で触って直す 20% です。

  • 採用（推奨）

    A 霧と灯り（幻想寄り）

    アニメ 2.5D の立ち絵（Live2D）の塗りと光を生かせる唯一の案。concept-v2 から続く「幻想ベース、階層で濃淡」に一致し、灯りが深層で小さくなる演出に伸ばせる。

  • 保留

    C 墨と朱（版画的）

    手記の頁と敗北画面（「力尽きた」「手記はここに残る」）の表現として残す。「朱は予兆と被弾だけ」の規律は A に取り込む。

  • 見送り

    B 鉄と革（写実寄り）

    アニメ調の立ち絵と喧嘩する。硬い質感は世界観より「軍事シム」に寄る。

前提: ルールと数値は battle_core_v3.md のまま。本設計はその値の見せ方と操作だけを決め、乱数の無い戦闘なので演出で結果を曖昧にしない。

1 ターンの操作

操作 1

カードを選ぶ

クリックかキー 1〜3。カードが持ち上がり、投入量チップ T0〜T3 が現在の間合いでの予測値付きで出る。移動を含むカードなら移動先に残像が立ち、床の狙い帯の色が移動後の補正に変わる。

操作 2

投入量を押す

チップのクリックがそのままプレイ。既定は「使った後も残 3 以上になる最大の段」で、構え維持の注記付き。払えない段は薄く、押せない。

操作 3

ターンを終える

ボタンの上に「今終えると 残 7 → Guard +2」が常に出る。敵フェーズは自動で進み、Space で早送りしても数値と位置は変わらない。

種類実装理由
位置・数値・色・alpha の補間DOTween（無料版）距離 260 / 520 / 820 のパラメータ補間は tween が自然。§5 の ms と ease をそのまま書ける
立ち絵の体勢・攻撃・被弾・崩れ・倒れAnimator（Live2D は Cubism Motion）絵に紐づくクリップ。GUI で反復調整する
演出の順序と早送りDOTween の Sequence + timeScale1 行動 = 1 Sequence。早送りしても結果は同じ

アセット: 立ち絵は Live2D ならモデル 1 + モーション 8 + パラメータ 3、差分スプライトなら 11 枚（敵は 12 枚）。エフェクト 7 種、UI 部品 12 種、書体 3（Shippori Mincho / Zen Kaku Gothic New / IBM Plex Mono、全て OFL）。

残り 20% の内訳

  • 実機で触って直す調整（約 10%）: ms と ease の微調整、早送りの手触り、チップの当たり判定、ゲームパッドの割当、ウルトラワイドでの L1 / L2 切替。
  • 本物の立ち絵と効果音（約 8%）: Live2D モデル 2 体、モーション 8 + 5、効果音 12 種。灯りと靄の質感はプレースホルダのまま。
  • 開示度の実データ（約 2%）: R2-3 で開示度の段階が決まったら §7 の仮置き 3 段を合わせる。ボスの 2 段階予兆は範囲外。

置いた仮定

  • ブランチは未マージの docs/concept-v3-inheritance-loop から切った。main に戻すと concept-v3 の前提が無くなるため。
  • チップのクリックをそのままプレイにした（確認ボタン無し）。誤操作より操作数を優先し、選べない段は押せなくして防ぐ。
  • 既定の投入量は敵 AI と同じ「残 3 以上を保つ最大の段」。プレイヤーの初手が温存の意味を自然に守るようにした。
  • 開示度は表示側から 0 / 1 / 2 の 3 段を仮置きした。ルール側（R2-3）が決めたら合わせる。
  • 人型は当面 Canvas 内（RawImage に Live2D の RenderTexture）。世界座標に出すのは UI との前後関係が問題になってから。
  • 敵の Guard と構えは対称に表示する。
  • 間合いの床の帯は「トラック UI」ではなく、予兆の狙い範囲を示す補助。段階を選ぶ操作はできない。

未確認のこと

  • Google Fonts の Shippori Mincho / Yuji Syuku が Unity の TextMeshPro で JIS 第 1 水準を欠けなく持つか（OFL なので同梱は可）。
  • DOTween 無料版で Sequence の timeScale 早送りが Animator と同期して破綻しないか。実機で確認する。
  • 端数処理。battle_core_v3.md §7.3 の round が 2.5 を 3 にするか 2 にするか（C# の Math.Round は既定で銀行家丸め）。モックアップは暫定で切り捨て。ルール側への要望に加えた。

ルール側に返したい要望

  • 開示度の段階を定義してほしい（§7 の 3 段を叩き台に）。予兆バナーと狙い帯の出し分けに要る。
  • 崩しを受けた敵の「次は低投入になる」見込みを予兆に添えてよいか。開示度 2 限定なら矛盾しない。
  • 端で止まる移動（clamp）をイベントとして通知してほしい。UI が「これ以上下がれない」を出す。
  • 敵の Guard と構えを対称に見せる前提でよいか。
  • 端数処理（MidpointRounding）を C# 側で確定してほしい。UI は予測値を確定値で出すため。

次に判断が要る点

  • 見た目の最終選択: A を推す。モックアップで A / B / C を階層 1 / 3 / 5 で見比べてから決めてほしい。
  • C の使い所: 手記の頁と敗北画面に版画的な表現を使うか。使うなら手記 UI の設計時に決める。
