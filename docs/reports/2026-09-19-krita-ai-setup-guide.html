Krita で AI に描かせて、自分で仕上げる

導入の続きから、機能の全体、このゲームの立ち絵と差分を作る手順までをまとめたガイドです。

結論: Krita に追加機能「Krita AI Diffusion」を入れ、裏方の生成サーバーは追加機能に自動で入れさせます（Local Managed Server）。

絵を作るモデルは Animagine XL 4.0 にします。ポーズ違いの差分は Flux 2 Klein 4B の編集機能で作ります。どちらも商用に使えるライセンスです。

インストール済みの Comfy Desktop は、今回の手順では使いません。追加機能が求める部品と版を自分でそろえる手間が大きいためです。

1. 3 つのアプリの関係と、いまの状態

料理にたとえると、Krita は台所です。AI の生成サーバー（ComfyUI）はオーブンで、追加機能（Krita AI Diffusion）は台所の壁についたオーブンの操作パネルです。こうだいさんは台所に立ったまま、パネルでオーブンに焼かせ、焼けたものを包丁で整えます。

台所（絵を描くアプリ）

Krita 5.3.4

無料の描画アプリです。レイヤー、ブラシ、選択範囲、変形など、手で描いて直す道具がそろっています。

操作パネル（追加機能）

Krita AI Diffusion

Krita の中に「AI Image Generation」パネルを足します。指示の入力、選択範囲への描き直し、下絵からの清書を Krita の画面で行います。GPL-3.0 の無料ソフトです。

オーブン（生成サーバー）

ComfyUI

実際に AI で絵を作るプログラムです。画面の裏で動き、追加機能から注文を受けて絵を返します。

正確には、追加機能は ComfyUI に「処理の手順書（ワークフロー）」を送り、ComfyUI が GPU で計算して画像を返します。ComfyUI の入れ方は 2 通りあります。1 つは追加機能に自動で入れさせる方法（Local Managed Server）です。もう 1 つは、自分で入れた ComfyUI につなぐ方法（Custom Server）です。

自分で入れた ComfyUI につなぐと、追加の部品 4 つ（ControlNet 前処理、IP-Adapter、Inpaint、Tooling）と必須モデル十数個を、正しい名前と場所でそろえる必要があります。ComfyUI が更新されると、部品との版の食い違いで止まることもあります。Local Managed Server なら、追加機能の作者が動作を確かめた組み合わせを一括で入れます。

Comfy Desktop は消さなくてかまいません。ただし、生成サーバーと Comfy Desktop を同時に起動すると VRAM を取り合います。使うときは片方だけにします。不要ならアンインストールしてもかまいません。

2. セットアップ手順（インストールの続き）

所要時間は、手作業が 20〜30 分と、ダウンロード待ちが回線しだいで 30〜90 分の見込みです（推定）。メニュー名は公式ドキュメントの英語表記です。Krita を日本語で使っている場合は、カッコ内の訳を目安にしてください。

  1. 追加機能の zip をダウンロードする

    GitHub のリリースページから krita_ai_diffusion-1.53.0.zip を保存します。展開はしません。

    Krita 6 が出たら、追加機能は 2.x 系を使います。いまの Krita 5.3.4 には 1.x 系が正解です。

  2. Krita に取り込む

    Krita を起動し、Tools ▸ Scripts ▸ Import Python Plugin from File...（ツール ▸ スクリプト ▸ ファイルから Python プラグインをインポート）を選びます。保存した zip を選びます。

    「プラグインを有効にするか」と聞かれたら Yes を押します。そのあと Krita を再起動します。再起動しないとパネルが出ません。

  3. パネルを表示する

    新しい文書を作ります。最初は小さめ（例: 1024×1024）で十分です。

    Settings ▸ Dockers ▸ AI Image Generation（設定 ▸ ドッキングパネル ▸ AI Image Generation）にチェックを入れます。画面の端に「AI Image Generation」パネルが出ます。

  4. 生成サーバーの種類を選ぶ

    パネルの Configure を押します。3 つの選択肢が出ます。

    選択肢中身選ぶか
    Online Service作者が運営するクラウドの GPU で生成します。アカウントが要り、有料です選ばない 0 円の方針に合いません
    Local Managed Server追加機能が ComfyUI と部品とモデルを自分の PC に入れ、起動と停止も受け持ちますこれを選ぶ
    Custom Server自分で入れた ComfyUI（Comfy Desktop など）につなぎます選ばない 1 章の理由のとおりです

  5. サーバーの入れ場所と種類を決める

    Local Managed Server を選ぶと、インストール画面が出ます。次のように設定します。

    • Server Path（入れ場所）: C:\ai\krita-server にします。既定は %APPDATA%\krita\ai_diffusion\server ですが、OneDrive の同期対象や、空白を含む場所は避けます。
    • Backend: CUDA を選びます。NVIDIA の GPU 用です。インストールの前に選ぶ必要があり、あとからは変えにくい項目です。
    • Workloads（モデルのまとまり）: 下の表のとおり、SDXL と Flux 2 の 2 つだけにチェックを入れます。
    Workload入れるか理由
    SD 1.5入れない古い世代で、画質が一段落ちます
    SDXL入れるAnimagine XL 4.0 はこの世代のモデルです。下絵・参照画像・選択範囲の描き直しに使う部品は、商用可の Apache-2.0 か OpenRAIL です
    Illustrious / NoobAI入れないこの系統向けの部品の多くは NoobAI の派生で、ライセンス（fair-ai-public-license）が商用利用を制限します。5 章を読んでください
    Flux 2（Klein 4B）入れる「槍を振り上げさせて」のような文章の指示で、同じ人物のポーズを変えられます。Apache-2.0 で商用可です
    Flux 1 / Z-Image入れない写真寄りのモデルで、8 GB では重く、今回の用途に要りません

    Individual Packages タブでは、次の 3 つを追加で選びます。そのほかは既定のままにします。

    • ControlNet Universal (XL): 落書き・線画・ポーズの棒人間などを下絵として読ませる部品です（xinsir、Apache-2.0）。差分づくりの中心になります。
    • Flux 2 Klein 4B [Q6_K]: 8 GB 向けに軽くした版です。fp8 版と Q6_K 版が選べる場合は Q6_K にします。
    • HAT Super-Resolution: 画像を大きくする部品です（Apache-2.0）。任意です。

    最後に Install を押します。ここで数十 GB のダウンロードが始まります。終わるまで Krita を閉じないでください。

  6. Animagine XL 4.0 を置く

    Hugging Face のページから animagine-xl-4.0-opt.safetensors（約 6.9 GB）をダウンロードします。opt は、手足の形と色を改良した版です。

    ファイルを C:\ai\krita-server\ComfyUI\models\checkpoints\ に置きます。フォルダーがなければ、インストールが終わっているかを確かめます。

    ライセンスは CreativeML Open RAIL++-M で、商用利用を認めています。違法・有害な用途は禁じられています。

  7. サーバーを起動して接続する

    設定画面の Connection で Launch（起動）を押します。数十秒で「Connected」になります。以後は Krita を起動すると自動でサーバーも起動します。

    接続できないときは、必須モデルが欠けています。Manage ▸ Verify を押すと、全モデルを検査して足りない物を取り直します。

  8. このゲーム用の「スタイル」を作る

    スタイルは、モデルと生成の設定をまとめた「レシピカード」です。パネル上部のスタイル一覧の横にある設定ボタンから Style 設定を開き、新しいスタイルを作って、次の値を入れます。

    項目値根拠
    名前card-battle Animagine—
    Model Checkpointanimagine-xl-4.0-opt一覧に出ないときは再読み込みボタンを押します
    Base model（Checkpoint configuration (advanced)）Automatic のまま（SDXL と判定される）Illustrious に手動で切り替えないでください。切り替えると NoobAI 系の部品が使われます
    Sampler presetAlternative（Euler Ancestral）Animagine の推奨サンプラーが Euler a です
    Steps / CFG28 / 5Animagine の推奨は Steps 25〜28、CFG 4〜7（推奨 5）です
    Style Prompt（後ろに付ける言葉）{prompt}, masterpiece, high score, great score, absurdresAnimagine の画質タグです。{prompt} の位置に毎回の指示が入ります
    Negative Prompt（避けたい物）lowres, bad anatomy, bad hands, text, error, missing finger, extra digits, fewer digits, cropped, worst quality, low quality, low score, bad score, average score, signature, watermark, username, blurry, bloodAnimagine の推奨に、流血の禁止（blood）を足しました

    同じ要領で、Flux 2 Klein 4B を使うスタイル（名前 card-battle Edit）も作ります。こちらは Style Prompt を空にし、そのほかは既定のままにします。

  9. 画面と性能の設定

    設定画面の各タブで、次を変えます。

    • Interface ▸ ネガティブプロンプトを表示: オンにします。パネルに「避けたい物」の欄が出ます。
    • Interface ▸ 翻訳（Translation）: 日本語（ja）を選びます。指示を日本語で書くと、生成前に英語へ訳されます。ローカルサーバーで動きます。
    • Interface ▸ タグの自動補完: オンにします。Animagine はタグ形式の指示を好むので、候補が出ると書きやすくなります。
    • Interface ▸ ワークフローの書き出し: オンにします。最後の生成の workflow.json がログと同じフォルダーに残ります。モデル名と seed（乱数の種）の記録に使います。
    • Performance ▸ Maximum batch size: まず既定のままにします。VRAM 不足で遅くなったら 1 に下げます。
    • Performance ▸ Resolution multiplier: 1.0 のままにします。候補を早く見たいときだけ、パネルの一時切り替えで 0.5〜0.75 にします。

  10. 動作を確かめる

    1024×1024 の新しい文書で、指示欄に 1boy, solo, samurai, standing, full body, simple background と入れ、Generate（Shift+Enter）を押します。

    • 30 秒〜1 分ほどで、キャンバスに下書きとして絵が出る
    • 下の履歴に小さな画像が並ぶ
    • Apply を押すと、新しいレイヤーとして載る
    • タスクマネージャーの GPU の「専用 GPU メモリ」が 8 GB に張りついていない

    ここまで通ったら、生成の秒数とピークの VRAM をメモしてください。0 円案が 8 GB で成り立つかの判断材料になります。

3. Krita AI Diffusion でできること

機能は多いですが、軸は 3 つです。一から作る、一部を描き直す、下絵や見本に従わせるです。3 つを組み合わせて、少しずつ絵を目標に寄せていきます。

3.1 生成の基本: Generate、Apply、履歴

  • Generate: キャンバスの中身を無視して、同じ大きさの新しい絵を作ります。
  • 下書きの表示: 結果はまずキャンバス上の「仮の表示」です。同じ指示で何枚も作り、履歴から選ぶ使い方が前提です。
  • Apply: 履歴の画像の Apply ボタンを押すか、画像をダブルクリックすると、新しいレイヤーとして確定します。不要な結果は確定しないだけで消えます。
  • 複数を混ぜる: 気に入った部分が複数の結果に散らばっているときは、全部 Apply します。そのうえで、要らない部分を柔らかい消しゴムで消して混ぜます（Generate & Erase）。

3.2 強さ（Strength）と Refine

強さのスライダーは「いまの絵をどれだけ残すか」の逆です。100% は一から作り直し、100% 未満にするとボタンが Refine に変わります。Refine はいまの絵を出発点にして描き直します（image-to-image）。

  • 30〜70% がよく使う範囲です。 仕上げに近づくほど下げます。
  • 用途: 質感・陰影・細部の追加、崩れの除去（色と形は残す）、絵柄の寄せ（写真調→アニメ調など）です。
  • 注意: 生成結果を Refine するときは、先に Apply してください。Apply しないと、白いキャンバスを描き直すことになります。

3.3 選択範囲への描き直し（Selection Fill）

Krita の選択ツールで範囲を囲むと、生成はその範囲だけになります。ボタンの横の下向き矢印で、描き直し方を選べます。

モードすることこのゲームでの使い道
Fill周りになじむように描き直す。周辺の色に寄る崩れた手・顔・武器の先の描き直し
Expandキャンバスを広げた余白を描き足す足元や武器の先が切れた絵を広げる
Add Content新しい物を足す。指示か下絵が要る小物（世代差分の護符・布など）を足す
Remove Content物を消して周りで埋める使わない 非商用ライセンスのモデル（MAT）を使います
Replace Background選んだ人物を残し、背景を入れ替える（実験的）背景を単色にそろえる
Customなじませ方（Seamless）、指示の対象（Focus）、塗りの前処理（Fill）、周辺の範囲（Context）を手で決めるSeamless のチェックを外す（既定で入っていて、入っていると条文を確かめられない Fooocus Inpaint を読みます）。Fill の「Inpaint」は MAT を使うので選ばない
強度 80% を超えないこと（2026-09-23 追記）

SDXL（Animagine）で選択範囲に描くと、強度が 80% を超えたときに Fooocus Inpaint が読み込まれます。Fill・Expand・Add Content・Replace Background は、既定の強度 100% のままだとこれに当たります。Fooocus Inpaint はライセンスの条文を確かめられないので、選択範囲は強度 80% 以下の Refine で描き直すか、Custom で Seamless を外して使います。根拠は tools-and-prerequisites.md §13 です。

生成は選択範囲より少しはみ出します。はみ出しは消しゴムで消せますが、足りない分はあとから足しにくいからです。はみ出しの量は Diffusion 設定の Selection Feather と Selection Blend で変えられます。

3.4 コントロールレイヤー（下絵や見本に従わせる）

文章だけで狙いどおりの構図を出すのは難しいので、画像で指示します。レイヤーを選び、Add control layer ボタンで種類を選ぶと、そのレイヤーが指示になります。レイヤーを非表示にしても効きます。

見本型（参照画像）: 雰囲気や人物を写す

  • Reference: 人物・構図・色・絵柄を見本から取ります。文章の指示と同じくらいの自由度で効きます。承認した主人公の絵を入れておくと、差分でも同じ人物に寄ります。
  • Style / Composition: 絵柄だけ、構図だけを取ります。SDXL でよく効きます。
  • Face: 顔の特徴を写します。SDXL で使えるかは未確認です。
  • 見本は正方形が向いています。透明な部分は無視されます。

構造型: 位置を画素単位で合わせる

  • Scribble / Line Art / Soft Edge / Canny Edge: 落書きや線画の位置に形を合わせます。手描きのラフを清書させるときに使います。
  • Pose: OpenPose の棒人間でポーズを指示します。棒人間は Krita のベクターツールで関節を動かして編集できます。差分づくりの主役です。
  • Depth / Normal: 奥行きや面の向きで形を指示します。3D ソフトから出した図が使えます。
  • Unblur: ぼかした絵を元に、そっくりな絵を細部だけ変えて作ります。
  • Segmentation / Stencil: 色分けの図や白黒の型で配置を決めます。今回は使いません。
  • From image: いま見えている絵から、下絵（線画・棒人間など）を自動で作ります。使ってよいのは Canny（モデルを使わない）と Line Art（MIT）だけです。Depth は非商用のモデル（Depth Anything V2 Base）、Scribble は研究目的の但し書きがあるモデル（PiDiNet）、Pose はライセンスが未確認の検出モデル（YOLO-NAS）を使います。製品に使う差分では、棒人間を手で置くほうが安全です。
  • Hands: 手の形を直すコントロールです。使わない 非商用の手のモデル（MANO）を使います。
  • 強さと範囲: スライダーで効きの強さを、詳細設定の Range で「生成のどの段階に効かせるか」を決めます。構図は前半で、細部は後半で決まります。

3.5 リージョン（場所ごとの指示）

画面の場所ごとに、別の指示と見本を割り当てます。「左は槍の兵、右は犬」のように複数の物を描き分けるときに使います。構図を決める道具ではないので、形は下絵のコントロールレイヤーで決めます。立ち絵は 1 体ずつ作るので、出番は背景の絵を作るときぐらいです。

3.6 編集モデル（文章で直させる）

Flux 2 Klein 4B は、今ある絵を「命令」で直すモデルです。「槍を頭上に振り上げさせて。顔と服は変えない」のように書きます。

  • 得意: ポーズの変更、照明の変更、物の追加と削除、人物を切り出して白背景に置くことです。
  • 書き方: 対象を特徴で名指しし、変えたい点を 1 つずつ書きます。「変えない物」も明記します。
  • 強さ: 100% で使います。下げると何も変わらないことが多いです。
  • 弱み: 体のつじつまが崩れることがあり、アニメ調の絵柄も Animagine ほどそろいません。編集のあとに Animagine のスタイルで低い強さの Refine をかけて、絵柄を戻します。
  • 複数の画像: 見本の画像を別レイヤーに置き、Add control layer で足すと、「この服を着せて」のような指示ができます。画像を足すほど VRAM と時間が増えます。

3.8 指示文の書き方

  • 言語: 基本は英語です。2 章で翻訳をオンにすれば、日本語で書けます。
  • 強調: (polearm:1.3) で強め、(red:0.8) で弱めます。単語にカーソルを置いて Ctrl+↑/↓ でも変えられます。
  • コメント: # から行末までは無視されます。一時的に外したい言葉に使います。
  • ワイルドカード: {tattered robe|rusted armor|straw cape} と書くと、生成ごとに 1 つが選ばれます。外見の案出しに向いています。
  • LoRA: <lora:ファイル名:0.7> で、同じ人物を保つための追加学習データを効かせます。
  • レイヤー参照: <layer:レイヤー名> で、そのレイヤーを見本（Reference）として使います。
  • Animagine の語順: 「1boy などの人数 → キャラ名（今回はなし）→ 作品名（なし）→ そのほかのタグ → 画質タグ」の順が推奨です。画質タグはスタイルが自動で足します。

3.9 解像度

  • 生成の大きさ: キャンバスの大きさがそのまま生成の大きさになります。細部が甘いときは、キャンバスが小さすぎる可能性があります。
  • モデルの得意な大きさ: SDXL は約 100 万画素で学習しています。Animagine の推奨は縦長 832×1216 です。これより大きいキャンバスでは、追加機能が自動で「小さく作って拡大しながら描き直す」2 段の生成に切り替えます。
  • 割り切れる数: 縦横は 8 の倍数、できれば 64 の倍数にします。1024×1536 は両方とも 64 の倍数です。

4. ゲームの立ち絵と差分を作る手順

最初の 1 体は、試走に決めてある長柄の歪み兵（polearm_warped）で通すのを推します。主人公の見た目は、その前か並行してスタイルガイドで決めます。人 はこうだいさんの作業、Claude は Claude の作業です。

段階 0: 型をそろえる（最初の 1 回）

決まりごと値出典
ゲーム内の枠140×300（縦長、比 約 1:2.1）。足元の中央が基準点ArenaView.cs:13,29
向きすべて右向きで描く。敵はゲーム側で左右反転する同上（scaleX=-1）
原本の大きさ1024×1536 の文書で作る。取り込みは長辺 1024tools §5
背景生成中は単色の灰色。あとで抜いて透過 PNG にするtools §5
差分待機・行動・被弾 / 崩れ / 倒れ。体勢（構え）の差分は作らないtools §9 #17
禁止既存の作品名・作者名を指示に入れない。流血を描かない。購入素材や他作品の画像を見本に入れないSKILL.md「やらないこと」
人Krita の File ▸ New で 1024×1536 のテンプレートを作り、背景色を中間の灰色（例 #808080）にしておきます。 Claude仕様カード（.claude/docs/art_document/briefs/polearm_warped.md）と、英語の指示文の案を用意します。
利き手の注意

敵はゲーム側で反転するので、右手に持った槍は画面では左手になります。武器を持つ手は、反転後の見え方で決めます。

段階 1: 外見を探す（候補を出して選ぶ）

  1. スタイルを card-battle Animagine にします。
  2. ワイルドカードを使った指示を入れます。例: 
    1other, solo, full body, standing, from side, facing right, holding polearm, long polearm, {tattered hooded robe|rusted lamellar armor|straw raincoat}, {bandaged face|cracked mask|hollow eyes}, corrupted soldier, dark miasma, japanese dark fantasy, muted colors, simple background, grey background
  3. 生成の回数を増やし（Generate ボタン横の回数の設定）、8〜16 枚出します。
  4. 履歴の画像にカーソルを乗せると、ワイルドカードで選ばれた語が出ます。気に入った組み合わせの指示をコピーして固定します。
  5. 主人公と並べたときに絵柄がそろうかを見て、1〜2 枚に絞ります。
人候補から 1〜2 枚を選び、選んだ理由を 1 行メモします。この選定メモは、台帳の notes 欄に入れる人の判断の記録になります。 Claude候補を並べた比較ページを作り、形がゲーム画面の 300 px の高さで見分けられるかを確かめます。
形から決めたいとき

先に黒一色で影絵を塗り、Scribble のコントロールレイヤーにします。強さを 50〜70% にして生成すると、影絵の形のまま中身を描かせられます。Claude が SVG で描いた影絵を読み込んでも使えます。

段階 2: 清書（崩れを直し、自分の手を入れる）

  1. 選んだ絵を Apply して、レイヤー名を base にします。
  2. 全体を強さ 35〜45% で Refine し、細部と陰影を整えます。結果が良ければ Apply します。
  3. 手・指・顔・槍の穂先など、崩れた箇所を選択ツールで囲み、Fill で描き直します。1 か所ずつ、何枚か出して選びます。
  4. AI で直らない所は、ブラシで描き直します。線の太さ、光の向き（スタイルガイドの値）、配色の統一は手で行います。
  5. 仕上げに強さ 20〜30% の Refine を 1 回かけると、手描きの部分がなじみます。手描きを残したい所は、先に選択範囲から外します。
  6. 作業ファイルを .kra で OneDrive に保存します（例 OneDrive\art\polearm_warped\polearm_warped_base.kra）。
人描き直しと手描きを行い、かかった時間を測ります。1 体目の時間が、残り 9 体の計画の基準になります。 Claude書き出した PNG を切り抜き・拡大して、崩れの残りを指摘します。清書の前後で差分の画像も作ります。
権利の注意

文化庁の考え方では、生成と選択だけでは、人の創作の寄与として認められにくいです。この段階で人が加えた部分が、著作物として主張できる根拠になります。何をどれだけ直したかを記録に残してください。

段階 3: 背景を抜いて透過 PNG にする

  1. 灰色の背景レイヤーを非表示にし、人物だけのレイヤーを PNG で書き出します（背景が灰色のまま残っていてかまいません）。
  2. Claude が背景を抜きます（rembg の isnet-anime、Apache-2.0）。
  3. 抜けた PNG を Krita で開き、黒と白の背景の両方で縁を確かめます。残った灰色の縁は消しゴムで消します。
人縁の残りを手で消します。 Claude背景抜き、白シルエットの作成、横幅の測定（scripts/silhouette.py）を行います。

Krita 内で済ませたい場合は、Replace Background で背景を単色に置き換えてから、色域選択で消す方法もあります。

段階 4: 差分を作る（行動・被弾・崩れ・倒れ）

方法は 2 つあります。まず A を試し、ポーズが大きく変わる差分（倒れ）だけ B にするのを推します。

方法 A: 見本 + 棒人間で描き直す（Animagine）

  1. 清書した絵を別の文書に貼り、Reference のコントロールレイヤーにします（強さ 0.6〜0.8 から）。
  2. 新しいレイヤーに Pose のコントロールレイヤーを作り、棒人間の関節をベクターツールで動かして、目的のポーズにします（例: 槍を横に薙ぐ）。
  3. 段階 1 で固定した指示に、動作の言葉だけ足します。例: swinging polearm, sweeping attack, dynamic pose。
  4. 8 枚ほど出し、清書版と同じ人物に見える物を選びます。そのあと段階 2・3 と同じ直しをします。

方法 B: 文章で直させる（Flux 2 Klein 4B）

  1. 清書した絵を開き、スタイルを card-battle Edit にします。ボタンが Edit になります。
  2. 命令を英語で書きます（翻訳を使えば日本語でも可）。例: 
    make the soldier fall backwards onto the ground, lying on his back, polearm dropped beside him. keep the same clothes, colors and face. grey background.
  3. 結果を Apply し、スタイルを card-battle Animagine に戻して、強さ 30〜40% で Refine します。これで絵柄が清書版にそろいます。
人棒人間でポーズを置き、候補を選び、崩れを直します。 Claude差分ごとの指示文と命令文を用意し、全差分を並べて同じ人物に見えるかと、ゲーム画面の大きさでの見分けやすさを確かめます。
同じ顔がどうしても保てないとき

清書した絵を 10〜20 枚そろえて LoRA（その人物だけの追加学習）を作ります。8 GB で学習が回るかは未実測です。まず方法 A と B で足りるかを見ます。

段階 5: パーツに分ける（動かす対象だけ）

静止画の差し替えで済ませる段階 0 の敵には、この段階は要りません。Unity 2D Animation や Live2D で動かす主人公とボスだけが対象です。

  1. 清書の .kra を複製し、頭・前髪・胴・腕（上腕と前腕）・手・脚・武器などをレイヤーに切り分けます。
  2. 重なって隠れていた部分（腕の下の胴など）は、選択範囲の Fill か手描きで描き足します。
  3. レイヤー名は英語にし、命名の規則（スタイルガイドで決める）にそろえます。
  4. File ▸ Export で .psd に書き出します。
Krita の PSD の注意

Live2D が読み込みを保証しているのは Photoshop と CLIP STUDIO PAINT の PSD だけです。Krita の PSD が層のまま通るかは、1 体目で確かめます。すべての層を 1 つの最上位グループに入れると統合されるという報告があるので、グループはできるだけ使いません。Unity では、取り込み設定の Importer 欄で PSDImporter を選びます。

段階 6: Unity に取り込む

人透過 PNG を渡すだけです。 ClaudeAssets/Art/Characters/polearm_warped/chr_polearm_warped_idle_stand.png のような規則の名前で置きます。長辺 1024・BC7・足元中央の基準点を設定し、実画面で撮って確かめます。いまの差し替え口は静止画専用なので、動かす絵を差す口の追加は別の実装タスクです。

段階 7: 記録する（1 枚ごと）

2 章でオンにした workflow.json に、モデル名・seed・指示文が残ります。画像を採用するたびに、このファイルを画像と同じ名前で保存します。

人選定理由と、手を入れた内容・時間をメモします（例: 「右手の指を描き直し、槍の穂先を描き足し。40 分」）。 Claudeメモと workflow.json から、台帳 Docs/art/asset-ledger.csv の 30 列を埋めます。モデルのライセンス（Animagine は OpenRAIL++-M、Klein 4B は Apache-2.0）もここに書きます。

任意: 背景の絵を作る場合

いまの決定は「グラデーション + 靄」で、塗った背景は作りません。作るときは次の流れになります。

  1. 文書を 1920×1088（64 の倍数）で作り、奥・中・手前をリージョンで分けて指示します。
  2. 左右が足りなければ、切り抜きツール（C）でキャンバスを広げて Expand で描き足します。
  3. 奥・中・手前をレイヤーに分けて書き出すと、Claude がゲーム側で奥行きの動き（パララックス）と靄を重ねます。

人の作業は 1 階層 2〜4 時間の見込みです（推定）。文字の読みやすさの計算もやり直しになります。

6. 困ったとき

症状原因と対処
パネルが出ない取り込み後に Krita を再起動していない。Settings ▸ Dockers のチェックも確かめる
接続できない、モデルが足りないと出るConnection の Manage ▸ Verify で検査と取り直しをする。ログは Connection の「View log files」から開ける（client.log）
「Could not bind on address」ポート 8188 を別の ComfyUI（Comfy Desktop など）が使っている。そちらを閉じるか再起動する。変えるなら %APPDATA%\krita\ai_diffusion\settings.json の "server_arguments": "--port 25608"
生成が極端に遅いVRAM が足りずに溢れている。Unity・Chrome・Comfy Desktop を閉じる。キャンバスを小さくするか Resolution multiplier を下げる。Maximum batch size を 1 にする
「HeaderTooLarge」などのエラーモデルのダウンロードが壊れている。Manage ▸ Verify
「c10.dll」などが見つからないMicrosoft Visual C++ 再頒布パッケージを入れる（公式）
Refine すると白っぽくなる生成結果を Apply せずに Refine した。先に Apply する
Edit ボタンが出ないスタイルのモデルが編集モデルと判定されていない。Checkpoint configuration (advanced) で種類を確かめる
サーバーを最新にしたいConnection の Manage ▸ Re-install。モデルと設定は残る
C: の容量が減ったキャッシュ（%USERPROFILE%\.cache\huggingface、%LOCALAPPDATA%\uv\cache、%LOCALAPPDATA%\pip\cache）は中身を消してよい

Krita の公式窓口は、この追加機能の質問を受け付けていません。追加機能の Discussions か Issues を使います。Krita が OneDrive のフォルダーに入っている点は、動いている限りそのままでよいです。起動が不安定になったら、OneDrive の外へ入れ直すのを先に試します。

7. 置いた仮定と未確認、次に決めること

確かめたこと

  • 手元の版（Krita 5.3.4、Comfy Desktop 1.0.47、GPU とドライバー、空き容量）は、この PC で直接調べました。
  • 導入手順・機能・設定の名前は、追加機能の公式ドキュメントの原文（GitHub の docs/）と、最新版 1.53.0 のリリース情報で確かめました。
  • モデルのライセンスは、Hugging Face の各モデルの表記を 25 件取得して確かめました。MAT を使うのが Remove Content と Fill「Inpaint」だけであることは、追加機能のコードで確かめました。

未確認・推定

  • Krita を日本語で使っている場合のメニュー名は目安です。
  • インストール画面の細かい表記（ワークロード名、Individual Packages の並び）は、版によって違う可能性があります。
  • 8 GB で SDXL + コントロールレイヤー 2 枚、および Flux 2 Klein 4B（Q6_K）が快適に動くかは未実測です。2 章の最後の動作確認で測ります。
  • SDXL で Face モードが使えるか、Hyper-SD と YOLO-NAS のライセンス、Krita の PSD が Live2D に層のまま通るかは未確認です。
  • 所要時間（セットアップ 20〜30 分とダウンロード 30〜90 分、背景 1 階層 2〜4 時間）は推定です。

次に決めること

  • 主人公の見た目: 性別・年齢・装束・武器が未決です。段階 1 の案出しを主人公から始めるか、長柄の歪み兵から始めるかを決めてください。推奨は、主人公と長柄の歪み兵を並べて、同時に絵柄を決めることです。
  • Comfy Desktop の扱い: 残すかアンインストールするかを決めてください。残す場合でも、生成サーバーとの同時起動はしません。
