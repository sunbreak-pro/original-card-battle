削る範囲を先に決めてから、バトル画面を本実装する

Unity 側にあるのは「1 戦だけの最小戦闘画面」です。Web 版の 10 画面・十数種のリソースを全部運ぶのではなく、戦闘の柱に直結するものだけを残した「縦切り」を決め、その中心であるバトル画面から作り始めるのが最短です。

  • 今日から

    削減リストを確定し、バトル画面の本実装へ

    本レポートの「残す / 縮小 / 凍結 / 削除」を承認・修正して docs に固定し、その直後にバトル画面（Unity）の本実装に入ります。

  • 必要になったら

    最小のラン構造と拠点

    バトルが遊べるようになってから、ステージ選択 → 数戦 → 生還 / 死亡 → 拠点（有料回復・カード購入）の 1 周だけを作ります。

  • 入れない

    魔術師・魔石・実績・闇市・クエスト・噂・倉庫

    戦闘の柱（間合い・体勢・スタミナ）にも副柱（不可逆・観察）にも直結しないものは Unity へ運びません。データは Web リポに残るので復活は可能です。

前提: Unity 側の実装は BattleScreenView の最小戦闘画面のみ（カード 6 種・敵 1 体・間合い 3 段・スタミナ）。Web 版は 10 画面・9 Context・約 4 万行で、移植は未着手です。concept-v2（2026-06-27 再承認）の「剣士先行・2 ステージ・ターン制維持・エネルギー廃止・Difficulty 廃止」はそのまま前提にしています。

引っ越しで言えば、家具を全部運ぶ前に「新居に置く部屋」を決める作業です。ゲームは内側から 4 層に分かれ、内側ほど優先度が高くなります。今回の縦切りは第 1 層を本実装し、第 2〜3 層は最小の 1 周だけ、第 4 層は観察レベルだけを残します。

リソースの棚卸し

「リソース」は数字で持っていて増減するもの全部です。冷蔵庫の中身と同じで、種類が多いほど管理が重くなります。戦闘の柱に使うもの、不可逆性を作るもの、観察を記録するもの以外は外します。

提案する順序

STEP 1 / 数日

削減の確定

本レポートの提案を承認・修正し、docs/vision/plans/ に「Unity 縦切りスコープ」として固定します。tier1 の Web 依存項目（R1-3 魔術師無効化・R1-4 フック整理・R1-18 セーブ移行など）は Unity では不要と明記します。

STEP 2 / 本命

バトル画面の本実装

(a) 見た目の骨格: レイアウト確定・立ち絵プレースホルダ・カードの見た目 (b) ルール: 体勢と崩し・初期デッキ 15 枚・敵 3 体・デバフ 3 種を C# コアに追加し dotnet test で担保 (c) 演出: 被弾・移動・崩れの最小アニメ。

STEP 3 / その後

最小のラン 1 周

タイトル → ステージ選択 → 4 ノード × 3 階層 → 生還 / 死亡 → 宿と店 → 再出発。ここで初めて手記・ソウル・ライフが意味を持ちます。

STEP 2 の (b) は、TS コア（Web リポの src/ui/battle-lab/core/）を鏡写しで更新するかどうかで手間が倍変わります。C# 側だけで設計し、TS コアは「移植済み部分の基準」として凍結するのがおすすめです。パリティテストは既存 18 手順の照合に留め、新ルールは C# のユニットテストだけで守ります。

置いた仮定

  • concept-v2 と tier1 の決定事項（剣士先行・2 ステージ・ターン制維持・エネルギー廃止・Difficulty 廃止・手記の死越え永続）はそのまま有効とみなしました。
  • 「削る」の基準は、主柱（間合い・体勢・スタミナ）と副柱（不可逆性・観察）のどちらかに直結するかどうか、の 1 点にしました。
  • Unity 側は現状「1 戦のみ」なので、Web 版の画面を移植する順番 = 作る順番として整理しました。
  • 凍結・削除したデータは Web リポに残るため、いつでも戻せる前提です（Web リポは削除しません）。

未確認のこと

  • Unity リポ（sunbreak-pro/RPG-by-card）は初回コミットが未了のままです。着手前に一度コミットして土台を固定した方が安全です。
  • 装備データ約 145 件・敵 100 体の数は grep による概算です。設計書の値（剣士 60 枚・敵 40 体配属予定）と食い違う箇所は設計書側が正です。

次に判断が要る点

  1. 魔術師を凍結でよいか。concept は「後追い適合」ですが、Unity では追わないと決めれば元素共鳴・バフの半分・カード 40 枚が一気に消えます。
  2. 剣気を今回入れるか。提案は凍結です。「体勢崩し成立で剣気が溜まる」案（R1-2 BAT-7）を採るなら、体勢と同時に設計する必要があります。
  3. 装備をどこまで残すか。提案は「武器 1 + 防具 1、成長なし」です。鍛冶屋と品質ガチャを残すなら第 3 層が一気に重くなります。
  4. TS コアの追従をやめるか。提案は「移植済み部分の基準として凍結、新ルールは C# 専用」です。
