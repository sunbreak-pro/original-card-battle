デモ版は、コアに語彙を足してから 80 種を入れる計画です

カード 80 種・敵・デッキ選択・モードと終了画面・通しの試験の 5 本を、この順にそれぞれのブランチと PR まで進めます。2026-09-23 にこうだいさんが判断を確認しました。連戦で山札と捨札の並びを持ち越さないことだけを推した案から変え、ほかは推した案のまま進めます。

  • 推す案

    コアに語彙を足してから 80 種を入れます

    状態 9 語、特性の条件 12 種と効果 10 種、スタンス枠、回復と崩しをデモの精度で入れます。80 種がほぼ文書どおりに動くので、バランスを確かめる用途に使えます。

  • 必要になったら

    #48 / #49 の完了条件まで満たします

    全ての組み合わせのテストは全量版に残します。#48 / #49 を先に閉じると決まったら広げます。

  • 入れない

    64 種を近い効果で置き換えます

    Issue の字義どおりの案ですが、64 種が別の札になり、バランスの確認に使えません。

たとえると、料理 80 品を作るのに、台所に鍋が 1 つしかない状態です。いまのコアで欠けなく作れるのは約 16 品で、残る 64 品は別の鍋（連動・予兆・初手などの条件、出血・強化などの状態、スタンス）が要ります。代わりの料理を出すより、鍋を買い足してから作るほうを推します。代わりに #188 の PR はテスト込みで 2,500 行前後に膨らむ見込みです。

確認した判断

7 件のうち、5 だけを推した案から変えました。3 の手薄は 2 枚以下で決定し、カードと敵の一覧の書き直しは #193 に回しました。

番号判断決めたこと変わること
1コアに足す範囲状態・特性・スタンス・回復・崩しをデモの精度で入れます（上の推す案）。#188 が大きくなります。#48 / #49 の一部を先に作ることになります。
2ブランチの積み方5 本とも origin/main から切り、依存先のブランチを merge してから作業します。PR の base は全て main です。merge の順は #188 → #189 → #190 → #191 → #192 に決まります。PR 本文に「#◯ の後に merge」と書きます。
3手薄の枚数が文書で割れている「残り手札 2 枚以下」で決定しました。コアはこの値で入れます。カードと敵の一覧は「1 枚以下」のままなので、書き直しを #193 で cards の担当に回しました。
4試作データの食い違い（#179）伸び突き・体当たり・盾打ちの 3 枚と、錆槍の竜兵の表示名を v4.3 の文書に揃えます。縦切りで固定していたテストの期待値が変わるので、1 本ずつ計算し直します。
5連戦で何を持ち越すかHP と現在のスタミナだけを持ち越し、デッキは戦闘ごとに混ぜ直します（推した案から変更）。戦闘の間には毎回「休む / そのまま次へ」を選べます。山札と捨札の並びは持ち越しません。
6ボス 3 体の作り方決定木・2 行動・スタンスまでは入れ、専用の状態は近い通常の状態で代え、適応と段階は省きます。ボス戦はボスらしい揺さぶりが弱くなります。手触りの確認には使えます。
7通しの試験の詰まりの判定60 ターンで決着しない戦闘を詰まりとして落とします。自動の打ち手は「払える札のうち左端を出す」のままです。ボス戦が 60 ターンを超えたら、詰まりか長い戦いかを見分けてから、上限を階級ごとに分けるかを PR に書きます。

置いた仮定

  • 画面は実行時にコードで組むので、Unity のシーンとプレハブは触らない見込みです。メインのチャットの作業は、npm run unity:sync で C# を写して Battle.unity を Play することになります。
  • 大きさ 2 の敵（門竜とボス）の戦闘は、7 マスの場で戦います。
  • 自動の打ち手は左端の払える札を出すだけなので、#192 の勝率は弱い打ち手で測った値です。敵どうしを比べる初見として使います。
  • 連戦の既定の並びは、§12 の 3 体を v4.3 の id に当てた 錆槍の竜兵 → 瘴牙の走竜 → 鉄壁の門竜 です。9 戦の並びと結果のログファイルは作りません。
