キャラクターの外見と UI は、画像 API の候補を人が仕上げ、差分スプライトで動かすところから始める

敵 9 体とプレイヤーの外見、戦闘の UI / UX と演出を作るためのツールと前提をまとめました。手元には描画アプリも生成環境もまだありません。一方で Unity 6 と 2D Animation、Unity を Claude から操作する MCP は揃っています。

  • 今日から

    API で候補 → CSP で加筆 → 差分スプライト

    • 画像生成は Gemini を主、OpenAI を副にします。
    • 加筆とパーツ分けは CLIP STUDIO PAINT PRO（買い切り 6,900 円）です。
    • いまの人型に、差分と白シルエットを差し替えます。
    • UI は HTML モックから UGUI の C# に写します。
    • 権利台帳と Steam の開示を最初から付けます。
  • 必要になったら

    Live2D・2D Animation・ローカル生成

    • Live2D は主人公とボスの 2 体だけです。
    • 残り 8 体は、差分で足りなければ 2D Animation に上げます。
    • ComfyUI は 8 GB の VRAM で実測してから入れます。
    • 背景の塗り絵と TextMeshPro は後回しです。
  • 入れない

    規約か正本とぶつかるもの

    • Midjourney は、規約が自動ツールでの生成を禁じています。
    • NoobAI 系は、生成物の商用化を禁じています。
    • rembg の既定モデルは、重みが非商用です。
    • VFX Graph と Particle は、v2 が使わないと決めています。
    • Figma MCP は、無料枠が月 20 回です。
前提: 戦闘 UI v2 は「霧と灯り」の A+ で、立ち絵は 2.5D アニメ（battle_ui_ux_v2.md:511,535）です。いまの人型は、1 枚の白い型紙を Rim・Fill・Flash・残像の 4 か所で色の乗算に使っています（ArenaView.cs:207-212）。塗った絵を差すなら、差分ごとに白シルエットが要ります。

読みやすさの計算

A+ のトークンを scripts/color_check.py で計算しました。WCAG のコントラスト比と、Machado 2009 の色覚模擬での色差（ΔE）です。

組値基準判定
omen の文字、階層 1 の背景上端の上4.32:1本文 4.5:1不足
boss の文字、同じ背景の上4.28:1本文 4.5:1不足
whiff の文字、同じ背景の上3.68:1本文 4.5:1不足
warm と amberΔE 12.3（正常色覚）ΔE 20（仮）近い

不足する 3 色を背景に直接置く文字には使わず、下に panel の帯を敷く規則を v2 に提案します。狙い帯の「的中」と「半減」は塗りの色だけで分かれている（ArenaView.cs:361-363）ので、形か模様の差を足す案も上げます。ΔE 20 は規格ではなく、プロジェクトで決める仮の値です。

法務とプラットフォーム

  • Steam: ゲームに同梱してプレイヤーが目にする AI 生成物は、Pre-Generated として開示します。人が加筆した絵も対象と読めます。
  • 日本の著作権: 文化庁の考え方（2024-03-15）は、人が創作的に加筆した部分に著作物性を認めます。生成の試行回数や候補の選択だけでは寄与になりません。
  • 使う前の確認: 文化庁のチェックリスト（2024-07-31）は、類似の確認と生成過程の保存を求めます。作品名や作家名はプロンプトに入れません。
  • 購入素材: Unity Asset Store の素材は、同意なく AI の学習に使えません。参照画像にも入れません。
  • 外注: 著作権法 61 条 2 項があるので、契約に 27 条・28 条の特掲、人格権の不行使特約、AI 利用の申告を入れます。
  • 台帳: human_edit と human_minutes と選定の理由が、人の寄与の記録になります。台帳は 30 列です。

リスクと回避

リスク回避
塗った絵をそのまま差すと、Flash が白く光らず、Rim は暗い複製になります。差分ごとに白シルエットを作り、Rim・Flash・残像に使います。Fill は白で差します。
Unity 6000.5 は LTS ではありません。Cubism SDK の開発環境に 6000.5 は載っていません。敵は 2D Animation で進めます。Live2D を入れるときに 6000.5 で半日試し、動かなければ 6000.3 LTS に移します。
Overlay の Canvas には、SpriteRenderer も Live2D も直接は挟めません。段階 0 は Image の差し替えにします。段階 1 からは RenderTexture を RawImage に出します。
生成まわりのライセンスに落とし穴があります（NoobAI、rembg の既定モデル、Illustrious の版差）。台帳にモデルと版ごとのライセンスを書きます。未確認のものは pending にして、製品ビルドに入れません。
異形や流血の表現は、API に拒否されるおそれがあります。生成は「歪んだ体」までにとどめ、出血と斬撃は VFX で足します。
10 体の線と塗りがそろわないおそれがあります。スタイルガイドを先に作り、承認済みの絵を参照に固定します。それでもぶれるなら LoRA に進みます。
四足の敵と盾持ちでは、枠と反転の前提が崩れます。四足の横幅の上限と、反転後の持ち手の規則をスタイルガイドに入れます。silhouette.py が横幅を出します。
演出の時間と配置のずれを測る手段がありません。UiTween に開始と終了のログを足し、ビルドに -floor と -pose の引数を足す実装を依頼します。

一連の流れを実行するスキル

今回の調査から Note までと、その先の制作を同じ型で回せるように、プロジェクトスキル visual-production-pipeline を作りました。どのモードも、最後はレポート、Artifact、life-editor の Note（タグ card-battle）で閉じます。

呼び方工程すること
survey [観点]調べ直し今回と同じ 6 観点のワークフロー（workflows/survey.js）を回し、正本を差分で更新します。
setupS0 → S1判断の記録、LFS と .env の差分案、台帳、スタイルガイドを揃えます。
character <id>C0 → C11仕様カード、影絵、生成、選定、白シルエット、加筆、動き、取り込み、実画面、台帳の順に進みます。
background <階層>B1背景と靄のタイルを作り、立ち絵の縁のコントラストを確かめます。

人の手の工程（選ぶ、描く、リグを組む）では待ちません。材料を揃えて仕様カードの進捗欄に書き、同じ id で再開します。
