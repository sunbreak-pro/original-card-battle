#こうだいさんの決定反映場所
1移動も属性にする。コンボは属性を基準に（例: このターンにムーブをプレイ済みならスタミナ +1）。猪突猛進は アタック + ムーブ で、遠から使うと威力ボーナス属性 5 つ（アタック / ガード / スタンス / スキル / ムーブ）を 1〜2 つ、15 パターン。特性 = 条件 8 種（連動 / 位置 / 予兆 / 温存 / 死力 / 初手 / 締め / 崩し後）× 効果 7 種。A+M は moveFirst で「移動してから斬る」core v4 §2
2ドラッグ式。敵へ向けると矢印で相手を選ぶ。全体と自分への効果は画面中央で離す縦の帯 = 投入量、横 = 相手（矢印か「場」）。敵 2 体のときは矢印の先で選ぶ。カードは targets（one / all / self）を持つUI v1.2 §3.6、core v4 §7
3T0 は威力を持たせるが効果はかなり低く（アタック 5、ムーブは 1 段階）。手札が固定 5 枚なので 0 コストにも意味を残すT0: アタック面 威力 5（二属性 3）、ムーブ 1 段階、ガード 3。2 回目の決定で目盛りを 5 に合わせ、全体を約 1.6 倍（HP 50、単属性アタック 5 / 8 / 12 / 16、構え +3）。minInvest 0 は 80 種中 20 種までcore v4 §3
4スタンス枠は 1 つで試す枠 1、置き換え式、出したカードは戦闘中は山札に戻らない。効果の型 6 つcore v4 §4
5状態は 10 語でよい。ボスはより特殊で強力なものを10 語固定 + ボス専用 2 つ（瘴気纏い = 最大スタミナ −1〜−2、呪縛 = 次ターンはムーブ不可）。予兆で見えて対処できる形core v4 §5、敵 §4
6敵 9 体でよい。試験運用はまず連戦で作ることを実装フェーズが参照できるように明示§12 連戦モード（既定 3 戦、休憩の選択、HP / スタミナ / 瘴気の持ち越し、結果画面とログ）。実装プランの完了条件 4 に「連戦が最初の目標」core v4 §12、プラン
7設計書に集中し、実装は次セッション。最後に次セッション用プロンプト設計書 4 本を確定。プロンプトは §5 と実装プランに同文プラン

3. カード 80 種の案

属性 5 種（A アタック / G ガード / St スタンス / Sk スキル / M ムーブ）を 1 枚に 1〜2 つ。二属性は T の欄に「威力 5 ／ 詰め 1」のように 2 面を並べる。min は最低投入量で、0 のカードだけ T0 がある。目盛りは T0 のアタックが威力 5（単属性 5 / 8 / 12 / 16、ガード 3 / 6 / 9 / 12）。特性は「条件: 効果」で 72 枚が持ち、残り 8 枚は素直な札として各段 +2。正本は .claude/docs/card_document/swordsman_cards_v4.md。

戦闘コア v4 を Unity 用 C# に実装してください。設計は確定済みで、正本は次の 4 つです。順に読んでから着手してください。

前提:
- 現状のコードは unity-port/BattleCore/（v3、C# 9 / netstandard2.1）と unity-project-kit/Assets/View/（UGUI、v1.1）。dotnet test は 54 / 54。同期は npm run unity:sync、Unity CLI は unity test --mode EditMode と unity build --target StandaloneWindows64。手順は unity-port/README.md と HISTORY.md 2026-09-12 の項。
- v3 で検証済みの部分（投入量 / 間合い補正 / 予兆 / 構え / 崩し / 瘴気 / 端数 AwayFromZero）は変えない。
- 最初の目標は連戦モード（battle_core_v4.md §12）。単発の戦闘を作ってから繋ぐのではなく、最初から 3 戦を続けて通す形で作る。
- 試験台 BattleCore.Sim は dotnet のコンソールプロジェクトとして unity-port/ に足す。デッキの型 5 種 × 敵 9 体 × 貪欲な打ち手で、基準 9 項目を表にする。
- View はドラッグ操作（battle_ui_ux_v1.md §3.6）をまだ作らない。v4 の state で壊れないこと（5 枚の手札、状態とスタンスの文字表示）までにする。
- 触らないもの: src/（Web 版）、battle_core_v3.md、設計書の数値（差分があれば実装に合わせず、報告に回す）。
- ブランチは feat/battle-core-v4（docs/battle-100-inventory から。親は未マージ）。

進め方: 範囲（触るファイル / 完了条件 / 触らないもの）を宣言してから、Types → Combat → Reducer → Cards / Enemies → Sim → 連戦 → View 最小対応 → テスト → ビルド → スクリーンショットの順。人手の確認が要る点（Editor 前面での連戦プレイ）は報告に書く。
報告は html-report スキルで、基準 9 項目の表と連戦のスクリーンショットを載せる。

置いた仮定

  • 「移動も属性にする」を「ムーブを他の 4 つと同格の属性にする」と読んだ。1 枚は 1〜2 属性のままなので、パターンは 15 になる。
  • T0 = 5 に合わせるため全体を約 1.6 倍した（HP 50、構え +3、出血 / 再生は 1 段 2）。スタミナ・投入量・崩し・持続ターンは変えていない。
  • 特性の語彙は条件 12 × 効果 10 に固定した。同じ「条件 + 効果」の組は 3 枚まで。特性の無い札は初期の 8 枚だけで、威力 +2 / Guard +2 を上乗せしている。
  • 2 体戦は精鋭「群れの長」だけ。3 体以上は入れない。間合いは敵ごとに持ち、プレイヤーの移動は全敵に同じ向きで効く。
  • ボス専用の状態は「予兆で見えて対処できる」を条件にした。予兆なしの即時効果は作らない。
  • カードと敵の数値は全て叩き台。配分と役割だけを確定とし、数値は試験台と連戦モードで直す。
  • 習熟（R1-5）と探索の面（R1-6）は「あり / なし」「候補」の列だけで、中身は決めていない。

次に判断が要る点

  1. 「0 投入 5 ダメージ × 5 枚」が試験台で 10% を超えたら、T0 を 3 に戻すか minInvest 0 の枚数を減らす。どちらにするかは結果を見てから。
  2. カード 80 種の名前と役割に違和感があれば、実装前に差し替える。数値の違和感は試験台の結果を見てからでよい。
  3. 敵 9 体の階層配置（1〜5）を探索側の設計（R2-1 / R2-8）と後で合わせる。
